# Lola LMS — ТЗ. Часть 0. Обзор, цели, стек, архитектура

> Документ для Claude Code. Пишется в репозиторий как `docs/00-overview.md`.
> Статус: v0.8 (19.09.2026). Разбор эталона LMS Collaborator завершён; несведённые места
> закрыты гипотезами с решениями (см. `README.md` и разделы «Гипотезы» в модулях).

## 0.1 Что строим

Lola — мультитенантная SaaS-платформа корпоративного обучения для линейного персонала
(кухня, зал, склад, точки продаж). Первый тенант — Каппі (две точки в Одессе), но система
изначально строится как продукт для продажи другим сетям.

Функциональный ориентир — **полный дубль LMS Collaborator v3.3.0** (эталон:
`bulochki.davintoo.com`, доступ только на чтение, изменения в чужой системе запрещены).
Дубль означает: набор модулей и сценариев не уже эталона. Реализация своя,
интерфейс — по бренд-буку Lola, копирование вёрстки и кода эталона не производится.

## 0.2 Цели и не-цели

**Цели релиза 1 (запуск на Каппі):**
- сотрудник проходит назначенное обучение с телефона за 3–5 минут на урок;
- руководитель видит готовность смены по точкам и позициям;
- аттестация проходит в системе, с сертификатом и историей попыток;
- контент заводится силами HR без разработчика.

**Объём продукта:** функциональность эталона копируется целиком — ни один модуль
не вычёркивается, различается только этап (R1/R2/R3, см. `08-reference-inventory.md`).
Копируются требования, а не код, вёрстка и тексты эталона; контент эталона не переносится.

**Не-цели релиза 1** (переносятся на R2/R3, но делаются):
- развитие и компетенции, оценка и чек-листы, вебинары и очные занятия;
- корпоративный хаб: wiki, события, бонусы и магазин;
- публичная саморегистрация тенантов и биллинг;
- нативные мобильные приложения (на R1 достаточно PWA).

**Осознанно не делаем вовсе** (решение принято по данным эталона, а не по вкусу):

| Модуль | Что показал эталон | Решение |
| --- | --- | --- |
| Форум | 0 тем и 0 сообщений за три года работы | не делаем; при спросе — R3 |
| Wiki | вторая база статей рядом с базой знаний, дублирует её | одна база знаний |
| Рабочие задачи | нули во всех вкладках | не делаем, у Каппі есть свои инструменты |
| Вебинары | 0 назначений; контент заведён, не используется | карточка есть, интеграции провайдеров нет |
| Чат | четыре кода уведомлений на модуль, которым не пользуются | не делаем; общение идёт в Telegram |
| SCORM | в типах контента не встретился | R3, только на приём |

Это не сокращение объёма ради сроков, а отказ от переноса того, что на живой
установке за три года так и не заработало. Каждый пункт можно вернуть,
если появится спрос.

## 0.4 Стек

| Слой | Решение | Почему |
| --- | --- | --- |
| Фронтенд | Nuxt 3 (SSR), TypeScript, Vue 3 | тот же стек, что cappi.ua; SSR нужен для SEO публичных страниц |
| Стили | Tailwind + токены бренд-бука Lola | токены генерируются из `tokens.json` бренд-бука |
| Бэкенд | Nitro (h3), TypeScript | один рантайм с фронтом, деплой одним артефактом |
| БД | PostgreSQL 16 + pgvector | pgvector — под семантический поиск по базе знаний |
| ORM | Drizzle ORM + drizzle-kit | типобезопасность, миграции в репозитории |
| Изоляция тенантов | Row Level Security, роль `app_user` без BYPASSRLS | защита на уровне БД, а не только кода |
| Очередь | pg-boss (на том же Postgres) | не плодим Redis до нагрузки; задачи транзакционны с данными |
| Файлы | S3-совместимое хранилище (MinIO на своём железе / Hetzner) | видео и фото уроков |
| Медиа | ffmpeg в воркере: перекодирование в h264/AAC, постер | видео снимают на телефон, вес надо резать |
| Аутентификация | телефон + OTP (SMS/Telegram), сессии в httpOnly cookie | у линейного персонала нет рабочей почты |
| Уведомления | Telegram Bot API, SMS-провайдер, e-mail (резерв) | Telegram — основной канал |
| Поиск | Postgres FTS (ukrainian) + pgvector | без отдельного Elasticsearch |
| Тесты | Vitest (юнит/интеграция), Playwright (e2e) | |
| CI | GitHub Actions: lint → typecheck → test → build → migrate → deploy | |
| Хостинг | Docker Compose на Proxmox (см. homelab), потом — отдельный узел | |

## 0.5 Домены и приложения

| Домен | Приложение | Содержание |
| --- | --- | --- |
| `lola.ua` | отдельный репозиторий (маркетинг) | лендинг, тарифы, демо — **вне этого ТЗ** |
| `hub.lola.ua` | этот репозиторий | корпоративный хаб тенанта (новости, wiki, форум) — R2/R3 |
| `app.lola.ua` | этот репозиторий | продукт: кабинет, админка, API |
| `<tenant>.lola.ua` | этот репозиторий | опционально: поддомен тенанта (этап 6) |

Языки интерфейса: **украинский (по умолчанию) и английский**. Все строки — через i18n,
хардкод текста в компонентах запрещён. Контент курсов — на языке тенанта, без перевода.

## 0.6 Мультитенантность

1. Каждая строка каждой доменной таблицы содержит `tenant_id uuid not null`.
2. На всех таблицах включён RLS: `using (tenant_id = current_setting('app.tenant_id')::uuid)`.
3. Приложение подключается ролью `app_user`, у которой **нет** BYPASSRLS.
4. Каждый запрос выполняется в транзакции с `set local app.tenant_id` и `set local app.user_id`
   (хелпер `withTenant(tenantId, userId, fn)` — единственный способ обратиться к БД).
5. Кросс-тенантные операции (панель оператора) идут отдельной ролью `platform_admin`
   и отдельным модулем, где RLS снимается явно и логируется.
6. Файлы в S3 лежат в префиксе `t/<tenant_id>/…`; подписанные ссылки живут 10 минут.

## 0.7 Принципы, которым подчиняется код

- **Сервер — источник правды.** Клиент не считает прогресс, баллы и доступность урока.
- **Попытка теста иммутабельна.** При старте сохраняется снапшот вопросов и правильных
  ответов; правка вопроса не меняет уже сданные попытки.
- **Версии контента.** Урок и тест версионируются; результат ссылается на версию.
- **Мягкое удаление** (`deleted_at`) для контента и людей; жёсткое — только по запросу на удаление данных.
- **Всё, что видит пользователь, — через API.** SSR-страницы ходят в те же эндпоинты.
- **Каждое изменение — событие** в `audit_log` (кто, что, когда, старое/новое значение).
- **Фоновые задачи идемпотентны**: повторный запуск не создаёт дублей уведомлений и сертификатов.

## 0.8 Структура репозитория

```
lola/
├─ app/                     # Nuxt: страницы, компоненты, composables
│  ├─ pages/                # кабинет, админка, публичные
│  ├─ components/
│  ├─ composables/
│  └─ assets/tokens.css     # сгенерировано из бренд-бука
├─ server/
│  ├─ api/                  # HTTP-эндпоинты (тонкие)
│  ├─ services/             # бизнес-логика (толстые, тестируемые)
│  ├─ db/
│  │  ├─ schema/            # Drizzle: по одному файлу на домен
│  │  ├─ migrations/
│  │  └─ policies/          # SQL c RLS-политиками
│  ├─ jobs/                 # обработчики pg-boss
│  └─ utils/withTenant.ts
├─ shared/                  # типы и zod-схемы, общие для клиента и сервера
├─ tests/
│  ├─ unit/  integration/  e2e/
├─ docs/                    # это ТЗ
├─ CLAUDE.md                # правила работы для Claude Code
└─ docker/                  # compose, Dockerfile, MinIO, Postgres
```

## 0.10 Открытые вопросы

**Разбор эталона завершён** (19.09.2026). Списки «доосмотреть» закрыты:
`08` §8.12 — сводка, подробности по модулям. Там, где снять с эталона не удалось,
зафиксированы гипотезы с решениями (разделы «Гипотезы и принятые по ним решения»).

Решения по открытым вопросам запуска приняты так:

| Вопрос | Решение | Почему |
| --- | --- | --- |
| **SMS для OTP** | Основной канал — Telegram-бот; SMS только как резерв для тех, у кого Telegram не привязан. Провайдер — украинский агрегатор с оплатой по факту, бюджет считаем из 120 активных × 4 входа в месяц × резерв 20% ≈ 100 SMS в месяц | На эталоне SMS-канала нет вовсе, и это работает: у линейного персонала Telegram есть. Платить за SMS-пакет заранее незачем |
| **Хранилище** | R1 — MinIO на своём сервере (`26`), S3-совместимый API с первого дня | На эталоне 44 ГБ за три года. Это не тот объём, ради которого стоит платить внешнему провайдеру, а совместимый API оставляет переезд на один конфиг |
| **Английский интерфейс** | На релизе 1 — только `uk`. Все строки через i18n с первого коммита, словарь `en` заводим пустым | Переводы в эталоне живут отдельным экраном и используются для подмены терминов, а не для второго языка. Заложить дешевле, чем переделывать; переводить сейчас — тратить время впустую |
| **Формат сертификата** | И то, и другое: PDF по шаблону тенанта **и** публичная страница `/verify/<номер>` | Разобрано в `14` Г-14.3. PDF нужен человеку, страница — проверяющему |
| **Форум, wiki, рабочие задачи, вебинары** | В R1 не делаем | На эталоне за три года: 0 тем на форуме, 0 назначений вебинаров, нули в рабочих задачах. Обоснования — `21` §14.6, `19` §14.5, `18` Г-18.3 |
