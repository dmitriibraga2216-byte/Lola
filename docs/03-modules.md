# Lola LMS — ТЗ. Часть 3. Функциональные модули

Каждый модуль описан по схеме: назначение → правила → крайние случаи.

**Разбор эталона завершён 19.09.2026.** Этот документ — обзорный: детали каждого модуля
и то, что снято с эталона, — в `10`–`25`. Пометок `[эталон: сверить]` здесь больше нет;
где эталон снять не удалось, решение принято гипотезой (разделы «Гипотезы и принятые
по ним решения» в модульных документах).

## 3.1 Каталог и карточка курса

**Назначение.** Единая точка, где сотрудник видит назначенное и доступное для самозаписи.

**Правила**
- Разделы: «Моє навчання» (назначенное), «Каталог» (`is_catalog_visible = true`), «Пройдене».
- Карточка курса показывает: обложку, название, категорию, длительность, число уроков,
  прогресс, срок, статус, кнопку действия. Одно действие на карточку.
- Фильтры: категория, статус, срок, точка (для руководителя), теги. Поиск — по названию и тегам.
- Самозапись создаёт `enrollment` с `source='self'` и без срока.
- Повторное прохождение: если курс пройден и включена периодичность — за 30 дней до
  `valid_until` появляется новый `enrollment` с `source='repeat'`.

**Крайние случаи**
- Курс сняли с публикации, пока человек проходил → текущий `enrollment` доигрывается
  на своей версии; новых назначений не создаётся.
- Курс назначен и одновременно доступен в каталоге → показывается один раз, как назначенный.

## 3.2 Прохождение урока

**Правила**
- Порядок: уроки идут последовательно; следующий открывается после завершения предыдущего,
  если у курса включён режим «строго по порядку» (по умолчанию — включён).
- Завершение урока: все обязательные блоки просмотрены **и** прошло `min_seconds`
  (если задано). Время считает сервер по событиям `lesson.tick` (раз в 15 секунд, идемпотентно).
- Позиция сохраняется: при возврате открывается последний незавершённый урок.
- Видео: отметка завершения только после 90% просмотра (событие `media.progress`).
- Офлайн: при потере сети прогресс копится локально и досылается; конфликт решается
  в пользу большего прогресса.

**Крайние случаи**
- Человек открыл урок на двух устройствах → прогресс суммируется по `lesson_progress`,
  время не удваивается (дедупликация по окну 15 секунд).
- Урок изменён методистом → на текущем `enrollment` остаётся старая версия, обновление
  подхватывается при следующем назначении или повторе.

## 3.3 Тестирование

**Типы вопросов.** Семь снято с эталона (`12` §14.6), три добавлены нами.

| Тип | Название в эталоне | Код | Проверка |
| --- | --- | --- | --- |
| Один из списка | Одиночне | `single` | автоматически |
| Несколько из списка | Множинне | `multi` | автоматически; «за формулою» или «все або нічого» |
| Развёрнутый ответ | Вільна відповідь | `free` | вручную; подсказка проверяющему, вложения |
| Упорядочивание | Упорядкування | `ordering` | автоматически |
| Классификация по группам | Класифікація | `classification` | автоматически |
| Соответствие пар | Співставлення | `comparison` | автоматически |
| Выбор области на картинке | Вибір на зображенні | `answer_by_map` | автоматически, области в долях |
| Число с допуском `[решение]` | — | `number` | `abs(ans - value) <= tolerance` (граммовки) |
| Короткий текст `[решение]` | — | `text_short` | автоматически, нормализация регистра и пробелов |
| Файл или фото `[решение]` | — | `file` | вручную (фото выкладки) |

Три последних добавлены под задачи общепита: «сколько грамм в порции» неудобно
спрашивать вариантами, а фото выкладки — единственный способ проверить витрину удалённо.

**Метод подсчёта баллов** (снято с эталона): `formula` — доля верных элементов,
`all_or_nothing` — только полностью верный ответ. По умолчанию `all_or_nothing`
у одиночного выбора и `formula` у остальных составных типов.

**Группа вопроса** обязательна: параметр назначения «одне питання з кожної групи»
раздаёт разным людям разные наборы (`12` §14.3).

**Правила**
- Старт попытки: сервер формирует `snapshot` (состав вопросов, порядок, эталоны) и пишет в
  `attempts.snapshot`. Дальше всё считается по снапшоту.
- Таймер: `time_limit_at = started_at + time_limit_sec`; по истечении попытка
  автоматически отправляется, отвеченные вопросы засчитываются.
- Критический вопрос: ошибка в нём → попытка `failed` независимо от баллов.
- Показ ответов: `never | after_question | after_attempt` (настройка теста).
- Число попыток: по исчерпании — блокировка до снятия наставником (`attempt.reset`).
- Пересчёт балла: `score = Σ(правильные × weight) / Σ(weight) × 100`.
- Если есть вопросы ручной проверки — статус попытки `review` до проверки; пользователю
  показывается «На перевірці».

**Крайние случаи**
- Вкладка закрыта в середине → попытка остаётся `in_progress` до таймера или до
  `attempts.expire_after` (по умолчанию 24 часа), затем автозакрытие фоновой задачей.
- Вопрос удалён после старта → попытка не ломается: работает снапшот.

## 3.4 Аттестация и очередь проверки

**Правила**
- Аттестация — это `quiz.kind='certification'` с `pass_score`, ограничением попыток и,
  опционально, `requires_offline_confirm`.
- Развёрнутые ответы и файлы попадают в очередь: `review.queue` видит наставник своей точки.
- Наставник ставит зачёт/незачёт по каждому ответу, может оставить комментарий;
  после проверки всех ответов попытка пересчитывается и получает финальный статус.
- Свои попытки в очередь проверяющего не попадают.
- `requires_offline_confirm`: после сдачи теста статус `passed_pending_confirm`;
  руководитель подтверждает очную часть кнопкой, тогда выдаётся сертификат.
- SLA проверки: задача висит дольше 48 часов → напоминание наставнику и руководителю.

## 3.5 Назначения

**Адресация**
```jsonc
{ "type": "user",      "ids": ["uuid", …] }
{ "type": "position",  "ids": ["uuid"] }          // все повара
{ "type": "location",  "ids": ["uuid"] }          // вся точка
{ "type": "org_unit",  "ids": ["uuid"] }          // всё направление
{ "type": "role",      "ids": ["uuid"] }
{ "type": "segment",   "filter": { "hired_after": "2026-01-01", "position_ids": [...] } }
```

**Правила**
- Назначение раскрывается в `enrollments` фоновой задачей `assignment.expand`.
- Динамическая аудитория: новый сотрудник, попавший под условие, получает `enrollment`
  автоматически (задача `assignment.sync` раз в час и по событию `user.placement_changed`).
- Срок: абсолютная дата или относительный («14 днів з моменту призначення»).
- Обязательность влияет на отчёт готовности и на нотификации, не на доступ.
- Отмена назначения: `enrollment` со статусом `not_started` удаляется, начатые —
  переводятся в `expired` с сохранением результатов.
- Переаттестация: `recurrence` создаёт новый `enrollment` по расписанию.

## 3.6 Редактор курса

**Правила**
- Дерево: курс → модули → уроки, drag-and-drop сортировка, автосохранение черновика.
- Блоки контента (см. `02-data-model.md` §2.5): текст (WYSIWYG с ограниченным набором),
  изображение, видео, файл, чек-лист, выноска, встраивание (YouTube/Vimeo).
- Публикация: предпросмотр → «Опублікувати» → новая версия, changelog обязателен.
- Дублирование курса и импорт урока из другого курса.
- Проверки перед публикацией: у курса есть хотя бы один урок; у теста — вопросы;
  проходной балл 1–100; все медиа `status='ready'`.
- Санитизация HTML на сервере (allowlist тегов), защита от XSS — тест обязателен.

## 3.7 База знаний

- Статьи с теми же блоками, что уроки; категории и теги; версии и история правок.
- Поиск: полнотекстовый (`ukrainian`) + семантический по `embedding`; выдача смешанная.
- Привязка статьи к уроку («читати далі») и к позиции (подборка для роли).
- Доступ по скоупам: публичные для тенанта или ограниченные точкой/позицией.

> Патч `docs/v2/39-patches.md` П-03: если курсу назначен этап `knowledge`
> (`docs/v2/33-lifecycle.md` §3.2–3.3), возможности этапа отключают прогресс, дедлайн, оценку и
> сертификат — база знаний остаётся плоским списком без давления сроков, как и задумано здесь.

## 3.8 Опросы и обратная связь

- Типы: опрос (анонимный/именной), оценка курса после прохождения, 360° (этап 5).
- Вопросы: шкала 1–5, да/нет, выбор, свободный текст.
- Автозапуск: опрос после завершения курса; напоминание, если не заполнен за 3 дня.
- Отчёт: распределение ответов, средние, выгрузка. Анонимные — без имён, порог в 5 ответов
  (меньше — данные не показываются, чтобы нельзя было вычислить автора).

> Патч `docs/v2/39-patches.md` П-03, П-12: дополнено типом «Лінійна шкала» (числовой диапазон
> с подписями концов) и полями «Анонімне опитування» (влияет на хранение: ответ не связывается
> с человеком на уровне выборки) и «Підказка для відповіді» у открытого вопроса —
> `docs/12-tests-questions.md`. **Не путать** с `docs/v2/36-content-feedback.md`: там обратная
> связь по качеству контента (жалоба на вопрос, оценка материала), здесь — опрос людей.

## 3.9 Отчёты

| Отчёт | Что показывает | Кому |
| --- | --- | --- |
| Готовность смены | % людей с пройденными обязательными курсами по точке/позиции | manager, admin |
| Прогресс по курсу | воронка: назначено → начали → завершили → сдали | author, admin |
| Просроченные | список людей и курсов с истекшим сроком | manager, admin |
| Результаты аттестаций | попытки, баллы, проверяющие, время | manager, admin |
| Активность | DAU/WAU, среднее время на урок, доля с телефона | admin |
| Личный отчёт | свои курсы, баллы, сертификаты | все |
| По наставникам | сколько проверок, средний срок ответа | admin |

Правила: любой отчёт — с фильтром по датам, точке, позиции, курсу; выгрузка в xlsx
(фоновая задача, ссылка приходит в уведомление); цифры считаются на сервере,
в выгрузке те же цифры, что на экране.

все переменные шаблона документируются в UI.

## 3.11 Геймификация (этап 5)

- Баллы за завершение урока, курса, аттестации; лидерборд по точке и по сети (можно выключить).
- Бейджи по правилам; серия дней (streak).
- Правило бренда: награда — бирюзовая цифра и формулировка, без конфетти и фанфар.

## 3.12 Панель оператора платформы

- Список тенантов: план, активные пользователи, дата окончания триала, статус.
- Создание тенанта: slug, название, язык, админ (телефон), стартовые роли и настройки.
- Вход «от имени» с указанием причины, всё пишется в `audit_log`.
- Метрики: активность по тенантам, объём медиа, ошибки задач.

## 3.13 Отложено (после релиза 1)

- SCORM 1.2 / 2004 и xAPI импорт — нужен отдельный плеер и хранилище пакетов.
- Вебинары и живые сессии (интеграция с Zoom/Meet).
- Мобильные приложения (PWA закрывает потребность на старте).
- Индивидуальные планы развития и матрицы компетенций.
- Маркетплейс готовых курсов между тенантами.

# Модули второго и третьего этапов (полный дубль эталона)

Ниже — модули, которые в эталоне есть и которые мы тоже делаем. Порядок соответствует
`08-reference-inventory.md`. Для каждого — назначение и ключевые правила; поля появятся
в `02-data-model.md` по мере выхода этапа.

## 3.14 Практикумы (R1)

Задание, которое человек выполняет в реальности и сдаёт: текст, фото, файл, видео.
Проверяет наставник по критериям, ставит оценку по шкале и комментарий; возможен возврат
на доработку с указанием, что исправить. Комментарии тредом, видны автору и проверяющим.
Практикум может входить в курс как урок и назначаться отдельно.

## 3.15 Программы и траектории (R1 / R2)

**Программа** — последовательность курсов, тестов и практикумов с порядком и сроками
(«Програма навчання бариста»). Прогресс считается по вложенным элементам, сертификат
выдаётся за программу целиком.
**Траектория** (R2) — программа с ветвлением: следующий шаг зависит от результата
предыдущего или от должности человека.

## 3.16 Комплексные тесты (R2)

Экзамен из нескольких тестов с общим проходным баллом и общим лимитом времени;
результат считается по совокупности, попытка одна на весь комплекс.

## 3.17 Очные занятия (R2)

Расписание, место, тренер, вместимость, запись и лист ожидания, отметка посещаемости
(в том числе по QR на входе), оценка занятия участниками, отчёт по посещаемости.

## 3.18 Вебинары (R2)

Событие со ссылкой на внешнюю площадку (Zoom/Meet), регистрация, напоминания за сутки и
за 15 минут, отметка участия по факту подключения (если провайдер отдаёт), запись после.

## 3.19 Заявки (R1 / R2)

- **Заявка на дополнительную попытку** (R1): человек просит попытку, наставник одобряет — журнал.
- **Заявка на обучение** (R2): человек выбирает курс из каталога, требующий согласования;
  маршрут согласования — руководитель точки, затем HR.
- **Заявка на внешнее обучение** (R3): внешний курс, стоимость, бюджет, согласование, отчёт.

## 3.20 Развитие: ИПР, цели, компетенции, профили должностей (R2 / R3)

- **Компетенции** — библиотека с уровнями (1–5) и описанием поведения на каждом уровне.
- **Профиль должности** — требуемые компетенции и обязательные курсы; из него автоматически
  формируются назначения (это и есть «правила автоматизации» эталона, только явно).
- **ИПР** — индивидуальный план: цели, курсы, сроки, ответственный; статусы с настраиваемым
  жизненным циклом, проверка руководителем, протокол смены статусов.
- **Карьерное развитие** (R3) — треки перехода между должностями и заявки на них.
- **Стратегический план** (R3) — план обучения на период по подразделениям с бюджетом.

## 3.21 Оценка персонала и чек-листы (R2)

- **Процедура оценки**: период, участники, оценщики (руководитель, коллеги, сам),
  анкета из критериев со шкалами, сроки, напоминания, итоговый отчёт по человеку и по точке.
- **Чек-лист наблюдения**: наблюдатель проходит по пунктам на смене, отмечает выполнение,
  прикладывает фото; итог — процент и план исправлений. Пересекается с программой тайного
  покупателя: на R2 решить, ведём ли тайника здесь.
- Справочники: группы критериев, шкалы оценивания.

## 3.22 Корпоративный хаб (R1–R3)

- **Новости** (R1): лента, категории, просмотры, закрепление, обязательное прочтение.
- **Объявления** (R2): модальное окно при входе, подтверждение «ознайомився», отчёт кто прочитал.
- **События** (R2): календарь корпоративных событий с записью.
- **Wiki** (R2): иерархия страниц, история правок, права по веткам.
- **Публичная оргструктура** (R2): дерево компании с людьми и должностями.
- **Контакты и дни рождения** (R3): справочник и виджет.
- **Форум** (R3): темы, ответы, модерация, подписки.
- **Чат** (R3): личные и групповые переписки.
- **Бонусы и магазин** (R3): начисление баллов за обучение, каталог призов, заказ и выдача,
  журнал операций. Сделано в `gamification` (24.09.2026): две валюты одной книги — бали рейтинга
  и бонуси магазина, решения — `21` §17.

> Патч `docs/v2/39-patches.md` П-03: «Новини» здесь — корпоративная лента тенанта, которую
> пишет администратор тенанта и видят его сотрудники. Она разведена с платформенной лентой
> «Об'яви платформи» (`docs/v2/24-settings-platform.md` П-24.2, таблица `platform_announcements`
> без `tenant_id`, вне RLS) — на эталоне обе назывались одним словом «новини», но пишет их
> разный субъект и видит разная аудитория. «Публічна оргструктура» этого раздела заменяется
> витриной из `docs/v2/32-org-structure.md` §5 — тем же деревом в режиме только для чтения;
> отдельной реализации дерева здесь не нужно.

## 3.23 Рабочие задачи (R3)

Постановка задач сотрудникам вне обучения: тип, описание, срок, исполнитель, статус,
комментарии, отчёт по выполнению. Настраиваемые типы и статусы.

## 3.24 Бейджи, баллы, шкалы оценок (R2)

Бейджи по правилам (завершение, серия, скорость), баллы за действия, лидерборд по точке
и по сети (выключается), шкалы оценки заданий (не только процент: зачёт/незачёт, 1–5, буквы).

## 3.25 Переводы интерфейса (R1)

Все строки — ключами; администратор тенанта может переопределить любую строку для своего
пространства (эталонный модуль «Переклади»). Языки uk/en на R1, добавление языка — без релиза.

## 3.26 Сводный отчёт и конструктор выгрузок (R2)

Пользователь выбирает сущность (люди, назначения, попытки), поля, фильтры и группировку,
сохраняет как именованный отчёт, ставит на расписание с отправкой в Telegram или на почту.

## Модули пакета `docs/v2`

> Патч `docs/v2/39-patches.md` П-03. Пакет `docs/v2/` (снят сравнением с Sintegrum,
> `docs/v2/00-comparison.md`) добавляет одиннадцать модулей. Здесь — обзорная ссылка на
> каждый; полное описание, схема и API — в документе пакета.

### 3.27 Рекрутинг: кандидаты

Кандидат и сотрудник — одна запись `users` с разным `kind`; воронка по колонкам статусов,
резюме, ИИ-оценка, конверсия в найм. `docs/v2/28-recruiting-candidates.md`.

### 3.28 Рекрутинг: вакансии

Публичная страница вакансии, отклики без сессии (`/api/v1/public/*`), интеграции с
площадками публикации. `docs/v2/29-vacancies.md`.

### 3.29 ИИ в отборе

Собеседование голосом/текстом по сценарию, оценка ответов моделью как вход для человека —
ИИ не принимает решений о людях (инвариант пакета). `docs/v2/30-ai-interview.md`.

### 3.30 Библиотека модулей

Переиспользуемые модули контента с версионированием; урок может быть телом библиотечного
модуля (`lessons.module_id` — nullable). `docs/v2/31-module-library.md`.

### 3.31 Оргструктура

Дерево подразделений и позиций, привязка людей, детектор конфликтов оргструктуры (импорт).
`docs/v2/32-org-structure.md`.

### 3.32 Этапы жизненного цикла и офбординг

Восемь платформенных этапов (найм → онбординг → інтеграція → навчання → атестація →
офбординг + база знань, психологічні тести), возможности этапа через `stageCan()`, а не по
коду. `docs/v2/33-lifecycle.md`.

### 3.33 Хранилище

Учёт объёма файлов по владельцу и по этапу, мягкое удаление с заявкой на подтверждение,
доказательства с ограниченным сроком ссылки. `docs/v2/34-storage.md`.

### 3.34 Тариф и лимиты

Одиннадцать осей лимитов, аддоны докупки, деградация без остановки обучения при исчерпании
лимита. `docs/v2/35-billing-limits.md`.

### 3.35 Обратная связь по контенту

Жалоба на некорректный вопрос, оценка материала, пересчёт результатов теста без ухудшения.
`docs/v2/36-content-feedback.md`.

### 3.36 Делегирование проверки

Единая очередь проверки с делегированием и метриками времени на работу. `docs/v2/37-review-delegation.md`.

### 3.37 Расширения карточки человека

Лента активности, заметки, документы, нормы отсутствий, рейтинг. `docs/v2/38-people-extensions.md`.
