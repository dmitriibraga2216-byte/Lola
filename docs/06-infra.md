# Lola LMS — ТЗ. Часть 6. Инфраструктура, фоновые задачи, интеграции

## 6.1 Окружения

| Среда | Где | Данные | Кто пускает |
| --- | --- | --- | --- |
| local | docker compose на машине разработчика | сид-данные | все |
| staging | контейнер на Proxmox | копия прод-схемы, обезличенные данные | CI на `main` |
| production | отдельный узел | боевые | CI по тегу `v*` |

`docker-compose.yml` поднимает: `app` (Nuxt+Nitro), `postgres:16` с pgvector, `minio`,
`mailpit` (для писем в dev). Одна команда `pnpm dev:up` поднимает всё и накатывает миграции с сидом.

## 6.2 Файлы и медиа

- S3-совместимое хранилище, бакет `lola-media`, ключи `t/<tenant_id>/<yyyy>/<mm>/<uuid>.<ext>`.
- Загрузка только через presigned PUT: сервер выдаёт ссылку после проверки скоупа, mime и размера.
- После `POST /media/:id/complete` ставится задача `media.process`:
  - изображение → `webp` в трёх размерах (320/768/1600), сохранение оригинала;
  - видео → `h264 + aac`, максимум 1080p, битрейт ≤ 2.5 Мбит/с, постер на 1-й секунде;
  - документ → проверка mime, генерация превью первой страницы (pdf).
- Чтение: подписанная ссылка на 10 минут, генерируется на каждый запрос; прямых публичных
  ссылок нет (кроме публичной страницы проверки сертификата).
- Антивирус: `clamav` в воркере на загруженные файлы (этап 3), при срабатывании — карантин.

## 6.3 Очередь задач (pg-boss)

| Задача | Расписание / триггер | Идемпотентность |
| --- | --- | --- |
| `assignment.expand` | при создании назначения | ключ `assignment_id` |
| `assignment.sync` | каждый час + событие смены позиции | сверяет фактическую аудиторию |
| `notification.dispatch` | каждую минуту | ключ `notification_id` |
| `notification.digest` | по понедельникам 09:00 по таймзоне точки | ключ `user_id+week` |
| `due.scan` | ежедневно 08:00 | ключ `enrollment_id+stage` |
| `attempt.expire` | каждые 5 минут | по `time_limit_at` |
| `media.process` | после загрузки | ключ `media_id` |
| `certificate.issue` | после зачёта | ключ `enrollment_id` |
| `report.export` | по запросу | ключ `report_id` |
| `import.validate` / `import.apply` | по запросу | ключ `import_job_id` |
| `mv.refresh` | каждые 10 минут | — |
| `cleanup.sessions` | ежедневно | — |

Правила: у каждой задачи `retryLimit=5` с экспонентой, `expireInMinutes`, мёртвые задачи
падают в `pgboss.archive` и попадают в алерт. Ни одна задача не шлёт уведомление напрямую —
только через `notifications`, чтобы был журнал и дедупликация.

## 6.4 Уведомления

**Каналы**: Telegram (основной), SMS (OTP и критичное), e-mail (руководителям и отчёты),
web-push (этап 4).

**Telegram**
- Один бот на платформу, `telegram_chat_id` привязывается по одноразовому токену.
- Отправка: `sendMessage` с inline-кнопками; при ошибке 403 (бот заблокирован) — пометка
  `telegram_blocked`, переключение канала на SMS, уведомление руководителю при повторе.
- Лимиты Telegram: очередь с троттлингом 25 сообщений/сек на бота, 1 сообщение/сек на чат.

**SMS**: провайдер по API, только OTP и «прострочено» при заблокированном Telegram.
Учёт стоимости: счётчик отправок на тенанта, лимит в настройках.

**Тихие часы**: сообщения, попавшие в ночь, ставятся на утро (`scheduled_for`), кроме OTP.

## 6.5 Импорт людей

1. Файл xlsx/csv, шаблон скачивается из интерфейса.
2. Колонки: `ПІБ*`, `Телефон*`, `Email`, `Посада*`, `Рівень посади`, `Місто`, `Підрозділ*`,
   `Точка*`, `Роль`, `Мітки`, `Дата найму`, `Зовнішній ID`.
3. Валидация: формат телефона, существование справочников (с автосозданием по флагу),
   дубликаты внутри файла и в базе.
4. Предпросмотр: таблица с подсветкой ошибок, счётчики «створити / оновити / пропустити».
5. Применение — фоновой задачей батчами по 200, с прогрессом; отчёт xlsx с построчным итогом.
6. Идентификация существующего: по `external_id`, иначе по телефону.
7. Приглашения рассылаются отдельным действием, не автоматически.

## 6.6 Безопасность

- RLS на всех таблицах, роль приложения без BYPASSRLS, тест на полноту политик (см. §2.12).
- Пароли — argon2id; OTP хранится хешем; токены сессий — хеш в БД, сырой только в cookie.
- Rate limiting: на IP и на ключ (телефон, пользователь) через таблицу счётчиков.
- Загрузка файлов: allowlist mime, проверка сигнатуры файла, ключ не из имени файла.
- HTML контента санитизируется на сервере (allowlist тегов и атрибутов).
- CSP: `default-src 'self'`, медиа с S3-домена, без `unsafe-inline` (nonce для Nuxt).
- Журнал безопасности: входы, смены ролей, выгрузки данных, impersonation.
- Секреты — в переменных окружения, в репозитории только `.env.example`.
- Бэкапы: `pg_dump` ежедневно + WAL, хранение 30 дней, ежемесячная проверка восстановления.
- Удаление данных по запросу: анонимизация пользователя (ФИО → «Користувач #id», телефон
  и e-mail в null), результаты обучения сохраняются обезличенно; операция логируется.

## 6.7 Наблюдаемость

- Логи структурные (pino), в каждой записи `trace_id`, `tenant_id`, `user_id`.
- Метрики Prometheus: HTTP (RED), задачи (глубина очереди, время выполнения, падения),
  БД (пул, медленные запросы), бизнес (старты попыток, завершения курсов, отправки уведомлений).
- Алерты: очередь > 500, падений задач > 10 за 10 минут, `/ready` красный, p95 API > 1 c,
  ошибки Telegram > 5%.
- Sentry для ошибок клиента и сервера с привязкой к `trace_id`.

## 6.8 Производительность

- Цели: p95 ответа API ≤ 300 мс, старт урока ≤ 1 с на 4G, вес первого экрана ≤ 250 КБ gzip.
- Кеш: справочники и настройки тенанта — в памяти процесса с инвалидацией по событию.
- Списки — курсорная пагинация, никаких `offset` на больших таблицах.
- Изображения отдаются в webp по размеру экрана; видео — прогрессивно, без автозагрузки.
- Ориентир нагрузки: 50 тенантов × 300 человек, пик 200 одновременных попыток теста.

## 6.9 CI/CD

```
lint → typecheck → unit → integration (postgres в сервисах) → build → e2e (playwright)
     → migrate (staging) → deploy staging → smoke → tag → migrate (prod) → deploy prod
```

- Миграции только вперёд, откат — новой миграцией; деплой останавливается, если миграция
  не прошла на staging.
- Секреты в GitHub Environments; прод требует ручного подтверждения.
- Health-check после деплоя; при трёх неудачах — автоматический откат на предыдущий образ.

## 6.10 Тестирование

| Уровень | Что покрываем | Порог |
| --- | --- | --- |
| unit | правила баллов, прогресс, раскрытие аудитории, шаблоны | ≥ 80% сервисов |
| integration | RLS (изоляция тенантов), API-контракты, задачи | все критичные пути |
| e2e | вход по OTP, прохождение урока, тест с ручной проверкой, назначение, импорт | 8 сценариев |
| нагрузка | 200 одновременных попыток | k6, раз в этап |

Обязательные тесты безопасности: изоляция тенантов, утечка эталонов ответов,
доступ к чужому файлу, XSS в контенте урока, обход лимита попыток.
