# Lola LMS — ТЗ. Часть 8. Полная карта функций эталона → Lola

Источник: рабочая инсталляция LMS Collaborator 2.43.0 (`bulochki.davintoo.com`), роль
«Адміністратор», осмотр 19.09.2026, только чтение — в чужой системе ничего не менялось.

**Решение по объёму: копируем функциональность целиком.** Ни один модуль не вычёркивается;
различается только этап (R1 — первый релиз, R2 — второй, R3 — третий). Из эталона берутся
**требования**, а не код, вёрстка и тексты: реализация своя, упаковка своя (бренд Lola,
mobile-first, вход по телефону, мультитенантность).

Контент эталона (курсы, тесты, статьи «Булочек») не копируется вообще — переносится только
структура возможностей.

## 8.1 Карта разделов

Эталон: восемь разделов — `Користувачі`, `Контент`, `Навчання`, `Розвиток`, `Інформація`,
`Оцінка`, `Для роботи`, `Налаштування системи`; внутри каждого группы
«Головне · Управління · Я перевіряю · Результати · Налаштування».

Lola повторяет эту структуру один в один, включая группировку и счётчики в пунктах меню.
Отличие одно: разделы называются по-своему и появляются по скоупам пользователя.

## 8.10 Что повторяем как приём

- **Меню по задачам, а не по сущностям**: «Я перевіряю», «Результати», «Управління».
- **Счётчики в пунктах меню** — видно, где тебя ждут.
- **Режим просмотра системы глазами роли** (в эталоне — кнопка «Режим редагування за ролями»).
- **Редактор с разделением «состав» и «настройки»** — две вкладки.
- **Протокол на каждое действие**: импорт, статусы, уведомления, сессии, безопасность.
- **Назначение как самостоятельная сущность** с типом, метками, сроками, напоминаниями
  и собственным списком аудитории.

## 8.11 Что делаем иначе (упаковка, не функции)

| Эталон | Lola |
| --- | --- |
| Вход по логину/почте и паролю | Телефон + код, пароль как резерв |
| Плотный десктопный интерфейс | Mobile-first, десктоп как второй приоритет |
| Отдельная инсталляция на клиента | Один экземпляр, изоляция тенантов через RLS |
| Отчёт на каждый тип контента (12 штук) | Отчёты с общим каркасом и фильтром по типу |
| Собственный визуальный язык вендора | Бренд-бук Lola: беж, солнце, бирюза, коралл, Nunito |

## 8.13 Детали, снятые при осмотре

**Назначения (`/manage/tasks/v3`)** — типы: вручную, автоматически, по каталогу, по траектории,
архив. Колонки: Назва, Тип, Автор, Мітки, Створено, Початок, Завершення, Користувачі, ІПР,
Компетенції. Две группы настроек: «Параметри» и «Нагадування» — напоминания настраиваются
на самом назначении.

**Правила автоматизации (`/automation-rules`)** — названы по должностям: «Бариста», «Менеджер»,
«Нічний продавець», «Адміністратор», «Помічник продавця», «Всі працівники компанії». То есть
это профиль обучения должности: человек появился на позиции → набор курсов назначился сам.

**Редактор теста** — две вкладки: «Питання» (состав, отбор из банка с фильтром, счётчик вопросов)
и «Опис та налаштування» (описание, метки, авторы, вложения, картинка карточки, публикация).

**Пользователи (`/users`)** — вкладки Активні/Заблоковані/Усі; колонки перечислены в §8.4;
справочники (міста, посади, рівні посад, підрозділи, мітки) ведутся отдельно.

### 12.8 Единое правило карточки контента

Проверены формы создания девяти типов: ресурс, тест, опрос, практикум, комплексный тест,
очное занятие, вебинар, сертификат, бейдж. Во всех девяти карточка содержит только:

**Назва · Опис · Прикріплені файли · Мітки · Опублікувати · Зображення для картки завдання**

и ничего про то, как это проходят. Ни сроков, ни попыток, ни проходного балла, ни дат
занятия, ни вместимости, ни критериев проверки — всё это задаётся в **назначении**
(`/manage/tasks/v3`), а попытка хранит копию правил на момент старта.

Это — главный архитектурный вывод всего разбора эталона. Он определяет `02` (данные),
`12` (тесты), `15` (назначения) и объясняет, почему один и тот же тест живёт
в десяти назначениях с разными правилами и не ломается.

Исключения, которые всё же держат параметры в карточке, — только анкетные:
опрос (режим выполнения, анонимность, конфиденциальность), чек-лист (шкала, веса)
и оценка (шкала, нормы, правила комментирования). У них параметр неотделим от состава
вопросов, поэтому и живёт рядом с ним; и у всех трёх после первого заполнения
параметры замораживаются (`20` §14.4).
