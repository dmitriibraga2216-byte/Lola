# Lola LMS — ТЗ. Часть 12. Тести та банк питань

## 1. Назначение и границы

Модуль описывает банк вопросов, конструктор теста, механику попытки и подсчёт результата.

**Ключевое архитектурное решение, снятое с эталона:** правила прохождения (число попыток,
проходной балл, лимит времени, сроки, показ ответов) задаются **в назначении**, а не в тесте.
В карточке теста — состав вопросов, описание, метки, авторы, обложка. Один и тот же тест
можно назначить новичкам с тремя попытками и без таймера, а на аттестации — с одной попыткой
и лимитом 15 минут, не создавая копию.

Входит: типы вопросов и их параметры, банк, отбор вопросов, попытка, снапшот, подсчёт,
показ разбора, заявка на дополнительную попытку.
Не входит: аттестация и очередь проверки (`14`), назначения (`15`), практикумы (`13`).

### 3.3 Типы вопросов — полный перечень с параметрами

**1. `single` — один правильный ответ**
- `options`: `[{id, text, image_media_id?}]`, 2–10 вариантов.
- `answer`: `{correct_id}`.
- Параметры: перемешивание вариантов (в назначении), «немає правильної відповіді» как вариант.
- Подсчёт: верно → `points`, иначе 0.

**2. `multiple` — несколько правильных**
- `options`: 2–15 вариантов; `answer`: `{correct_ids[]}`, минимум 1.
- Параметры: `partial_credit`, `negative_marking`, `require_exact` (только полное совпадение).
- Подсчёт при `partial_credit`: `points × (верно выбранных − неверно выбранных) / всего верных`,
  результат не меньше 0. При `require_exact`: всё или ничего.

**3. `order` — упорядочивание**
- `options`: 3–10 элементов; `answer`: `{order:[id,…]}`.
- Параметры: `partial_credit` (балл за каждую пару в правильном относительном порядке).
- Подсчёт: `points × (число верных пар / общее число пар)`.

**4. `match` — соответствие**
- `options`: `{left:[{id,text}], right:[{id,text}]}`, 2–10 пар; допускаются лишние
  элементы справа (дистракторы).
- `answer`: `{pairs:[{left_id,right_id}]}`.
- Подсчёт: `points × верных пар / всего пар` при `partial_credit`.

**5. `number` — число с допуском** (граммовки, температуры)
- `answer`: `{value, tolerance, unit, tolerance_type: "abs"|"pct"}`.
- Параметры: единица измерения показывается рядом с полем; допуск абсолютный или в процентах.
- Подсчёт: верно, если `|ответ − value| ≤ tolerance` (или `value × tolerance/100`).
- Валидация ввода: только число, разделитель — точка или запятая.

**6. `text_short` — короткий текст**
- `answer`: `{accepted:[строки], case_sensitive:false, trim:true, normalize_spaces:true,
  allow_typos:0}` — `allow_typos` = расстояние Левенштейна 0–2 `[решение]`.
- Подсчёт: совпадение с любым из `accepted` после нормализации.

**7. `text_long` — развёрнутый ответ**
- `answer`: null; проверка ручная (см. `14`).
- Параметры: минимальная и максимальная длина (10–5000 знаков), критерии оценки для
  проверяющего (список пунктов), эталонный ответ для проверяющего (не виден ученику).

**8. `file` — файл или фото**
- Параметры: допустимые форматы (image, pdf, video), максимальный размер, число файлов 1–5,
  можно ли снимать камерой сразу (`capture=environment` на мобильном).
- Проверка ручная; критерии — как у `text_long`.

**9. `hotspot` — точка на изображении** `[решение, R2]`
- `options`: изображение + области (прямоугольники или круги); `answer`: `{area_ids[]}`.
- Для проверки знания планограммы, схемы цеха, зон уборки.

**10. `cloze` — пропуски в тексте** `[решение, R2]`
- `stem` с плейсхолдерами `{{1}}`, `answer`: массив вариантов для каждого пропуска.

Для каждого типа поддерживаются: изображение и видео в формулировке, разбор, подсказка,
критичность, вес, сложность, метки, лимит времени на вопрос.

## 4. Состояния попытки

| Статус | Значение | Переход |
| --- | --- | --- |
| `in_progress` | идёт | → `submitted` (отправил), → `expired` (истёк таймер/сутки) |
| `submitted` | отправлена, идёт автопроверка | → `review` (есть ручные), → `passed`/`failed` |
| `review` | ждёт наставника | → `passed`, → `failed` |
| `passed` | зачёт | → `annulled` (аннулирована) |
| `failed` | незачёт | → `annulled` |
| `expired` | не отправлена вовремя | автоматически оценивается по отвеченному |
| `annulled` | аннулирована руководителем | конечное, в статистику не входит |

## 5. Экраны

### 5.1 Банк вопросов

Таблица: текст вопроса (первая строка), тип (иконка), банк, категория, метки, сложность,
вес, критичность, автор, дата изменения, статистика (% верных). Фильтры: банк, тип,
категория, метка, сложность, критичность, автор. Поиск по тексту вопроса.
Массовые действия: перенести в банк, добавить метку, изменить сложность, архивировать.

### 5.2 Редактор вопроса

Слева — тип (меняется без потери текста, где возможно), формулировка (редактор блоков),
варианты (добавление, перетаскивание, отметка правильных), разбор, подсказка.
Справа — параметры: вес, сложность, критичность, метки, банк, лимит времени,
частичный балл, штраф за неверные.
Внизу — «Попередній перегляд»: вопрос глазами ученика, с проверкой ответа.

### 5.3 Редактор теста

Две вкладки, как в эталоне:
- **«Питання»**: панель отбора («Обрати» → фильтр по банку, категории, метке, сложности),
  «Додати питання» → «Створити» (новый) или «Питання з іншого тесту», поиск по тексту,
  счётчик «Кількість запитань: N», список с перетаскиванием, вес и критичность прямо в строке.
  Для `selection_mode=random` — конструктор правил: «взять 5 вопросов из банка X со сложностью 3–4».
- **«Опис та налаштування»**: тема, описание, «Коротко про тест» (WYSIWYG), метки, авторы,
  прикреплённые файлы, обложка карточки, публикация.

### 5.4 Прохождение теста (ученик)

Стартовый экран: название, описание, число вопросов, лимит времени, число попыток и сколько
осталось, проходной балл, кнопка «Почати». Если попытки исчерпаны — «Спроби вичерпано»
и кнопка «Попросити ще одну спробу».

Экран вопроса: «Питання 2 з 5», таймер (если есть), формулировка, варианты, кнопки
«Далі» / «Пропустити» / «Назад» (если разрешено), карта вопросов (свайп вверх на мобильном).
Автосохранение ответа при каждом изменении.

При `show_answers=after_question`: после ответа — бирюзовая или коралловая подложка
и разбор, кнопка «Далі».

Экран отправки: «Ви відповіли на 5 з 5. Надіслати?»; если есть пропуски и
`require_all_answered=true` — список непройденных, отправка заблокирована.

Экран результата: крупная цифра (бирюзовая при зачёте, коралловая при провале),
«{score}% · прохідний {pass}%», время, список вопросов с отметками и разборами
(по правилу `show_answers`), кнопки «Повторити» (если остались попытки, с учётом паузы)
или «До навчання».

Состояние «На перевірці»: «Наставник перевірить розгорнуті відповіді. Зазвичай це займає до доби».

### 5.5 Статистика теста (автор)

Таблица вопросов: текст, тип, сколько раз показан, % верных, средний балл, дискриминация
(разница между сильными и слабыми учениками) `[решение]`. Подсветка: вопросы с % верных
< 20% (слишком сложный или ошибка в эталоне) и > 95% (слишком лёгкий).

### 6.3 Заявка на дополнительную попытку

Ученик: кнопка «Попросити ще одну спробу» + поле причины (10–300 знаков).
Наставник видит заявку в очереди: человек, тест, сколько попыток использовано, баллы,
причина; кнопки «Дати спробу» / «Відмовити» + комментарий.

## 7. Правила и алгоритмы

1. **Старт попытки.** Сервер проверяет: есть ли запись, не исчерпаны ли попытки, прошёл ли
   cooldown, не истёк ли срок. Формирует снапшот (с учётом `shuffle_*` и правил отбора),
   пишет `params` из назначения, ставит `deadline_at`.
2. **Отбор при `random`.** Для каждого правила берутся вопросы, подходящие по фильтру,
   перемешиваются, берётся `count`. Если подходящих меньше — попытка не стартует,
   автору уходит уведомление `quiz.not_enough_questions`.
3. **Сохранение ответа** — `PUT /attempts/:id/answers/:questionId`, идемпотентно,
   последний ответ побеждает; после `submitted` изменения не принимаются (423).
4. **Автопроверка** — по снапшоту, не по текущим вопросам.
5. **Критический вопрос:** ошибка → `passed=false` независимо от баллов; в разборе
   помечается «Критичне питання».
6. **Подсчёт:** `score = Σ(баллы) / Σ(веса) × 100`, округление до сотых.
   `passed = score ≥ pass_score AND нет ошибок в критических AND все ручные зачтены`.
7. **Таймер** считает сервер: `deadline_at` в снапшоте, клиент только показывает.
   При `submit` после дедлайна — ответы после `deadline_at` не засчитываются.
8. **Автозакрытие:** попытка `in_progress` без активности 24 часа закрывается задачей
   `attempt.expire` и оценивается по отвеченному.
9. **Смена вкладки** при `proctoring=tab_switch` увеличивает `tab_switches`; отображается
   проверяющему, автоматически ничего не блокирует `[решение]`.
10. **Аннулирование** доступно руководителю с указанием причины; аннулированная попытка
    не считается использованной и не входит в статистику.
11. **Правка вопроса** увеличивает `version`; активные попытки не затрагиваются.
12. **Удаление вопроса** запрещено, если он есть хоть в одном снапшоте: только архивация.

## 9. Отчёты

**Звіт з тестування**: человек, точка, позиция, тест, попытка №, балл, статус, время,
дата, проверяющий. Фильтры: тест, точка, позиция, период, статус, только последние попытки.
**Статистика вопросов**: см. §5.5, выгрузка в xlsx.
**Сравнение попыток**: динамика балла человека по повторным попыткам.

| GET | `/attempts/:id/result` | разбор по правилу `show_answers` |
| POST | `/attempts/:id/annul` | `{reason}` |
| POST | `/attempts/:id/extra-attempt` | заявка ученика |
| POST | `/attempt-requests/:id/decide` | `{approved, comment}` |

**Требование безопасности:** сериализатор попытки физически не содержит эталонов;
отдельный тест `tests/integration/attempt-leak.spec.ts` проверяет, что в ответе
`GET /attempts/:id` нет ни `answer`, ни `explanation` до завершения.

## 11. Фоновые задачи

`attempt.expire` (каждые 5 минут), `attempt.autograde` (после submit, если очередь),
`question.stats_recalc` (ночью), `quiz.validate_rules` (проверка, что правила отбора
набирают нужное число вопросов — раз в сутки и при изменении банка).

## 12. Крайние случаи

- Ученик потерял сеть в середине — ответы уже сохранены на сервере; при возврате попытка
  продолжается с того же места, таймер не останавливался.
- Две вкладки с одной попыткой — сервер принимает последний ответ, конфликт не блокирует.
- Тест без вопросов — назначить нельзя, проверка при публикации.
- В снапшоте вопрос с медиа, которое удалили — медиа хранится до тех пор, пока есть снапшоты.
- Ученик отвечает на `number` «4,5» — принимается, нормализация запятой.
- Все вопросы критические и все с ошибкой — `score` 0, `passed=false`, разбор показывается.
- Попытка стартовала до изменения параметров назначения — работает по `params` из снапшота.

## 13. Критерии приёмки

1. **Дано** назначение с 1 попыткой и лимитом 10 минут, **коли** ученик стартует,
   **тоді** `deadline_at` = старт + 10 минут, а после дедлайна ответы не принимаются.
2. **Дано** тест с критическим вопросом, **коли** ученик набрал 95%, но ошибся в критическом,
   **тоді** статус `failed` и пометка в разборе.
3. **Дано** `multiple` с частичным баллом: 3 верных из 4, 1 лишний, **тоді** балл
   `points × (3−1)/4`, не меньше 0.
4. **Дано** `number` со значением 4 и допуском 0.5, **коли** ответ 4.4, **тоді** зачтено.
5. **Дано** попытка в статусе `review`, **коли** наставник зачёл все развёрнутые,
   **тоді** пересчитывается общий балл и статус меняется на `passed`/`failed`.
6. **Дано** автор изменил формулировку вопроса, **тоді** сданные попытки показывают
   старую формулировку из снапшота.
7. **Дано** `GET /attempts/:id` во время попытки, **тоді** в ответе нет правильных ответов.
