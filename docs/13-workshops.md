# Lola LMS — ТЗ. Часть 13. Практикуми

## 1. Назначение и границы

Практикум — задание, которое человек выполняет в реальности и сдаёт в систему: текстом,
фото, файлом или видео. Проверяет наставник по критериям, может вернуть на доработку.
Это единственный модуль, где основную работу делает человек вне экрана, а система только
принимает результат и хранит историю.

Типовые практикумы Каппі: «Сфотографуй зібраний сет за чек-листом», «Зніми відео, як
розбираєш рибу», «Опиши, що зробиш, якщо гість каже, що піца холодна».

Входит: задание, критерии, сдача, проверка, доработка, комментарии, отчёты.
Не входит: очередь проверки развёрнутых ответов теста (`14`), оценка персонала (`20`).

## 4. Состояния и переходы

| Статус | Значение | Переходы |
| --- | --- | --- |
| `draft` | черновик ученика, не отправлен | → `submitted` |
| `submitted` | отправлено, ждёт проверяющего | → `in_review`, → `withdrawn` (ученик отозвал, если разрешено) |
| `in_review` | проверяющий взял в работу | → `accepted`, → `rejected`, → `rework` |
| `rework` | возвращено на доработку | → `submitted` (переотправка), → `expired` |
| `accepted` | зачтено | конечное (можно аннулировать) |
| `rejected` | не зачтено, доработка невозможна | конечное |
| `expired` | не доработано в срок | конечное |
| `annulled` | аннулировано руководителем | конечное |

Правила:
1. `submitted → in_review` происходит автоматически, когда проверяющий открывает карточку.
2. Если проверяющий не завершил проверку за 30 минут, карточка возвращается в общую очередь.
3. `rework` увеличивает `rework_count`; при достижении `max_reworks` кнопка «Повернути»
   у проверяющего исчезает, остаются «Зараховано» и «Не зараховано».

## 5. Экраны

### 5.1 Практикум у ученика

Задание: название, описание блоками, пример выполнения (фото или видео), критерии списком —
человек должен видеть, по чему его оценят, **до** того как начнёт.
Форма сдачи: поле текста (если разрешено), кнопка «Додати фото» (камера или галерея, в
зависимости от `allow_camera_only`), список прикреплённых файлов с превью и удалением,
кнопка «Надіслати на перевірку», кнопка «Зберегти чернетку».

После отправки: статус «На перевірці», срок «Наставник перевірить до 20:00 завтра»,
история сдач (свернутая), лента комментариев.

При `rework`: коралловая плашка «Потребує доопрацювання» + комментарий наставника +
отметки по критериям (что не так) + форма переотправки с сохранением прошлых файлов.

При `accepted`: бирюзовая плашка «Зараховано», балл (если шкала не зачёт/незачёт),
комментарий, кнопка «До навчання».

### 5.2 Очередь проверки (наставник)

Список карточек: человек (аватар, имя, точка, позиция), практикум, когда сдано,
сколько осталось по SLA (коралловым, если просрочено), номер сдачи («2-га спроба»).
Фильтры: точка, практикум, статус, просроченные, «мої» / «усі».
Сортировка: по SLA, самые горящие сверху.
Счётчик в меню: сколько ждёт проверки.

### 5.3 Карточка проверки

Слева — работа ученика: текст, фото в галерее с увеличением, видео с плеером, файлы.
Справа — критерии: каждый с переключателем «Так / Ні» и полем комментария;
общий комментарий; кнопки «Зараховано», «На доопрацювання», «Не зараховано».
Внизу — история: прошлые сдачи, кто и когда проверял, что писал.
Панель контекста: другие практикумы этого человека, его результаты тестов.

Правила интерфейса: после решения — сразу следующая карточка из очереди; счётчик
«Залишилось 7»; кнопка «Пропустити» возвращает карточку в очередь.

### 5.4 Управление практикумами (методист)

Таблица: название, тип сдачи, критериев, проверяющий, SLA, сколько на проверке,
среднее время проверки, доля зачтённых с первого раза.

### 6.2 Сдача работы (ученик)

Текст: счётчик знаков, подсказка «Мінімум 50 символів».
Файлы: «Додати фото» / «Зняти на камеру» / «Додати файл»; превью с крестиком;
ошибки: «Файл більший за 50 МБ», «Можна додати до 3 файлів», «Формат не підтримується».
Кнопка отправки неактивна, пока не выполнены минимальные условия, с подписью-объяснением.

### 6.3 Проверка (наставник)

Критерии — переключатели, комментарий к каждому необязателен.
Общий комментарий обязателен при «На доопрацювання» и «Не зараховано» (10–2000 знаков),
необязателен при «Зараховано».
Ошибка: «Поясніть, що саме треба виправити — людина побачить цей текст».

## 7. Правила и алгоритмы

1. **Назначение проверяющего.** По `reviewer_rule`: `location_mentor` — все наставники точки
   человека; `author` — авторы практикума; `specific` — заданный список; `any_mentor` — все
   наставники тенанта. При `self_review_forbidden=true` сам человек из списка исключается.
2. **Захват карточки.** Открытие карточки ставит `reviewer_id` и `review_started_at`;
   других проверяющих карточка больше не показывается. Через 30 минут бездействия — освобождается.
3. **Зачёт.** При `pass_rule=all_criteria` — зачтено, если все критерии `passed=true`
   и ни один критический не провален. При `min_score` — если `score ≥ порог`.
4. **Доработка.** Ученику уходит уведомление с комментарием; срок доработки —
   `sla_hours` от момента возврата, по истечении статус `expired` и уведомление руководителю.
5. **Влияние на курс.** Практикум как урок курса: `accepted` = урок пройден,
   `rejected`/`expired` = запись курса переходит в `failed` `[решение]`.
6. **SLA.** Просроченная проверка подсвечивается, через 2×`sla_hours` уведомление уходит
   руководителю точки.
7. **Фото с камеры.** При `allow_camera_only=true` на мобильном используется
   `capture="environment"`; на десктопе показывается предупреждение «Зробіть фото з телефона».
8. **Хранение медиа.** Файлы сдач живут по правилам `media_assets`, но удаляются только
   вместе со сдачей и не раньше 12 месяцев после проверки `[решение]`.

## 9. Отчёты

**Звіт з практикумів**: человек, точка, позиция, практикум, сдача №, статус, балл,
проверяющий, время до проверки, время на доработку, дата.
**По наставникам**: сколько проверок, среднее время реакции, доля возвратов, просрочки SLA.
**По практикумам**: доля зачтённых с первого раза, самые проваливаемые критерии
(это показывает, чему люди не научены).

## 11. Фоновые задачи

`workshop.sla_scan` (каждый час — просрочки проверки и доработки),
`workshop.release_stale` (каждые 5 минут — освобождение захваченных карточек),
`workshop.expire_rework` (ежедневно).

## 12. Крайние случаи

- Наставник ушёл в отпуск и держит 20 карточек → руководитель может массово переназначить.
- Ученик сдал фото размером 40 МБ с телефона → клиент сжимает изображение до 2000px
  по длинной стороне перед загрузкой `[решение]`.
- Работа отправлена, пока наставник её проверял (доработка в двух вкладках) → сервер
  отклоняет вторую отправку с 409.
- Практикум изменили после сдачи → критерии в сдаче хранятся снимком, проверка по ним.
- Человек уволен с несданным практикумом → сдача переходит в `expired`, запись `cancelled`.
- Видео 400 МБ → загрузка по presigned-ссылке напрямую в хранилище, минуя шлюз (см. `27`).

## 13. Критерии приёмки

1. **Дано** практикум с тремя критериями и `pass_rule=all_criteria`, **коли** наставник
   отметил два из трёх, **тоді** кнопка «Зараховано» недоступна, доступны «Доопрацювання»
   и «Не зараховано».
2. **Дано** сдача в очереди, **коли** её открыл наставник А, **тоді** наставник Б её не видит;
   через 30 минут бездействия А карточка возвращается в очередь.
3. **Дано** `max_reworks=2` и две доработки позади, **тоді** кнопки «Доопрацювання» нет.
4. **Дано** `allow_camera_only=true`, **коли** ученик пытается выбрать файл из галереи
   на мобильном, **тоді** доступна только камера.
5. **Дано** SLA 48 часов, **коли** прошло 96, **тоді** руководителю ушло уведомление,
   а карточка в очереди помечена коралловым.
6. **Дано** наставник — тот же человек, что сдал, **тоді** его сдача в его очереди не появляется.

## 14. Сверено с эталоном

Проверено 19.09.2026 (`/workshop/create`, `/process/learning`).

**Форма создания практикума** (`/workshop/create`): «Назва*», «Опис», «Текст»,
«Прикріплені файли», «Мітки», «Опублікувати», «Зображення для картки завдання».

**Критериев в практикуме эталона нет.** Проверяющий видит работу и ставит решение целиком;
структурированного разбора по пунктам форма не предполагает. Очередей две, и они разные:
«Перевірка практикумів» (`/tasks/tutor-workshops`) и «Коментарі практикумів»
(`/workshop/evaluation-comments`).

**Вывод для Lola `[решение]`.** Критерии практикума (`13` §3.2), правило зачёта
`pass_rule`, лимит доработок и SLA очереди — наше улучшение, а не копия. Обоснование:
в дарк-китчене практикум проверяют разные наставники в разных точках, и без общего списка
критериев оценка расходится от человека к человеку. Цена решения — одна дополнительная
таблица и один экран редактора критериев; отказаться от неё можно, не трогая остальное
(тогда `pass_rule` = единственное решение проверяющего).

Единая очередь вместо двух — тоже наше решение: в эталоне комментарий и проверка разведены,
у нас это два действия над одной карточкой.

## 15. Гипотезы и принятые по ним решения

### Г-13.1 Очередь проверки и её колонки

**Снято частично.** `/tasks/tutor-workshops` — список практикумов (карточка: название,
«Програма:», «Курс:», «Дата: с — по», ссылка «Звіт»), а сдачи открываются из отчёта.
Колонки самого отчёта по практикуму снять не удалось: экран требует выбора практикума
через выпадающий список, который не открывается программно.

**Гипотеза.** Отчёт по практикуму устроен как отчёт по тесту (`22` §13.7):
«Огляд успішності», «Статистика» и таблица людей с колонками
ПІБ · Посада · Місто · Підрозділ · Мітки · Дата призначення · Дата останньої спроби ·
Поточний статус · Результат.

**Чем проверяется.** Открыть `/workshop/reports`, выбрать практикум и сравнить
с отчётом по тесту.

**Решение для Lola `[решение]`.** Строим **очередь сдач**, а не список практикумов:
колонки — Дата здачі · ПІБ · Точка · Практикум · Курс · Час в черзі · Хто перевіряє ·
Термін SLA. Сортировка по времени в очереди, по умолчанию показываются только
непроверенные. Список практикумов остаётся вторым режимом того же экрана.
Обоснование — в `13` §14: у наставника вопрос «что мне сегодня проверить».

### Г-13.2 Доработки в эталоне нет

**Гипотеза.** В форме практикума нет ни критериев, ни лимита возвратов; отдельная
очередь называется «Коментарі практикумів» — то есть возврат на доработку, если он есть,
реализован комментарием, а не статусом.

**Решение для Lola `[решение]`.** Вводим статус `rework` и `max_reworks` (по умолчанию 2).
Причина: без явного статуса сдача, возвращённая комментарием, выпадает из отчётов —
формально она «на перевірці» бесконечно. Счётчик нужен, чтобы наставник и ученик
не гоняли работу по кругу; после исчерпания остаются только «Зараховано» и «Не зараховано».

### Г-13.3 Шкала практикума — общая шкала заданий

**Проверено.** Справочник `/manage/tasks/evaluation-scales` («Шкали оцінки завдань»)
имеет колонки **Назва · Відображати у звітах · Характеристика оцінки ·
Діапазон оцінки завдання**. Это отображение диапазона процентов в название и характеристику.

**Решение.** Практикум использует этот же справочник: результат проверки — процент,
шкала переводит его в «Зараховано / Потребує доопрацювання / Не зараховано»
или в любую другую шкалу тенанта. Отдельной шкалы практикума не заводим.

### Г-13.4 История сдач

**Гипотеза.** В отчёте по тесту эталон хранит «Кращий результат» и «Використано спроб» —
то есть попытки хранятся все. Для практикума логично то же.

**Решение для Lola.** Храним все сдачи (`workshop_submissions`), в отчёте по умолчанию
показывается последняя, история открывается по клику. Файлы прошлых сдач не удаляются
до истечения срока хранения тенанта — иначе при споре нечего показать.
