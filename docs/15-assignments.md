# Lola LMS — ТЗ. Часть 15. Призначення, профілі навчання, правила автоматизації

## 1. Назначение и границы

Назначение («завдання») — центральная управляющая сущность системы: кто, что, когда должен
пройти и по каким правилам. Здесь же живут параметры прохождения теста (попытки, проходной
балл, таймер) — это снято с эталона и является ключевым решением архитектуры.

Три уровня автоматизации:
1. **Ручное назначение** — выбрал людей, назначил курс.
2. **Профиль обучения должности** — при появлении человека на позиции ему автоматически
   назначается набор курсов (в эталоне это «Правила автоматизації», названные по должностям).
3. **Правила автоматизации** — «при событии X с условием Y сделать Z».

Входит: сущность назначения, конструктор аудитории, параметры, напоминания, раскрытие в записи,
профили обучения, правила автоматизации, отмена и продление.
Не входит: сами записи и прогресс (`10`), уведомления как канал (`23`).

### 3.6 `automation_rules`

Структура снята с эталона 19.09.2026 (правило «Бариста»). В эталоне правило определяет
**только аудиторию**, а что назначать — задаёт траектория или программа, которая на это
правило ссылается. Lola повторяет эту схему: правило — переиспользуемый фильтр людей.

Форма правила в эталоне:
- «Назва*», «Опис»;
- триггер — два варианта: «вперше активовані в системі» и «отримали зазначені атрибути
  (Місто, Посада, Підрозділ, Мітка)»;
- четыре группы условий — **Міста, Посади, Підрозділи, Мітки**, у каждой переключатель
  «Всі, окрім» (инверсия) и значение «Будь-яке/Будь-який»;
- блок «Буде призначено» — сводка выбранного («Міста (1): Одеса; Посади (1): Бариста;
  Підрозділи: Всі; Мітки: Всі»);
- опции: «Опублікувати», «Призначення через (кількість днів)» — отложенное назначение;
- блок «ВИКОРИСТОВУЄТЬСЯ ДЛЯ» — список траекторий и программ, которые ссылаются на правило.

Действия над правилом в списке: «Редагувати», «Список користувачів» (кто подпадает прямо
сейчас), «Виконати вручну» (разовый запуск), «Видалити».

| Поле | Тип | Комментарий |
| --- | --- | --- |
| `name` | text | |
| `trigger` | text | см. §7.6 |
| `conditions` | jsonb | набор условий с `and`/`or` |
| `actions` | jsonb | см. §7.7 |
| `is_active` | boolean | |
| `run_limit` | jsonb | `{"once_per_user": true}` — чтобы не сработать дважды |
| `last_run_at` | timestamptz | |
| `stats` | jsonb | сколько раз сработало |

`automation_runs`: `rule_id`, `user_id`, `trigger_payload`, `actions_result`, `status`,
`error`, `created_at` — журнал срабатываний.

## 4. Состояния

`draft → active → paused → archived`. В `paused` новые записи не создаются, существующие
продолжают жить. `archived` — назначение снято с автосинхронизации, история сохранена.

## 5. Экраны

### 5.1 Список назначений

Колонки (как в эталоне): Назва, Тип, Автор, Мітки, Створено, Початок, Завершення,
Користувачі, Прогрес (завершили/назначено), Статус.
Вкладки: `Усі` · `Вручну` · `Автоматично` · `За каталогом` · `За траєкторією` · `Архів`.
Фильтры: тип, автор, метки, период создания, период дедлайна, контент, точка, статус.
Массовые действия: приостановить, возобновить, продлить срок, архивировать, напомнить всем.

### 5.2 Создание назначения

**Снято с эталона 19.09.2026.** Создание начинается с выбора типа контента —
в меню «Створити завдання» одиннадцать пунктов, каждый со своим URL:
`training-program`, `course`, `resource`, `workshops`, `meetup`, `test`, `complex-test`,
`polls`, `poll360`, `check-list`, `webinar`. То есть назначить можно любой объект системы,
включая опрос 360° и чек-лист.

Дальше экран назначения делится на четыре блока:
1. **Контент** — «Створити новий» или «Обрати з існуючих»;
2. **Налаштування** — «Налаштування параметрів завдання: тривалість, спроби, час,
   та інші обмеження» (это и есть параметры прохождения);
3. **Призначення** — «Призначити завдання користувачам або групі користувачів
   на основі вибраних параметрів»;
4. **Результати** — «Переглядайте та аналізуйте результати» прямо из карточки назначения.

Сверху — метки, **компетенции** («Обрати компетенції») и авторы. Отдельно есть страница
«Додаткові параметри для завдань» (`/manage/tasks/parameters-v3`) — тенант заводит свои
произвольные параметры назначения; в Lola это `assignments.custom_fields jsonb`
с описанием полей в настройках тенанта `[решение]`.

Lola сохраняет эту структуру, но без визарда: те же четыре блока на одном экране.

Один экран, четыре блока, без мастера-визарда:

**1. Що призначаємо** — поиск по контенту с фильтром по типу; карточка выбранного:
название, тип, длительность, число уроков; переключатель «Зафіксувати поточну версію».

**2. Кому** — конструктор правил: кнопка «+ Умова», каждая строка — тип и значения;
переключатель «Будь-яка з умов / Усі умови»; блок «Виключити»; справа живой счётчик
**«Під умову підпадає 38 людей»** и ссылка «Переглянути список» (модалка со списком,
можно снять галочки — тогда люди попадают в `exclude`).

**3. Коли** — старт (сразу / дата), дедлайн (без срока / дата / «N днів з призначення»),
повтор (нет / каждые N месяцев), переключатель «Підхоплювати нових людей».

**4. Як проходити** — две вкладки, как в эталоне:
- «Параметри»: проходной балл, попытки, пауза, таймер, перемешивание, показ ответов,
  пропуск и возврат, строгий порядок, досрочное завершение, сертификат;
- «Нагадування»: за сколько дней, в день срока, после срока, каналы, уведомлять ли
  руководителя и через сколько.

Кнопки: «Зберегти чернетку», «Призначити». Перед назначением — подтверждение:
«Призначити «{курс}» 38 людям? Дедлайн 24 вересня».

### 5.3 Карточка назначения

Шапка: название, тип, статус, автор, даты. Плитки: назначено, начали, завершили,
просрочено, средний балл. Таблица людей с фильтром по статусу и действиями
(продлить, снять, напомнить, перезапустить). Вкладка «Журнал» — изменения назначения
и срабатывания автосинхронизации.

### 5.4 Профили обучения

Список: название, к кому применяется, сколько элементов, сколько людей охвачено, активен.
Редактор: область применения (позиции, уровни, точки), список курсов с порядком и сроками
(drag-and-drop), переключатель «Застосувати до тих, хто вже працює», кнопка
«Попередній перегляд» — показывает, кому и что прилетит, до применения.

### 5.5 Правила автоматизации

Список: название, триггер, сколько раз сработало, последнее срабатывание, активно.
Редактор: три блока — «Коли» (триггер), «Якщо» (условия), «Тоді» (действия);
кнопка «Тестовий запуск» — показывает, что произошло бы, ничего не меняя.
Журнал срабатываний с фильтром по человеку и результату.

### 6.2 Отмена назначения

Показывает: «Це зніме навчання з 12 людей. 4 вже почали». Радио: что делать с начатыми —
«Дати доучитись» (по умолчанию) / «Зняти повністю». Причина обязательна.

## 7. Правила и алгоритмы

1. **Раскрытие аудитории.** `assignment.expand` вычисляет список людей по правилам,
   вычитает `exclude`, создаёт записи. Задача идемпотентна: повторный запуск не дублирует.
2. **Автосинхронизация.** При `auto_sync=true` задача `assignment.sync` раз в час и по
   событиям (`user.created`, `user.placement_changed`, `user.role_changed`, `user.tag_changed`)
   добавляет новых подходящих людей. Ушедших из-под условия **не снимает** — запись остаётся,
   иначе перевод между точками стирал бы прогресс `[решение]`.
3. **Приоритет параметров.** Настройки тенанта → параметры назначения → снимок в попытке.
   Изменение назначения не влияет на начатые попытки.
4. **Дедлайн.** `absolute` — общая дата для всех; `relative` — от даты создания записи,
   поэтому у разных людей разные даты.
5. **Повтор.** `recurrence.every_months` создаёт новую запись по завершении срока действия
   предыдущего результата, а не по календарю от назначения.
6. **Триггеры правил автоматизации:** `user.created`, `user.activated`,
   `user.placement_changed`, `user.role_changed`, `user.tag_added`, `course.completed`,
   `course.failed`, `certificate.expiring` (за N дней), `certificate.expired`,
   `assignment.overdue`, `date.schedule` (по расписанию cron), `probation.ending`
   (окончание испытательного срока, если ведётся `[решение]`).
7. **Действия правил:** `assign_content` (курс, программа, тест, практикум),
   `notify_user`, `notify_manager`, `add_tag`, `remove_tag`, `add_role`, `remove_role`,
   `create_task_for_mentor`, `webhook`.
8. **Ограничение повторов.** `run_limit.once_per_user` — правило срабатывает на человека
   один раз; `once_per_period` — не чаще раза в N дней.
9. **Тестовый запуск** обязателен перед активацией правила: показывает список людей
   и действий без записи в базу.
10. **Защита от лавины.** Одно раскрытие создаёт не больше 5000 записей за проход;
    остальное — следующими партиями, чтобы не положить очередь уведомлений.
11. **Профиль обучения** = автоматическое назначение: при смене позиции человек получает
    недостающие курсы профиля; уже пройденные (с действующим результатом) не назначаются заново.
12. **Возможности этапа ограничивают состав `params`** (пакет `docs/v2`, П-15,
    `docs/v2/33-lifecycle.md` §7.5). Этап курса объявляет набор булевых возможностей; если
    возможность выключена, соответствующий ключ `params` при создании и правке назначения
    отбрасывается — молча, как и ключ, чужой типу контента. Иначе у курса «Бази знань» в
    `params` оказался бы `deadline_mode`, и отчёт «нарушены сроки» начал бы считать нарушения
    там, где сроков нет.
    Соответствие «возможность → ключи» (`server/services/taskParams.ts`): `deadline` —
    `deadline_mode`, `time_limit_sec`; `attempts` — `attempts_allowed`, `attempt_cooldown_min`;
    `grading` — `result_source`, `pass_score`, `fix_result`, `scale_id`; `certificate` —
    `certificate_id`; `counts_in_rating` — `points`. Прочие возможности (`progress`, `review`,
    `graph`, `ai_generate`, `applies_to_*`) ни одного ключа `params` не адресуют — они меняют
    экраны и процессы, а не правила прохождения.
    **Правила прохождения остаются в назначении** (правило 11 CLAUDE.md): этап ограничивает
    набор ключей, но ни `attempts`, ни `pass_score`, ни `due_at`, ни `time_limit` не хранит.
    Ветка по этапу — только `stageCan()`, сравнение с кодом этапа запрещено (`33` §7.1).
13. **Уже созданные назначения при смене этапа курса не пересчитываются** (`33` §7.4,
    инвариант 1): их параметры зафиксированы в момент создания. Новое правило действует на
    новые записи; правка назначения применяет возможности этапа **к правке**, а не к тому,
    что уже сохранено.
14. **Вакансия не является носителем правил прохождения** (П-15, `docs/v2/29-vacancies.md`).
    Она хранит шаблон параметров, который применяется созданием обычного `assignments` —
    правило 11 CLAUDE.md не нарушается, правила по-прежнему живут в назначении.

## 12. Крайние случаи

- Аудитория 3000 человек → раскрытие партиями, прогресс виден в карточке назначения.
- Человек попадает под два назначения одного курса → создаётся одна запись, вторая
  привязка фиксируется в `enrollment_events` `[решение]`.
- Курс снят с публикации, назначение активно → новые записи не создаются, автору уведомление.
- Правило автоматизации ссылается на удалённый курс → правило деактивируется, админу алерт.
- Назначение с дедлайном в прошлом (создали задним числом) → форма предупреждает,
  но разрешает; записи сразу `expired`.
- Человек в отпуске → отпусков система не знает; митигация — метка «у відпустці»
  и исключение по метке `[решение]`.

## 13. Критерии приёмки

1. **Дано** аудитория «позиция Бариста + точка Лазарева», **коли** нажали «Переглянути список»,
   **тоді** счётчик и список совпадают с фактическим числом людей.
2. **Дано** `auto_sync=true`, **коли** нового человека поставили на позицию Бариста,
   **тоді** в течение часа у него появилась запись.
3. **Дано** назначение с `attempts_allowed=1`, **коли** ученик стартовал попытку,
   **тоді** в снимке попытки `attempts_allowed=1`, и изменение назначения на 3 не влияет
   на текущую попытку.
4. **Дано** повторный запуск `assignment.expand`, **тоді** число записей не изменилось.
5. **Дано** профиль должности с тремя курсами, один из которых человек уже прошёл,
   **коли** профиль применяется, **тоді** назначаются только два недостающих.
6. **Дано** правило «при завершении курса А назначить курс Б», `once_per_user`,
   **коли** человек прошёл А дважды, **тоді** Б назначен один раз.
7. **Дано** отмена назначения с «дати доучитись», **тоді** начатые записи остаются
   активными, ненач
атые исчезают.

### 14.3 Параметры назначения: пять групп

Экран `/manage/tasks/:id/settings-v3`, боковое меню:
**Загальне · Термін виконання · Результат · Нагороди · Метод призначення**.

#### Загальне — для назначения теста

| Параметр | Значения |
| --- | --- |
| **Кількість питань** | «Всі» \| **«Одне питання від кожної групи»** \| «Обмежено» |
| **Кількість спроб** | «Необмежено» \| «Обмежено» |
| **Час для проходження тесту** | «Необмежено» \| «Обмежено» |
| Режим тренування | «Дозволити перевірку правильних відповідей» |
| Дозволити відкриття інших сторінок | «…порталу під час тестування» |
| Показати протокол помилок | «…протокол неправильних відповідей» |
| Приховати правильні відповіді з протоколу | да/нет |

Подгруппа **ПИТАННЯ**: «Перемішувати варіанти відповідей»,
«Дотримуватися послідовності питань», «Пропускати питання»,
«Показувати користувачу, чи правильно він дав відповідь на питання»,
«Перейти до наступного питання вручну».

Подгруппа **ІНШІ ПАРАМЕТРИ**: «Дозволити коментування»,
«Повідомлення про успішне та неуспішне виконання завдання».

Для назначения курса та же группа «Загальне» содержит только «Дозволити коментування»
и «Повідомлення…» — набор параметров зависит от типа контента.

#### Термін виконання

- **«Термін завершення завдання»**: «необмежено» \| «кількість днів з моменту призначення»
  \| «календарний період».
- **«Час проходження завдання»**: «Необмежено» \| «Обмежено» (у курса; у теста эту роль
  играет «Час для проходження тесту»).

Тот факт, что срок задаётся *от момента назначения*, а не только календарём, — ключевой
для сети: новый человек получает тот же курс с тем же «семь дней», а не с прошлогодней датой.

#### Результат

- **«Результатом виконання завдання буде»**: «результат останньої спроби» \|
  «кращий результат з усіх спроб».
- **«Поріг проходження»** — «Встановити поріг, %». У курса рядом предупреждение:

  > «Увага! При створенні даного курсу для підсумкового тесту було встановлено поріг 0%.
  > Ви можете задати тут інше значення порогу проходження, яке використовуватиметься
  > для курсу та підсумкового тесту.»

  Это прямое подтверждение всей архитектуры: порог, заданный в назначении, **перекрывает**
  порог контента.
- «Фіксувати результат завдання» (у курса).
- **«Перетворити результат за шкалою»** → «Обрати шкалу» — процент переводится в шкалу
  из словаря (`20` §14.1).

#### Нагороди

«Бейдж за виконання завдання», «Сертифікат за завдання»,
«Бали за виконання завдання» («Використовуються для розрахунку рейтингу користувача»),
«Бонуси за виконання завдання» («Використовуються для купівлі товарів у магазині подарунків»).

Баллы и бонусы — **разные валюты**: баллы идут в рейтинг, бонусы тратятся в магазине.
В `21` §4 это учтено; здесь подтверждено, что начисляются они назначением, а не контентом.

> [дополнено, `gamification` (24.09.2026), `21` §17] Начисляет выполненное назначение, один раз на
> человека и назначение, строкой книги `points_ledger` (`02` §2.10). Пустые поля «Бали/Бонуси за
> виконання завдання» — правило тенанта по типу задания («Правила нарахування»), форма показывает
> его подсказкой; явный `0` — без нагороды. Баллы режет возможность этапа `counts_in_rating`.

#### Метод призначення

«Доступ через каталог навчання», «Автоматизація» → **«Правило автоматизації»**
(выбор из списка правил, см. `17` §14), «Використовувати в планах розвитку».

### 14.4 Аудитория — не конструктор, а фильтруемый список

`/manage/tasks/:id/assign-v3`. Вкладки: **Всі · Призначено (N) · Непризначені**.
Фильтры: Посада · Місто · Підрозділ · Мітки · Рівень посади · Дата реєстрації ·
Дата призначення · Спосіб призначення · Оргструктура.
Колонки таблицы те же плюс кнопка **«Призначити»** в каждой строке.
Сверху — **«Інші методи призначення» → «Призначити через CSV»**.

Колонка **«Спосіб призначення»** показывает, откуда человек получил задание
(встреченное значение — «Траєкторія»).

**Где конструктор аудитории.** На самом экране назначения его нет: там фильтруемый список
людей с ручным «Призначити» по строке и загрузка CSV. Конструктор живёт **в правиле
автоматизации** — четыре измерения (Місто, Посада, Підрозділ, Мітка), каждое с режимом
«Всі, окрім», и живая сводка «Буде призначено» (разобрано в `17` §14.2).

Для Lola это значит: один и тот же конструктор аудитории используется дважды — в разовом
назначении и в правиле. В эталоне он доступен только в правиле, и это заметное неудобство:
чтобы назначить курс «всем продавцам, кроме Аркадии» один раз, приходится заводить правило,
которое потом висит навсегда. Разовое применение конструктора — наше `[решение]`.

Фильтруемый список и колонку **«Спосіб призначення»** берём обязательно: без них
не видно, почему человеку прилетело задание.

### 14.5 Додаткові параметри для завдань

`/manage/tasks/parameters-v3` — справочник произвольных полей назначения.
Типы поля: **«Текстове поле» · «Вибір зі списку» · «Числове поле»**.
Есть «Створені параметри» — переиспользование уже описанного поля.

### 14.6 Уведомление об изменении контента

В шапке списка назначений эталон показывает:

> «14 завдань було змінено. Сповістити про оновлення призначеним користувачам?»
> + кнопка «Керувати сповіщеннями»

То есть правка контента не рассылает уведомления сама — система копит список изменённых
заданий и спрашивает администратора. Берём это правило в `23`: массовая рассылка
«материал обновлён» только по явной команде человека, иначе редактор запятой разбудит точку.

## 15. Гипотезы и принятые по ним решения

### Г-15.1 Напоминания по заданию

**Снято частично.** В шапке списка назначений есть вкладка «Нагадування», открывающая
модалку **«Нагадування про завдання»** с единственным видимым переключателем
**«Ввімкнути відправку нагадувань»**. Состав полей после включения снять не удалось:
это потребовало бы изменить настройку в работающей системе.

**Гипотеза.** После включения открывается расписание напоминаний: за сколько дней
до срока и с какой периодичностью напоминать, плюс напоминание после просрочки.
Косвенное подтверждение — в настройках времени отправки есть отдельная строка
«Час відправлення повідомлень про завдання, термін виконання яких закінчується»
(`23` §13.2.1), то есть напоминания о приближении срока точно существуют.

**Чем проверяется.** Включить тумблер в модалке, не сохраняя.

**Решение для Lola `[решение]`.** Модель напоминаний задаётся на назначении:

| Поле | Значение по умолчанию |
| --- | --- |
| `reminders_enabled` | да |
| `before_due_days[]` | `[7, 3, 1]` |
| `on_due_date` | да |
| `after_due_every_days` | 3, максимум 5 раз |
| `escalate_to_manager_after_days` | 7 после просрочки |
| `channel` | по умолчанию человека |

Почему список дней, а не одно число: «за неделю» нужно, чтобы человек успел спланировать
смену, «за день» — чтобы не забыл, «в день Х» — чтобы понял, что всё.
Ограничение на пять напоминаний после просрочки — чтобы система не превратилась в спам:
после пятого вопрос решает руководитель, а не бот.

### Г-15.2 Выход из-под условия автоматического назначения

**Гипотеза.** Правило автоматизации срабатывает по событию («вперше активовані в системі»,
«отримали зазначені атрибути»), а не пересчитывается постоянно (`17` §14.2).
Значит при смене должности назад старые назначения у человека **остаются**,
и снимать их эталон не умеет.

**Чем проверяется.** Перевести тестового человека с должности, попавшей под правило,
на другую и посмотреть, исчезли ли назначения.

**Решение для Lola `[решение]`.** Разводим два случая явно, настройкой правила
**«Що робити, коли людина перестала відповідати умові»**:

1. `keep` (по умолчанию) — назначение остаётся. Подходит для обязательного:
   человек прошёл обучение по кассе, ушёл в кухню — факт обучения не отменяется.
2. `cancel_unstarted` — ненача́тые назначения снимаются, начатые остаются.
   Это разумное поведение по умолчанию для стажёрских траекторий.
3. `cancel_all` — снимаются все, с записью в аудит и статусом `cancelled`,
   результаты сохраняются в истории.

Никогда не удаляем данные: снятие — это статус, а не `delete`.

### Г-15.3 Колонки «ІПР» и «Компетенції» в списке назначений

**Гипотеза.** В шапке карточки назначения есть «Обрати компетенції», а в параметрах —
«Використовувати в планах розвитку». Колонки в списке — счётчики: сколько компетенций
привязано к назначению и в скольких планах развития оно используется.
В снятых данных обе колонки показывают `0` у назначений без этих связей.

**Решение для Lola.** Так и реализуем: `assignment_competencies` (многие-ко-многим)
и флаг `use_in_dev_plans`. При успешном завершении задания привязанные компетенции
получают отметку подтверждения с источником `assignment` (`19` §5).

### Г-15.4 Формат CSV для «Призначити через CSV»

**Гипотеза.** Кнопка «Призначити через CSV» стоит рядом со списком людей назначения,
значит файл содержит только идентификаторы людей, а само задание берётся из контекста.
Скорее всего, это одна колонка — e-mail или «Зовнішній №».

**Решение для Lola `[решение]`.** Принимаем файл с одной обязательной колонкой-ключом
на выбор: `email`, `phone` или `external_id` (определяется по заголовку), плюс
необязательные `due_at` и `starts_at` — чтобы можно было раздать одно задание
с разными сроками по точкам. Разделитель — запятая или точка с запятой, кодировка
UTF-8 и CP1251 (Excel на Windows), первая строка — заголовок.
Перед применением показывается предпросмотр: сколько найдено, сколько не найдено,
