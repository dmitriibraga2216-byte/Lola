# Lola LMS — ТЗ. Часть 16. Люди, оргструктура, довідники, імпорт

Состав полей и действий снят с эталона 19.09.2026 (карточка пользователя, список, импорт)
и приведён к решениям Lola (вход по телефону вместо логина и пароля).

## 1. Назначение и границы

Модуль отвечает за то, кто есть в системе, где он работает, что умеет и какие у него права.
Всё остальное (назначения, отчёты, аттестации) опирается на эти данные.

Входит: профиль человека, размещения (город, подразделение, точка, должность, уровень),
роли и области, справочники, группы и сегменты, оргструктура, функциональные руководители,
импорт и синхронизация, журналы сессий и безопасности.
Не входит: аутентификация как процесс (`01-roles.md` §1.5), назначения (`15`).

### 3.2 Размещение — `user_placements`

`location_id` (точка), `position_id` (должность), `position_level_id` (уровень должности),
`city_id`, `org_unit_id` (подразделение), `is_primary`, `started_at`, `ended_at`.

История размещений хранится: отчёты по прошлым периодам должны показывать человека там,
где он работал тогда.

### 3.3 Справочники

| Справочник | Поля | Комментарий |
| --- | --- | --- |
| `cities` | name, is_active | «Міста» |
| `positions` | name, code, level_id, is_active | «Посади» |
| `position_levels` | name, rank int | «Рівні посад» — джун/мидл/старший, влияет на профили обучения |
| `org_units` | name, parent_id, path | «Підрозділи» — дерево |
| `locations` | name, address, city_id, org_unit_id, timezone, manager_id | точки |
| `tags` | name, color, kind | «Мітки»: сквозные для людей, контента, назначений |

Правила: элемент справочника нельзя удалить, если он используется; можно деактивировать.
Переименование сохраняет связи. Слияние двух значений — отдельная операция с журналом.

### 3.4 Группы и сегменты — `user_groups`

`name`, `kind` (`static` \| `dynamic`), `members` (для статической), `filter` (для динамической,
та же структура, что `audience.segment` в `15`), `is_active`, `recalc_at`.

### 3.5 Функциональные руководители — `functional_chiefs`

`user_id` (подчинённый), `chief_id` (руководитель), `kind` (`line` \| `functional`),
`scope` (по точке, по подразделению, по направлению). Нужны там, где руководитель
не совпадает с деревом оргструктуры: наставник по качеству, тренер сети.

### 3.6 `import_jobs`

`source` (`csv` \| `api` \| `hrm` \| `ad` \| `azure_ad`), `file_key`, `mapping jsonb`,
`options jsonb`, `status`, `stats jsonb` (`{rows, created, updated, skipped, errors}`),
`report_key`, `created_by`, `started_at`, `finished_at`.

## 4. Состояния человека

`invited` (создан, не входил) → `active` (входил) → `suspended` (заблокирован временно)
→ `archived` (уволен). Отдельный флаг `is_hidden` не меняет статус, а убирает человека
из списков и рейтингов (например, для собственника, который не должен светиться).

Правила: архивирование снимает активные записи обучения (`cancelled`), закрывает сессии,
отзывает роли, но сохраняет всю историю и сертификаты.

## 5. Экраны

### 5.1 Список людей

Вкладки: `Активні` · `Заблоковані` · `Усі користувачі`.
Колонки (настраиваются кнопкой «Налаштування таблиці»): ПІБ, посада, рівень посади, місто,
підрозділ, точка, ролі, мітки, телефон, дата реєстрації, остання активність, зовнішній №.
Фильтры: поиск по имени и телефону, посада, рівень, місто, підрозділ, роль, мітка,
период регистрации, период активности, «Фільтр по оргструктурі» (выбор узла дерева).
Кнопки: «Додати користувача», «Імпорт користувачів», «Експорт в Excel», «Скинути фільтр».

Действия в строке (как в эталоне): «Деталі», «Редагувати», «Список ролей»,
«Закрити всі сесії», «Заблокувати», «Видалити» (в Lola — «Архівувати»).
Вместо «Змінити пароль» в Lola — «Надіслати новий код входу» и «Скинути прив'язку Telegram».

Массовые действия: добавить метку, сменить точку, назначить роль, отправить приглашение,
архивировать, назначить обучение.

5. **Активність** — сессии (устройство, IP, последняя активность, кнопка «Закрити»),

### 5.3 Оргструктура

Дерево: подразделения → точки → люди. Перетаскивание узлов, редактирование в боковой панели,
счётчики людей на каждом узле. Отдельный режим «Функціональні керівники» — матрица
«кто кому подчиняется вне дерева».

### 5.4 Импорт

Источники (как в эталоне): **CSV**, **API**, **Active Directory**, **Azure AD**, **HRM-система**.
В Lola на R1 — CSV и API; AD/Azure/HRM — R2, разъёмы описаны в `09-integrations.md`.

Шаги CSV-импорта:
1. Загрузка файла (drag-and-drop или кнопка), скачать шаблон.
2. Сопоставление колонок: система угадывает, человек поправляет; сопоставление сохраняется
   как пресет для следующего раза.
3. Предпросмотр: таблица с подсветкой — зелёные «створити», жёлтые «оновити»,
   красные «помилка» с причиной в строке; счётчики сверху.
4. Опции: создавать ли отсутствующие справочники, что делать с людьми не из файла
   (ничего / архивировать), отправлять ли приглашения.
5. Применение фоновой задачей с прогрессом; отчёт xlsx с построчным результатом.

### 5.5 Журналы

**Сессии**: человек, устройство, браузер, IP, вход, последняя активность, кнопка закрытия.
**Безопасность**: вход, неудачный вход, смена роли, закрытие сессий, экспорт данных,
impersonation, изменение прав. Фильтры по человеку, типу события, периоду.
**Импорт**: история загрузок с отчётами.

### 6.2 Назначение роли

Роль (селект), область (тенант / подразделение / точка), срок действия (бессрочно или до даты),
причина (для аудита). Проверка: нельзя снять последнего администратора тенанта.

### 6.3 Архивирование

Причина (увольнение, перевод, ошибка, другое), дата, переключатели: закрыть сессии (по умолчанию),
снять незавершённое обучение (по умолчанию), сохранить в отчётах (по умолчанию).

## 7. Правила и алгоритмы

1. **Телефон — ключ.** Уникален в тенанте; при импорте дубль телефона = ошибка строки.
   Один человек в двух тенантах — две разные записи `users` с одним номером.
2. **Идентификация при импорте:** сначала `external_id`, затем `phone`, затем `email`.
3. **Смена должности** закрывает текущее размещение (`ended_at`) и создаёт новое;
   срабатывают правила автоматизации (`15` §7.6) и профили обучения.
4. **Блокировка** запрещает вход, но не снимает обучение: человек вернётся из отпуска
   и продолжит. Архивирование — снимает.
5. **Скрытый человек** не попадает в рейтинги, списки выбора и публичную оргструктуру,
   но остаётся в отчётах для администратора.
6. **Последний администратор** не может быть заблокирован, архивирован или лишён роли.
7. **Слияние дублей** (`people.merge`): выбирается основная запись, история обучения,
   сертификаты и попытки переносятся, вторая архивируется с пометкой «Обʼєднано з …».
8. **Экспорт в Excel** содержит только те колонки, которые человек видит по своей роли.
9. **Удаление данных по запросу** (`gdpr.erase`): ФИО → «Користувач #id», телефон, почта,
   дата рождения, фото — в null; результаты обучения сохраняются обезличенно; операция
   логируется и необратима.

## 12. Крайние случаи

- Импорт 2000 строк, 150 с ошибками → применяются 1850, отчёт содержит 150 строк с причинами.
- В файле человек без телефона, но с `external_id` → строка принимается, человек создаётся
  в статусе `invited` без возможности входа, в отчёте предупреждение.
- Два человека с одинаковым ФИО на одной точке → разрешено, различаются по телефону.
- Человек уволился и вернулся через полгода → та же запись, статус `active`, новое размещение,
  история цела.
- Смена телефона → старый номер освобождается, сессии закрываются, уходит уведомление.
- Человек удалил Telegram-аккаунт → `telegram_chat_id` сбрасывается при ошибке 403,
  канал переключается на SMS.

## 13. Критерии приёмки

1. **Дано** CSV на 500 строк, из них 30 с неверными телефонами, **коли** импорт применён,
   **тоді** создано 470, отчёт содержит 30 строк с указанием колонки и причины.
2. **Дано** человек переведён с точки А на Б, **коли** открыть отчёт за прошлый месяц,
   **тоді** он показан на точке А.
3. **Дано** единственный администратор тенанта, **коли** попытаться снять с него роль,
   **тоді** отказ с пояснением.
4. **Дано** человек архивирован, **тоді** его сессии закрыты, активное обучение снято,
   сертификаты остались доступны по публичной ссылке.
5. **Дано** `is_hidden=true`, **тоді** человек не появляется в рейтинге и в выборе людей
   при назначении, но виден администратору в списке.
6. **Дано** слияние дублей, **тоді** попытки и сертификаты обеих записей доступны
   в основной, вторая помечена «Обʼєднано».

## 14. Сверено с эталоном

Проверено 19.09.2026 (`/process/users`, `/users/import`).

**Раздел «Користувачі» эталона целиком:**

| Экран | Путь |
| --- | --- |
| Користувачі | `/users` |

| Організаційна структура | `/orgstructure/v3` |
| Функціональні керівники | `/orgstructure/functional-chiefs` |
| Історія навчання | `/manage/tasks/study-history` |
| Журнал сесій користувачів | `/users/sessions/report` |
| Журнал сповіщень | `/notifications/report` |
| Протокол імпорту користувачів | `/users/import/reports` |
| Журнал безпеки | `/users/security-journal` |
| Протокол конфліктів в оргструктурі | `/orgstructure/conflicts-history` |
| Спеціальні звіти | `/custom-reports` |
| Міста | `/users/cities` |
| Посади | `/users/positions` |
| Рівні посад | `/users/positions-levels` |
| Підрозділи | `/users/departments` |
| Мітки | `/tags` |

Справочники в эталоне ровно те же четыре, что и в `16` §3.4: города, должности,
уровни должностей, подразделения. **«Функціональні керівники»** — отдельная сущность
поверх оргструктуры: руководитель по функции, не совпадающий с линейным. В `16` §3.5 это
учтено как `manager_type`, теперь подтверждено эталоном.

**Импорт людей** (`/users/import`) — пять источников вкладками:
**CSV · API · Active Directory · Azure Active Directory · HRM**. Для CSV — зона загрузки
файла и ссылка на описание формата; сопоставление колонок открывается после загрузки.
Результат каждой загрузки складывается в «Протокол імпорту користувачів».

**Протокол конфликтов оргструктуры** — отдельный журнал: эталон не падает на конфликте
(человек в двух подразделениях, начальник сам себе подчинён), а пишет строку и продолжает.
Это же правило принимаем в `16` §7.

### 14.1 Группы пользователей

`/users/groups`. Колонки: Назва · **Кількість користувачів** · Дата зміни.
Фильтры: «Всі», **«Оргструктура»**, «Кількість користувачів», «Дата зміни».

В снятой установке группы двух сортов вперемешку: точки («Б12 ТЦ Меркурій»,
«Б11 5 ст.Фонтану»), цеха («Кондитерський цех», «Кухня Б12 ТЦ Меркурій», «Зал ТЦ Меркурій»)
и роли («Керівники ТТ» — 7 человек, «Керівники кухні» — 12, «Операційний відділ» — 0).
Всего около 40 групп.

Фильтр «Оргструктура» означает, что часть групп порождена оргструктурой автоматически,
а часть заведена руками. В `16` §3.3 вводим флаг `is_org_derived`: производные группы
нельзя править вручную, они пересобираются при импорте.

### 14.2 Метки

`/tags`, заголовок «Керування мітками». Колонки: **Мітка · Опис · Область дії мітки**.
Значения области, встреченные в списке: `course`, `resource`, `user`. Меток около 130.

**Область действия — обязательное поле.** Без неё выпадающий список меток на форме курса
показывает метки должностей, а на карточке человека — метки выпечки; в снятой установке
это уже произошло, и часть меток области не имеет вовсе.

Там же виден урок про валидацию: одна из меток — кусок html, случайно вставленный
из буфера (`<iframe-resource-in-resource-iframe=...`). В Lola: метка ≤ 40 знаков,
без угловых скобок, с подтверждением при создании новой прямо из формы контента.

### 14.3 Организационная структура

`/orgstructure/v3`. Слева дерево **«Структура компанії»** (в снятой установке корни:
«Керуюча компанія», «Торгові точки», «Офіс»), кнопка «Додати підрозділ»,
справа — сотрудники выбранного подразделения («Тут будуть відображатися співробітники
відділу»). Вкладка «Налаштування» ведёт на те же «Політики» (`24` §3.4.1),
раздел «Оргструктура».

Режим оргструктуры задаётся политикой, а не экраном: «За групами користувачів» \|
«На основі даних імпорту» \| «Гібридний». Отсюда и «Протокол конфліктів в оргструктурі» —
в гибридном режиме ручная правка и импорт неизбежно спорят.

**Для Lola.** Дерево подразделений и точки — разные оси (`16` §3.2): «Б7 на Бочарова» —
это и точка на карте, и узел структуры. Эталон их смешивает в одном дереве, и в снятой
установке видно результат: подразделения называются «Б6, вул. Кримська 70/1».
Разделяем: `org_units` (кто кому подчиняется) и `locations` (где человек работает).

### 14.5 Роли: их нельзя завести самому

`/users/:id/roles` — «Редагування ролей користувача»: шапка с ПІБ, городом,
подразделением и должностью, ниже — чекбоксы ролей. В снятой установке ролей четыре:
**«Адміністратор Т.Т.» · «Адміністратор.» · «Користувач.» · «Тьютор.»**
Ролей у человека может быть несколько.

**Экрана создания или редактирования роли в интерфейсе тенанта нет.** Набор ролей
и их права задаёт поставщик; администратор сети может только раздать готовые.
Точки в названиях («Адміністратор.», «Користувач.») — след ручного заведения
на стороне вендора.

**Решение для Lola `[решение]`.** Редактор ролей со скоупами (`24` §3.5) — наше
добавление, и оно оправдано: у сети точек появляются роли, которых нет в коробке
(«наставник только своей точки», «технолог — только производственные курсы»).
Цена — экран прав и аккуратные защиты от снятия последнего администратора.

Смена пароля человеку — отдельный экран `/users/:id/security` («Безпека → Зміна пароля»),
только два поля. Правильное разделение: смена пароля не должна лежать рядом
с редактированием должности.

## 15. Гипотезы и принятые по ним решения

### Г-16.1 Шаблон CSV импорта людей

**Гипотеза.** Экран `/users/import` показывает зону загрузки и ссылку на описание формата;
сопоставление колонок открывается после загрузки файла, а загружать файл в работающую
систему нельзя. Состав колонок выводится из формы создания человека (`16` §14.4):
эталон импортирует то же, что заводит руками.

**Чем проверяется.** Загрузить тестовый CSV и посмотреть экран сопоставления.

**Решение для Lola `[решение]`.** Задаём формат сами, шаблон отдаётся кнопкой
«Завантажити шаблон»:

| Колонка | Обяз. | Комментарий |
| --- | :-: | --- |
| `external_id` | ✓ | ключ идемпотентности; при повторном импорте строка обновляется |
| `last_name` | ✓ | |
| `first_name` | ✓ | |
| `patronymic` | — | |
| `phone` | ✓ | E.164 или местный формат, нормализуется |
| `email` | — | |
| `position` | ✓ | справочник, новое значение — с подтверждением |
| `position_level` | — | |
| `city` | — | |
| `department` | — | |
| `location` | — | точка |
| `manager_external_id` | — | руководитель |
| `hired_at` | — | `ДД.ММ.РРРР` |
| `position_since` | — | |
| `birth_date` | — | |
| `gender` | — | `ч` / `ж` |
| `tags` | — | через `;` |
| `status` | — | `active` / `blocked` |

Правила: колонки сопоставляются по заголовку автоматически, несопоставленные
показываются на экране сопоставления вручную; файл сначала **проверяется целиком**
и показывается протокол-предпросмотр (создать N, обновить M, ошибок K с номерами строк),
и только потом применяется; частичное применение запрещено — либо весь файл, либо ничего.

Отдельно — политика **«Не перезаписувати під час імпорту»** с выбором полей
(снята с эталона, `24` §3.4.1): поля из этого списка импорт не трогает,
даже если они есть в файле. Без неё ночная синхронизация затирает метки,
проставленные руками.

### Г-16.2 Что пишется в журнал безопасности

**Снято частично.** Колонки известны (`22` §13.4), в снятых данных встречается уровень
**«Нормальний»** и комментарий **«Адміністратор заблокував користувача»**.

**Гипотеза.** Журнал пишет события, связанные с доступом и учётными записями:
вход и неудачный вход, блокировка и разблокировка, смена пароля, смена ролей,
смена контактов. Уровень — градация важности, по которой работает переключатель
«Повідомляти про зміни на E-mail».

**Решение для Lola `[решение]`.** Фиксируем перечень событий журнала безопасности:

`login.success` · `login.failed` · `login.blocked` (превышены попытки) ·
`otp.sent` · `otp.failed` · `session.revoked` ·
`user.created` · `user.blocked` · `user.unblocked` · `user.archived` ·
`password.changed` · `password.reset_by_admin` ·
`roles.changed` · `contacts.changed` · `impersonation.started` · `impersonation.ended` ·
`export.personal_data` · `settings.security_changed` · `api_token.created` · `api_token.revoked`

Уровни: `info` (обычные действия), `warning` (неудачный вход, блокировка по попыткам),
`critical` (вход от имени, выгрузка персональных данных, смена настроек безопасности).
На почту по умолчанию уходит `critical`, остальное — по настройке.
