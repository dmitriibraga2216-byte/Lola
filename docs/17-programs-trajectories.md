# Lola LMS — ТЗ. Часть 17. Програми та траєкторії навчання

Структура снята с эталона 19.09.2026 (редактор траектории «Траєкторія навчання бариста»).

## 1. Назначение и границы

**Программа** — линейная последовательность элементов обучения с общим сроком и сертификатом.
**Траектория** — граф: старт, блоки, финиш, с условиями перехода между блоками и режимом
назначения. В эталоне это именно граф с узлами `Start`, набором блоков (курс, ресурс,
практикум) и `Finish`, привязанный к правилу автоматизации по должности.

Для Lola это одна сущность с двумя режимами отображения: `linear` (программа) и `graph`
(траектория) `[решение]` — модель данных общая, редактор переключается.

Входит: конструктор, элементы, условия перехода, режимы назначения, прогресс, сертификат.
Не входит: сами курсы (`11`), назначения (`15`), правила автоматизации (`15` §3.6).

### 3.3 `program_edges` — переходы (для `graph`)

`from_node_id`, `to_node_id`, `condition jsonb` — условие перехода:
`{"type":"always"}`, `{"type":"passed"}`, `{"type":"failed"}`, `{"type":"score_gte","value":80}`,
`{"type":"position_is","ids":[...]}`.

Это позволяет собрать реальную траекторию: провалил тест по кассе — идёшь на дополнительный
курс; сдал с первого раза — сразу к практикуму.

### 3.4 Режимы назначения (снято с эталона)

| Режим | Что значит |
| --- | --- |
| `manual` | «Призначається вручну» — обычное назначение |
| `catalog_free` | «Вільний доступ через каталог навчання» — самозапись без согласования |
| `catalog_request` | «Подання заявки через каталог навчання» — самозапись с согласованием |
| `automation` | «Застосувати правило автоматизації» + выбор правила |

Режимы комбинируются: программа может быть и в каталоге, и назначаться правилом.

### 3.5 `program_enrollments`

`program_id`, `user_id`, `status`, `current_node_id`, `nodes_state jsonb`
(по каждому узлу: статус, дата, балл, ссылка на запись курса), `progress_pct`,
`started_at`, `completed_at`, `due_at`, `certificate_id`.

## 4. Состояния

Программа у человека: `not_started → in_progress → completed | failed | expired | cancelled`.
Узел: `locked → available → in_progress → done | failed | skipped`.

Правило: узел становится `available`, когда выполнены его `unlock_after` по `unlock_rule`.
Для `linear` это просто предыдущий узел.

## 5. Экраны

### 5.1 Конструктор (автор)

**Линейный режим**: список элементов с перетаскиванием, кнопка «+ Додати елемент»
(поиск по контенту с фильтром по типу), у каждого — обязательность, срок, своё название.

**Режим графа**: канва с узлами `Start` и `Finish` (создаются автоматически), блоки
перетаскиваются, соединяются стрелками; на стрелке — условие перехода; у блока — тип
(«Курс», «Ресурс», «Практикум» — как в эталоне) и название. Панель справа — параметры
выбранного узла. Кнопка «Автовирівнювання».

Правая панель «ПАРАМЕТРИ ТРАЄКТОРІЇ» (как в эталоне): метки, публикация, изображение карточки,
«Не призначати завдання після завершення», режим назначения с выбором правила автоматизации
и ссылкой «Створити нове правило автоматизації», сведения «Оновлений» и «Автор».

Проверки перед публикацией: есть путь от `Start` до `Finish`; нет узлов без входящих рёбер;
все элементы опубликованы; нет циклов без условия выхода.

### 5.2 Программа у человека

Вертикальная лента шагов: пройденные — бирюзовые с галочкой, текущий — солнечный с кнопкой,
будущие — приглушённые с замком и подписью «Відкриється після «{назва}»».
Сверху: название, прогресс «3 з 8», срок, сертификат (если есть).
Для графа человеку показывается та же лента — только его фактический путь, без канвы.

### 5.3 Отчёт по программе

Воронка по узлам: сколько дошло до каждого шага, где отваливаются, среднее время
на шаг, средний балл. Таблица людей с текущим шагом.

## 7. Правила и алгоритмы

1. **Прогресс программы** считается по обязательным узлам: `done / required_total`.
2. **Завершение**: достигнут узел `finish` и все обязательные узлы `done`.
3. **Сроки**: у программы общий дедлайн; у узла — свой `due_days` от момента открытия узла.
4. **Условные переходы** вычисляются в момент завершения узла; результат пишется в
   `nodes_state`, чтобы путь человека был воспроизводим.
5. **`no_assign_after_finish`**: после завершения программы правило автоматизации
   повторно её не назначает, даже если человек снова подпадает под условие.
6. **Изменение опубликованной программы** создаёт новую версию; активные прохождения
   остаются на своей `[решение]`.
7. **Уже пройденные элементы** засчитываются: если человек прошёл курс из программы
   раньше и результат действителен, узел сразу `done` (настройка «Зараховувати попередні
   результати», по умолчанию включена) `[решение]`.
8. **Правило автоматизации** определяет только аудиторию (город, должность, подразделение,
   метка, с инверсией «Всі, окрім») и задержку «Призначення через N днів»; что назначать —
   определяет сама программа.

## 8. Уведомления

`program_assigned`, `program_node_unlocked` («Відкрився наступний крок»),
`program_due_soon`, `program_completed` (+ сертификат), `program_stuck`
(человек не двигается 14 дней — руководителю).

## 9. Отчёты

**Звіт з програм**: человек, программа, текущий шаг, прогресс, срок, статус, балл.
**Воронка программы**: по узлам.
**Покрытие**: сколько людей на позиции проходят соответствующую программу.

## 12. Крайние случаи

- Граф с циклом без условия выхода → публикация блокируется.
- Элемент программы архивирован → узел помечается «Недоступно», в знаменатель не входит,
  автору уведомление.
- Человек прошёл программу и снова попал под правило → при `no_assign_after_finish=true`
  повторного назначения нет.
- Два пути из одного узла с пересекающимися условиями → берётся первое подходящее ребро
  в порядке сортировки, остальные игнорируются; предупреждение в редакторе.
- Человек сменил должность в середине программы → программа остаётся, новая программа
  новой должности назначается дополнительно.

## 13. Критерии приёмки

1. **Дано** траектория с ветвлением «сдал → практикум, не сдал → доп. курс»,
   **коли** человек проваливает тест, **тоді** открывается доп. курс, а практикум остаётся закрыт.
2. **Дано** программа из 5 курсов, один пройден ранее с действующим результатом,
   **тоді** прогресс стартует с 1 из 5, узел зачтён.
3. **Дано** `no_assign_after_finish=true`, **коли** человек завершил и снова подпал под правило,
   **тоді** нового назначения нет.
4. **Дано** публикация графа без пути до `Finish`, **тоді** отказ с указанием проблемного узла.
5. **Дано** человек на шаге 3 из 8, **коли** открыть отчёт, **тоді** он виден в воронке
   на третьем шаге.
