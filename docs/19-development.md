# Lola LMS — ТЗ. Часть 19. Розвиток: компетенції, профілі посад, ІПР, цілі, заявки

## 1. Назначение и границы

Модуль отвечает на вопрос «куда человек растёт»: какие компетенции нужны его должности,
где у него разрыв, что он делает для роста и кто это согласовал.

В эталоне это раздел «Розвиток»: мій план розвитку, мої цілі, кар'єрний розвиток, заявки
на зовнішнє навчання, плани розвитку, стратегічний план, налаштування статусів для цілей,
бібліотека компетенцій, профілі посад, цілі співробітників, протокол статусів цілей.

Входит: библиотека компетенций, профили должностей, оценка разрыва, ИПР, цели с настраиваемым
жизненным циклом, карьерные заявки, заявки на внешнее обучение, стратегический план.
Не входит: оценка персонала и чек-листы (`20`), обучение как таковое (`10`–`15`).

## 3. Сущности и поля

### 3.1 `competencies` — библиотека компетенций

| Поле | Тип | Обяз. | Комментарий |
| --- | --- | :-: | --- |
| `name` | text | ✓ | «Робота з гостем у конфлікті» |
| `category_id` | uuid | — | группа: сервис, продукт, управление, безопасность |
| `description` | text | — | что это значит |
| `kind` | text | ✓ | `hard` \| `soft` \| `managerial` |
| `levels` | jsonb | ✓ | 3–5 уровней: `[{level:1, title:"Початковий", behavior:"..."}]` |
| `linked_courses` | uuid[] | — | чем закрывается разрыв |
| `linked_knowledge` | uuid[] | — | статьи базы знаний |
| `is_active` | boolean | ✓ | |

Уровни описываются поведением, а не абстракцией: «Рівень 3 — самостійно вирішує конфлікт
без залучення керівника, фіксує причину в журналі».

### 3.2 `position_profiles` — профиль должности

`position_id`, `position_level_id`, `competency_requirements jsonb`
(`[{competency_id, required_level, is_critical}]`), `mandatory_content jsonb`
(`[{subject_type, subject_id, due_days}]`), `probation_days`, `description`,
`updated_by`, `is_active`.

Профиль — мост между людьми и обучением: из него строятся автоназначения (`15`)
и считается разрыв компетенций.

### 3.3 `competency_assessments` — оценка уровня

`user_id`, `competency_id`, `level`, `source` (`self` \| `manager` \| `test` \| `workshop` \|
`assessment` \| `certification`), `evidence_id` (ссылка на попытку, сдачу, цикл оценки),
`assessed_by`, `assessed_at`, `valid_until`, `comment`.

Текущий уровень человека = последняя действующая оценка с наивысшим приоритетом источника:
`certification` > `assessment` > `test` > `manager` > `self`.

### 3.4 `development_plans` — ИПР

`user_id`, `period_from`, `period_to`, `owner_id` (руководитель), `status`
(`draft` \| `on_approval` \| `active` \| `review` \| `closed`), `summary`, `created_by`,
`approved_by`, `approved_at`, `closed_at`, `result_comment`.

### 3.5 `development_goals` — цели

| Поле | Тип | Обяз. | Комментарий |
| --- | --- | :-: | --- |
| `plan_id` | uuid | — | цель может быть вне плана |
| `user_id` | uuid | ✓ | |
| `title` | text | ✓ | 3–200 |
| `description` | text | — | ≤2000 |
| `kind` | text | ✓ | `competency` \| `learning` \| `result` \| `project` |
| `competency_id` | uuid | — | если цель про компетенцию |
| `target_level` | int | — | до какого уровня |
| `metric` | text | — | как измеряем: «Час збирання сету ≤ 6 хв» |
| `linked_content` | jsonb | — | курсы, практикумы, занятия |
| `due_at` | date | ✓ | |
| `status_id` | uuid | ✓ | из настраиваемого справочника статусов |
| `progress_pct` | int | ✓ | 0–100, ставит человек |
| `mentor_id` | uuid | — | кто помогает |
| `result` | text | — | что получилось |
| `evaluated_by`, `evaluated_at`, `evaluation` | | — | оценка руководителя |

### 3.6 `goal_statuses` — настраиваемый жизненный цикл

`name`, `code`, `color`, `order`, `is_initial`, `is_final`, `requires_comment`,
`allowed_transitions uuid[]`, `who_can_set` (скоупы). В эталоне это отдельный раздел
«Налаштування статусів для цілей» — повторяем.

`goal_status_log`: `goal_id`, `from_status_id`, `to_status_id`, `actor_id`, `comment`,
`created_at` — «Протокол статусів цілей».

### 3.7 Заявки

**`external_training_requests`**: `user_id`, `title`, `provider`, `format` (`online` \| `offline`),
`starts_at`, `cost`, `currency`, `justification`, `expected_result`, `status`
(`new` \| `manager_approved` \| `hr_approved` \| `approved` \| `rejected` \| `completed`),
`approvals jsonb` (кто, когда, комментарий), `budget_id`, `report` (отчёт после обучения),
`documents jsonb` (счёт, сертификат).

**`career_requests`**: `user_id`, `target_position_id`, `target_location_id`, `motivation`,
`status`, `approvals`, `assessment_id` (если назначена оценка готовности), `decided_at`.

### 3.8 `strategic_plans`

`period_from`, `period_to`, `org_unit_id`, `goals jsonb` (цели обучения на период),
`budget`, `kpi jsonb` (например: доля людей с действующей аттестацией ≥ 95%),
`owner_id`, `status`.

## 4. Состояния

**ИПР:** `draft → on_approval → active → review → closed`.
**Цель:** статусы настраиваются тенантом; по умолчанию —
`Заплановано → В роботі → На перевірці → Досягнуто | Не досягнуто | Скасовано`.
**Заявка:** `new → manager_approved → hr_approved → approved → completed`,
ветка `rejected` на любом шаге.

## 5. Экраны

### 5.1 Мій розвиток (сотрудник)

Три блока:
1. **Профіль посади** — требуемые компетенции с текущим и требуемым уровнем, полоса разрыва;
   рядом с каждым разрывом — кнопка «Що пройти», ведущая на связанные курсы.
2. **Мій план розвитку** — период, цели карточками со статусами и прогрессом,
   кнопка «Додати ціль».
3. **Заявки** — на внешнее обучение и карьерные, со статусом согласования.

### 5.2 Карточка цели

Название, описание, тип, связанная компетенция и целевой уровень, метрика, срок,
связанное обучение (с прогрессом), ползунок прогресса, комментарии, история статусов.
Кнопки: «Надіслати на перевірку», «Змінити статус», «Закрити».

### 5.3 Цілі співробітників (руководитель)

Таблица: человек, точка, цель, тип, статус, прогресс, срок, просрочка.
Фильтры: точка, статус, срок, тип, наставник. Массовое действие: напомнить.
Карточка согласования: цель, обоснование, кнопки «Погодити» / «Повернути» + комментарий.

### 5.4 Библиотека компетенций

Дерево категорий + список компетенций. Карточка: название, тип, описание, уровни
с описанием поведения, связанные курсы и статьи, в скольких профилях используется.

### 5.5 Профиль должности

Слева — требуемые компетенции с уровнями и отметкой критичности; справа — обязательное
обучение со сроками; внизу — «Скільки людей відповідає профілю» с проваливанием в список.
Кнопка «Застосувати до людей на посаді» — создаёт назначения недостающего.

### 5.6 Матрица компетенций (руководитель)

Таблица: строки — люди точки, столбцы — компетенции профиля, в ячейке — текущий уровень
цветом (бирюзовый = соответствует, солнечный = ниже на 1, коралловый = ниже на 2+).
Клик по ячейке — история оценок и чем закрыть разрыв.

### 5.7 Заявка на внешнее обучение

Форма: название, провайдер, формат, даты, стоимость, обоснование, ожидаемый результат,
документы. После подачи — цепочка согласования с видимыми шагами и решениями.

## 6. Формы

### 6.1 Цель

| Поле | Контрол | Обяз. | Валидация | Ошибка (uk) |
| --- | --- | :-: | --- | --- |
| Назва | текст | ✓ | 3–200 | «Сформулюйте ціль» |
| Тип | радио | ✓ | 4 значения | |
| Компетенція | селект | — | обязателен при типе `competency` | «Оберіть компетенцію» |
| Цільовий рівень | селект | — | > текущего | «Рівень має бути вищим за поточний» |
| Метрика | текст | — | ≤200 | подсказка «Як зрозуміємо, що ціль досягнута?» |
| Опис | текстовая область | — | ≤2000 | |
| Повʼязане навчання | мультиселект | — | | |
| Наставник | селект | — | | |
| Термін | дата | ✓ | > сегодня, ≤ конца периода ИПР | «Термін виходить за межі плану» |

### 6.2 Заявка на внешнее обучение

Название, провайдер, ссылка, формат, даты, стоимость и валюта, обоснование (50–1000),
ожидаемый результат (обязательно), документы (счёт, программа). Подсказка под стоимостью:
«Бюджет підрозділу на квартал: {сума}; використано {сума}» `[решение]`.

## 7. Правила и алгоритмы

1. **Текущий уровень компетенции** берётся из последней действующей оценки по приоритету
   источников; оценки с истёкшим `valid_until` игнорируются.
2. **Разрыв** = `required_level − current_level`; критические компетенции с разрывом ≥1
   подсвечиваются и попадают в отчёт руководителя.
3. **Автозакрытие разрыва:** при завершении курса, связанного с компетенцией, создаётся
   оценка `source=test` с уровнем из настройки курса `[решение]`.
4. **Согласование цели** требуется, если тенант включил «Цілі потребують погодження»;
   иначе человек ведёт цели сам.
5. **Жизненный цикл статусов** настраивается: переходы, кто имеет право, нужен ли комментарий.
   Попытка недопустимого перехода — 422 с объяснением.
6. **ИПР закрывается** по окончании периода: руководитель пишет итог, цели без результата
   переходят в `Не досягнуто` автоматически.
7. **Заявка на внешнее обучение** идёт по маршруту: руководитель точки → HR → (если сумма
   больше порога) администратор. Маршрут настраивается.
8. **После внешнего обучения** человек обязан приложить отчёт и сертификат; без отчёта
   заявка не закрывается, руководителю напоминание через 14 дней.
9. **Карьерная заявка** может автоматически назначать оценку готовности (цикл из `20`)
   и обучение профиля целевой должности.

## 9. Отчёты

**Матриця компетенцій** по точке и по сети: доля людей, соответствующих профилю.
**Розриви**: топ компетенций с наибольшим разрывом — показывает, какие курсы нужны сети.
**Цілі**: сколько поставлено, достигнуто, просрочено; по точкам и руководителям.
**Зовнішнє навчання**: заявки, суммы, по подразделениям, окупаемость (сдал ли человек
аттестацию после).
**Готовність до підвищення**: кто соответствует профилю следующей должности.

## 12. Крайние случаи

- Человек перешёл на другую должность в середине ИПР → план остаётся, профиль меняется;
  разрыв пересчитывается по новому профилю, руководителю уведомление.
- Компетенция удалена из профиля → оценки сохраняются, разрыв не считается.
- Цель без срока → форма не даёт сохранить.
- Заявка одобрена, обучение не состоялось → статус `rejected` с причиной «Не відбулося»,
  бюджет возвращается.
- У должности нет профиля → раздел «Профіль посади» показывает «Профіль ще не налаштовано»
  и ссылку для методиста.
- Два руководителя (линейный и функциональный) согласуют цель → достаточно одного,
  второй видит решение `[решение]`.

## 13. Критерии приёмки

1. **Дано** профиль должности с компетенцией «Касова дисципліна» уровня 3 и текущим уровнем 1,
   **тоді** в «Мій розвиток» виден разрыв 2 и кнопка «Що пройти» ведёт на связанный курс.
2. **Дано** человек завершил связанный курс, **тоді** уровень компетенции повышается,
   разрыв пересчитывается.
3. **Дано** статус «На перевірці» с `requires_comment=true`, **коли** руководитель переводит
   цель без комментария, **тоді** отказ с подсказкой.
4. **Дано** заявка на 8000 грн при пороге 5000, **тоді** маршрут включает администратора.
5. **Дано** период ИПР закончился, **тоді** цели без результата стали «Не досягнуто»,
   руководителю пришло напоминание закрыть план.
6. **Дано** матрица компетенций точки, **тоді** ячейки с разрывом 2+ коралловые,
   клик открывает историю оценок.
