# Lola LMS — ТЗ. Часть 22. Звіти, журнали, конструктор вивантажень

## 1. Назначение и границы

Отчёты — то, ради чего руководитель вообще открывает систему. Принцип: **один каркас,
много срезов**. В эталоне отчёт на каждый тип контента (12 штук) — у нас общий движок
с фильтрами и переключателем предмета, плюс отдельные операционные отчёты и журналы.

Входит: каркас отчёта, восемь основных отчётов, журналы, конструктор сохранённых
выгрузок с расписанием, экспорт.
Не входит: показатели внутри модулей (они описаны в своих документах).

расширить область — только сузить.

## 3. Каркас отчёта

Каждый отчёт состоит из одинаковых частей:

1. **Фильтры** (сверху, сворачиваются): период (пресеты «Сьогодні», «7 днів», «30 днів»,
   «Квартал», «Свій період»), подразделение, точка, позиция, уровень должности, метка,
   контент, статус, источник назначения, только обязательное.
2. **Плитки** — 3–5 ключевых чисел с подписью и сравнением с прошлым периодом
   («78% · +4 п.п. до попереднього періоду»).
3. **Основной блок** — таблица или столбики (правила графиков: максимум два цвета,
   каждое значение подписано числом, сеток нет).
4. **Детализация** — клик по любой цифре открывает список людей, который её составил.
5. **Действия** — «Вивантажити», «Зберегти як звіт», «Надіслати на пошту», «Нагадати всім».

Правила: все числа считает сервер; выгрузка содержит ровно те строки и цифры, что на экране;
в шапке выгрузки — кто, когда и с какими фильтрами её сделал.

## 4. Основные отчёты

### 4.1 Готовність змін (главный)

Матрица: строки — точки, столбцы — позиции, в ячейке — процент людей, у которых все
обязательные назначения завершены и аттестации действительны.
Цвет ячейки: бирюзовый ≥ 90%, солнечный 70–89%, коралловый < 70%.
Клик → список людей с тем, чего не хватает.
Переключатель «Враховувати прострочені як не готових» (по умолчанию включён).

Плитки: готовность по сети, сколько людей не готовы, сколько просрочено, сколько аттестаций
истекает в ближайшие 30 дней.

### 4.2 Прогрес навчання

Переключатель предмета: курс / программа / тест / практикум / занятие / опрос.
Воронка: назначено → начали → завершили → сдали с первого раза.
Таблица по людям: человек, точка, позиция, предмет, статус, прогресс, балл, срок, дата.
Разрез «по контенту» — какие курсы проходят хуже всего.

### 4.3 Прострочені

Человек, точка, позиция, что просрочено, на сколько дней, руководитель, последняя активность,
кнопка «Нагадати» в строке и массовая.
Сортировка по числу дней просрочки.

### 4.4 Атестації

Попытки: человек, аттестация, попытка №, части и баллы, итог, проверяющий, время проверки,
дата. Плитки: сдали с первого раза, средний балл, среднее время до проверки, провалы.
Разрез «по вопросам» — какие вопросы проваливают чаще всего (это заявка на доработку курса).

### 4.5 Робота наставників

Наставник, точка, проверок за период, среднее время реакции, доля возвратов на доработку,
нарушений SLA, средняя оценка от учеников `[решение]`.

### 4.6 Контент

Материал или курс, сколько назначено, завершаемость, среднее время, оценка курса,
на каком уроке отваливаются, дата последнего обновления, владелец.
Отдельный блок «Потребує уваги»: курсы с завершаемостью < 50%, не обновлявшиеся год,
с оценкой ниже 3.

### 4.7 Активність

DAU/WAU/MAU, доля с телефона, среднее время в системе, распределение по часам суток
(показывает, когда люди реально учатся — это влияет на тихие часы),
люди без активности 30+ дней.

### 4.8 Мої результати (сотрудник)

Пройденные курсы, баллы, сертификаты со сроками, прогресс по компетенциям, бейджи.

## 5. Журналы

| Журнал | Что содержит | Хранение |
| --- | --- | --- |
| Протокол змін статусів | кто, что, когда, старое → новое | 3 года |
| Журнал сповіщень | код, канал, получатель, статус, ошибка, текст | 1 год |
| Журнал сесій | вход, устройство, IP, длительность, выход | 1 год |
| Журнал безпеки | входы, смены ролей, выгрузки, impersonation | 3 года |
| Журнал імпорту | файл, кто, результат, отчёт | 3 года |
| Журнал автоматизації | правило, человек, действия, результат | 1 год |
| Журнал інтеграцій | вебхуки и внешние вызовы с телом и ответом | 90 дней |

Все журналы: фильтры по периоду, человеку, типу события; выгрузка; доступ по скоупу
`audit.view`; записи неизменяемы.

## 6. Конструктор выгрузок (R2)

Пользователь собирает свой отчёт: предмет (люди, назначения, попытки, сертификаты,
прогоны чек-листов), поля (чекбоксы с поиском), фильтры (те же, что в каркасе),
группировка и сортировка, формат (xlsx, csv), имя.

Сохранённый отчёт можно поставить на расписание: каждый понедельник в 09:00 присылать
в Telegram или на почту указанным людям. Расписание — cron в таймзоне тенанта.

`saved_reports`: `name`, `entity`, `fields jsonb`, `filters jsonb`, `group_by`, `sort`,
`format`, `schedule jsonb`, `recipients jsonb`, `owner_id`, `last_run_at`, `is_active`.

## 7. Правила и алгоритмы

1. **Область видимости** применяется до фильтров и не может быть расширена параметром запроса.
2. **Периоды** считаются по таймзоне точки, а не сервера: «вчора» для Одессы и для Киева —
   одна дата, но для тенанта в другой стране будет своя.
3. **Выгрузка больше 5000 строк** уходит в фоновую задачу; ссылка приходит уведомлением
   и живёт 24 часа.
4. **Сравнение с прошлым периодом** считается по равному интервалу непосредственно перед
   выбранным.
5. **Архивированные люди** по умолчанию исключены; переключатель «Враховувати архівованих»
   доступен в отчётах администратора.
6. **Кеш**: тяжёлые срезы (готовность смен, активность) считаются из материализованных
   представлений, обновляемых каждые 10 минут; на экране указано время последнего пересчёта.
7. **Точность важнее скорости**: если витрина устарела больше чем на час, отчёт считается
   напрямую с пометкой «Розраховано зараз».
8. **Приватность**: в отчётах по анонимным опросам и 360° не показываются данные,
   если респондентов меньше порога (`21`, `20`).

## 8. Уведомления

## 10. Фоновые задачи

`report.export` (генерация xlsx/csv), `report.scheduled_run` (по расписанию сохранённых
отчётов), `mv.refresh` (каждые 10 минут), `digest.weekly` (понедельник 09:00 по таймзоне
точки), `logs.retention` (ежедневная очистка по срокам хранения).

## 11. Крайние случаи

- Точка открыта в середине периода → в знаменателе только те дни, когда точка работала.
- Человек переведён между точками в середине периода → учитывается в той точке,
  где работал на дату события; в матрице готовности — по текущей точке.
- Отчёт за год по сети из 3000 человек → фоновая выгрузка, на экране предупреждение
  «Період великий, звіт прийде файлом».
- Данные ещё не пересчитаны → показывается время последнего пересчёта и кнопка «Оновити».
- Пользователь с ролью на двух точках → видит обе и может фильтровать, но не третью.
- Выгрузка содержит телефоны → доступна только со скоупом `report.export`, факт выгрузки
  пишется в журнал безопасности.

## 12. Критерии приёмки

1. **Дано** руководитель точки Лазарева, **коли** он открывает любой отчёт,
   **тоді** данные других точек недоступны ни через фильтр, ни через прямой запрос API.
2. **Дано** матрица готовности показывает 78%, **коли** кликнуть по ячейке,
   **тоді** открывается список людей, число которых сходится с процентом.
3. **Дано** выгрузка на 12 000 строк, **тоді** она уходит в фон, приходит уведомление
   со ссылкой, файл содержит те же цифры, что экран.
4. **Дано** сохранённый отчёт с расписанием «понеділок 09:00», **тоді** он приходит
   в Telegram в 09:00 по таймзоне тенанта, даже если сервер в UTC.
5. **Дано** анонимный опрос с двумя ответами при пороге 3, **тоді** отчёт показывает
   «Замало відповідей для показу».
6. **Дано** человек архивирован, **тоді** он исчез из числителя и знаменателя готовности.
