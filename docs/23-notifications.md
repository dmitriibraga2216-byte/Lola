# Lola LMS — ТЗ. Часть 23. Сповіщення: канали, шаблони, правила доставки

## 1. Назначение и границы

Уведомления — единственный способ довести обучение до человека, который не открывает
систему сам. Главный канал — Telegram, резервный — SMS, для руководителей — почта.
Модуль отвечает за шаблоны, маршрутизацию, тихие часы, дедупликацию и журнал.

Входит: каналы, шаблоны и переменные, настройки тенанта и человека, очередь и доставка,
Telegram-бот, дайджесты, журнал.
Не входит: конкретные события модулей (перечислены в их документах).

## 3. Сущности и поля

### 3.1 `notification_templates`

| Поле | Тип | Обяз. | Комментарий |
| --- | --- | :-: | --- |
| `code` | text | ✓ | `enrollment_due_soon` и т. д. |
| `scope` | text | ✓ | `global` \| `custom` — стандартный текст против переопределения тенанта (`13.1`) |
| `subject` | text | ✓ | «Заголовок повідомлення» |
| `body_text` | text | ✓ | Mustache-шаблон для Telegram, SMS и текстовой части письма, ≤2000 |
| `body_mjml` | text | — | вёрстка письма на MJML; пусто → письмо не шлём |
| `image_key` | text | — | картинка шаблона |
| `telegram_image_key` | text | — | отдельная картинка для Telegram (§13.4) |
| `buttons` | jsonb | — | для Telegram: `[{text, action}]` |
| `is_enabled` | boolean | ✓ | |
| `is_mandatory` | boolean | ✓ | нельзя отключить человеку (дедлайны, аттестации) |
| `throttle` | jsonb | — | `{max_per_day: 1, per_subject: true}` |
| `version` | int | ✓ | правка создаёт версию, старые отправки ссылаются на свою |

### 3.2 `notifications` — очередь и журнал

`user_id`, `code`, `channel`, `locale`, `payload jsonb` (значения переменных),
`rendered_body` (что реально отправили), `status` (`queued` \| `sending` \| `sent` \|
`failed` \| `skipped` \| `read`), `skip_reason` (`quiet_hours` \| `unsubscribed` \|
`duplicate` \| `no_channel` \| `blocked`), `error`, `attempt`, `scheduled_for`,
`sent_at`, `read_at`, `ref_type`, `ref_id`, `dedupe_key`.

### 3.3 Настройки

**Тенант** (`tenant.settings.notifications`): тихие часы (по умолчанию 09:00–20:00 по
таймзоне точки), каналы по умолчанию, отправитель SMS, адрес почты, дайджест руководителю
(день и час), лимит SMS в месяц, эскалация (через сколько уведомлять руководителя).

**Человек** (`user_notification_prefs`): по каждому коду — включено/выключено и канал;
обязательные коды показываются, но переключатель заблокирован с подписью
«Це сповіщення не можна вимкнути».

### 3.4 Переменные шаблонов

Общие: `{{user.first_name}}`, `{{user.full_name}}`, `{{location.name}}`,
`{{position.name}}`, `{{tenant.name}}`, `{{link}}` (автологин-ссылка).
Обучение: `{{course.title}}`, `{{due.date}}`, `{{due.days_left}}`, `{{progress.pct}}`,
`{{score}}`, `{{attempts_left}}`, `{{mentor.name}}`, `{{certificate.number}}`.
В редакторе — список доступных переменных с подстановкой по клику и предпросмотром
на реальных данных.

## 4. Каналы

| Канал | Когда используется | Ограничения |
| --- | --- | --- |
| Telegram | основной для всех | лимит 25 сообщений/сек на бота, 1/сек на чат; блокировка бота → 403 |
| SMS | OTP и критичное при недоступном Telegram | стоимость, лимит тенанта, 70 знаков в сегменте |
| E-mail | руководителям, дайджесты, выгрузки | требует адрес |
| Push (PWA) | сделано, докс/33 D-051; дублирует Telegram | требует разрешения браузера; без VAPID-ключей в окружении — канал пропускает отправку |
| In-app | колокольчик в интерфейсе | всегда, без ограничений |

**Правило выбора канала:** Telegram (если привязан и не заблокирован) → SMS (если код
критичный и включён) → in-app. Почта только для кодов, помеченных `email`.

## 5. Экраны

### 5.1 Мої сповіщення (человек)

Список кодов, сгруппированных по темам (навчання, атестації, нагадування, хаб),
переключатели; обязательные — с замком. Внизу: «Канал за замовчуванням» и кнопка
«Перевірити» — отправляет тестовое сообщение.

### 5.2 Шаблони (админ)

Таблица: код, канал, язык, включён, последнее изменение. Редактор: поле текста,
список переменных, предпросмотр на выбранном человеке, кнопка «Надіслати собі»,
история версий, кнопка «Повернути стандартний текст».

### 5.3 Журнал уведомлений

Таблица: время, человек, код, канал, статус, причина пропуска, текст (по клику),
ошибка. Фильтры: период, человек, код, канал, статус, точка. Кнопка «Надіслати повторно».

### 5.4 Ручная рассылка (руководитель)

Аудитория (конструктор из `15`), текст (до 500 знаков), канал, подтверждение с числом
получателей и предупреждением о тихих часах. Рассылка попадает в журнал как код `manual`.

### 5.5 Колокольчик в интерфейсе

Список последних 50, непрочитанные выделены, клик ведёт к предмету уведомления,
кнопка «Позначити все прочитаним».

## 6. Правила и алгоритмы

1. **Постановка в очередь.** Модуль не отправляет сам: пишет строку в `notifications`
   с `dedupe_key`. Отправкой занимается задача `notification.dispatch`.
2. **Дедупликация.** `dedupe_key = code + user_id + ref_id + дата`; повторная постановка
   с тем же ключом даёт `skipped: duplicate`.
3. **Тихие часы.** Если `scheduled_for` попадает в тихие часы точки человека, отправка
   переносится на ближайшее начало рабочего окна. Исключение: OTP и коды с
   `ignore_quiet_hours=true` (аварийные).

   > [уточнено, PR-34 пакета `docs/v2`] «Часы человека» — единая цепочка пояса
   > (`personTimezone()`, `docs/v2/38` §7.10): `users.timezone` (пояс удалённого, задан в
   > карточке) → пояс точки размещения → у кандидата — пояс точки вакансии (`docs/v2/39` П-23,
   > PR-37) → пояс тенанта. По ней же считается день на карте активности — «ночь» в уведомлениях и
   > «день» на карте у человека не расходятся. Пока `users.timezone` пуст, поведение прежнее.
4. **Троттлинг.** Не больше `throttle.max_per_day` сообщений одного кода одному человеку;
   и не больше 10 любых уведомлений в сутки на человека без явного указания
   `bypass_daily_limit` `[решение]`.
5. **Ретраи.** При временной ошибке (сеть, 5xx, лимит) — 5 попыток с экспонентой
   (1, 5, 25, 60, 180 минут). При 403 от Telegram (бот заблокирован) —
   `telegram_blocked=true`, канал переключается на SMS, руководителю уведомление.
6. **Эскалация.** Если по коду с `escalate_after_hours` человек не отреагировал
   (не открыл ссылку), уведомление уходит руководителю точки.
   > [решение, PR-30] Адресат — руководитель по `resolveManager()` (`docs/v2/32` §7.8), а не
   > только поле точки. Проход разбирает строки от самой старой отправки окном в 200 и
   > **закрывает каждую выбранную**: эскалацией (`escalated_to_id` — руководитель) или отметкой
   > «эскалировать некому» (`escalated_at` без `escalated_to_id`). Незакрытая строка без
   > адресата выбиралась бы каждый час и при двух сотнях таких строк навсегда заняла бы окно —
   > эскалация до людей с руководителем не доходила бы вовсе. Появившийся позже руководитель
   > старую строку не получает: эскалация — событие срока, а не долг, который ждёт адресата.
7. **Автологин-ссылка** `{{link}}`: одноразовый токен на 10 минут, привязан к `chat_id`
   и коду уведомления; после использования аннулируется.

   > [уточнено, fix-bot-login] Токен выпускается в момент отправки сообщения — на его адресата —
   > и кладётся в ссылку кнопки «Пройти»: `/tg/go?t=<токен>&to=<путь>&n=<уведомление>`; в базе —
   > только хеш (`telegram_tokens`, `kind = 'login'`). Вход — только по токену. «Привязан к
   > `chat_id`» — через человека: при переходе он должен быть активен, не заблокирован и с
   > привязанным Telegram. Код уведомления в токене не хранится: реакция (п. 6) отмечается по `n`
   > и только у своего уведомления. Неизвестный, просроченный или использованный токен — один
   > экран: «Посилання застаріло, попросіть у бота нове»; свежую кнопку присылает `/menu` (§7).
   > Подробно — `docs/28` §28.24.
8. **Дайджест руководителю** собирает за период: сколько просрочено, кто не начал,
   что ждёт проверки, аттестации на неделю — одним сообщением вместо десяти.
9. **Язык** берётся из `users.locale`, иначе из тенанта; при отсутствии шаблона на языке —
   fallback на `uk` с пометкой в журнале.
10. **Шаблон изменён** — отправленные ранее уведомления сохраняют свой текст
    (`rendered_body`), журнал не переписывается.

## 7. Telegram-бот

- Привязка: человек открывает `/start <token>` по ссылке из интерфейса; токен одноразовый,
  живёт 15 минут, привязывает `chat_id`.
- Команды: `/start`, `/menu` (мої завдання; `[уточнено, fix-bot-login]` всегда со свежей кнопкой
  входа — «Пройти» к первой задаче или «Відкрити Lola», если задач нет), `/help`, `/stop`
  (отписка от необязательных).
- Кнопки под уведомлениями: «Пройти» (автологин-ссылка), «Відкласти на день»
  (переносит напоминание, максимум дважды), «Не нагадувати про це» (только для необязательных).
- Бот не ведёт обучение в чате: всё открывается в вебе.
- Ошибки: 403 — блокировка, 429 — троттлинг с `retry_after`, 400 «chat not found» —
  сброс привязки.

## 8. Отчёты

**Доставляемость**: по кодам и каналам — отправлено, доставлено, ошибок, пропущено
и почему.
**Реакция**: доля открывших ссылку, среднее время до реакции по кодам — показывает,
какие формулировки работают.
**SMS-расходы**: сегментов, стоимость, по точкам.
**Заблокированные боты**: список людей, у которых Telegram недоступен — им нужен другой канал.

## 10. Фоновые задачи

`notification.dispatch` (каждую минуту, партиями с учётом лимитов каналов),
`notification.retry`, `notification.escalate` (ежечасно), `digest.build` (по расписанию),
`notification.cleanup` (удаление тел старше срока хранения), `telegram.health`
(проверка бота раз в час).

## 11. Крайние случаи

- Человек сменил номер → привязка Telegram сохраняется (она по `chat_id`), SMS идут на новый.
- Тенант исчерпал лимит SMS → критичные уведомления идут в Telegram и in-app,
  администратору алерт «Ліміт SMS вичерпано».
- Массовое назначение 3000 людям в 20:05 → всё уходит в очередь и отправляется утром
  с 09:00, растянуто по лимиту 25/сек.
- Человек нажал «Відкласти» три раза → третья кнопка не показывается, напоминание приходит.
- Шаблон содержит переменную, которой нет в payload → подстановка пустой строкой,
  предупреждение в журнале, отправка не блокируется.
- Бот удалён и создан заново → все `chat_id` недействительны, нужна массовая перепривязка;
  предусмотреть кнопку «Надіслати всім посилання на привʼязку».

## 12. Критерии приёмки

1. **Дано** тихие часы 09:00–20:00, событие в 21:30, **тоді** уведомление уходит
   в 09:00 следующего дня, в журнале причина «quiet_hours».
2. **Дано** два одинаковых события подряд, **тоді** второе `skipped: duplicate`.
3. **Дано** человек заблокировал бота, **тоді** первая же отправка ставит `telegram_blocked`,
   следующее критичное уходит SMS, руководителю уведомление.
4. **Дано** нажата кнопка «Пройти» в Telegram, **тоді** открывается урок сразу,
   без ввода кода; повторное нажатие той же ссылки через 15 минут требует входа.

   > [уточнено, fix-bot-login] Ссылка входит один раз и не дольше 10 минут с отправки (§6 п. 7).
   > «Требует входа» — в браузере без сессии: там повторное нажатие ведёт на экран входа с текстом
   > «Посилання застаріло». Кто уже вошёл в этом браузере, идёт по кнопке сразу на страницу —
   > пускает его действующая сессия, а не ссылка. Проверяется `tests/integration/bot-login.spec.ts`
   > и `tests/e2e/bot-login.spec.ts`.
5. **Дано** шаблон отредактирован, **тоді** ранее отправленные уведомления в журнале
   показывают старый текст.
6. **Дано** ручная рассылка на 200 человек, **тоді** она видна в журнале как `manual`
   с автором и текстом.

## 13. Сверено с эталоном

Проверено 19.09.2026 (`/notifications`, `/process/info`, `/process/settings`,
`/site/integration`).

### 13.1 Экран «Шаблони повідомлень»

Путь `/notifications`, доступен из двух разделов сразу — «Інформація» и «Налаштування».
Две вкладки: **«Глобальний»** (поставляется с системой) и **«Кастомний»** (переопределённые
тенантом). Колонки таблицы: **Назва | Email | Telegram** — то есть канал в эталоне задан
не полем шаблона, а колонкой: у одного события две версии текста, по одной на канал.
Списком около десяти страниц; среди названий — напоминания о днях рождения, сертификаты,
чат (четыре разных кода), комментарии, ERP, форум (два кода).

**Вывод для Lola.** Модель `23` §3.1 держит `channel` полем и разводит шаблоны строками;
это эквивалентно, но удобнее для добавления SMS и push. Оставляем поле, а экран рисуем
как в эталоне — одна строка на событие, столбец на канал; `[решение]` зафиксировано здесь.

Деление «Глобальний / Кастомний» принимаем дословно: правка тенанта не трогает
стандартный текст, а создаёт кастомную версию, и кнопка «Повернути стандартний текст»
просто удаляет её. Это же снимает вопрос о версионировании при обновлении системы.

### 13.2 Каналы в эталоне

Настраиваются в «Інтеграції → Сповіщення» (см. `09` §9.7): **E-mail** (полный SMTP)
и **Telegram** (два токена — свой бот и внешний). SMS-канала в эталоне нет.

**Вывод для Lola `[решение]`.** SMS остаётся: OTP-вход по телефону — основной сценарий,
а часть линейного персонала Telegram не ставит.

### 13.2.1 Поправка: тихие часы и дайджест в эталоне есть

При первом проходе я их не нашёл и записал как наше добавление — ошибка.
Экран `/notifications/settings` («Налаштування часу відправлення повідомлень»)
с предупреждением «зміна параметрів впливає на час відправлення повідомлень
для всіх користувачів» содержит:

| Настройка | Значение в снятой установке |
| --- | --- |
| **«Обмежити період відправлення повідомлень»** | переключатель — это и есть тихие часы |
| «Час відправлення повідомлень про дні народження» | 09:00, плюс «Надіслати додаткове нагадування за N днів» |
| «Час відправлення повідомлень про річниці» | 09:00 |
| «…для автоматично завершених завдань після закінчення терміну» | 00:00 |
| **«…керівникам зі списком пройдених завдань їх підлеглих»** | 09:00 — это дайджест руководителю |
| «…про завдання, термін виконання яких закінчується» | 09:00 |
| «…із нагадуванням за день до старту елемента програми» | 09:00 |

Модель эталона: не одно окно тишины на всё, а **час отправки на каждый класс событий**
плюс общий ограничитель периода. Берём обе вещи. Отдельное время для «автоматически
завершённых по сроку» стоит в 00:00 не случайно: это служебная рассылка, её гонят ночью,
когда очередь свободна.

Троттлинг, дедупликация и эскалация (`23` §6) в эталоне по-прежнему не обнаружены —
вот они действительно наши.

### 13.3 Журнал

«Журнал сповіщень» — `/notifications/report`, присутствует в четырёх разделах меню
(Навчання, Користувачі, Інформація, Оцінка). Личные настройки человека —
`/users/profile/notifications`, они же «Налаштування повідомлень» в разделе «Інформація».

### 13.4 Редактор шаблона

`/notifications/:id/edit`. Поля:

| Поле | Комментарий |
| --- | --- |
| Назва | код события, не редактируется |
| **Заголовок повідомлення\*** | тема письма / заголовок |
| **Текстовий шаблон повідомлення\*** | для Telegram и текстовой части письма |
| **MJML шаблон повідомлення\*** | вёрстка письма на MJML |
| Зображення | картинка шаблона |
| Зображення для відправки в Телеграм | отдельная, в блоке «ОПЦІЇ» |
| «Надіслати тестове повідомлення» | кнопка |

**Шаблонизатор — Mustache**, с секциями и инверсией:
`{{#singleBirthday}}…{{/singleBirthday}}`, `{{^singleBirthday}}…{{/singleBirthday}}`,
циклы `{{#birthdayUsers}}{{fullname}}{{/birthdayUsers}}`.
Переводы внутри шаблона — обёрткой **`{{#_tr}}Hello{{/_tr}}`**: строка идёт через словарь
переводов (`24` §3.6), поэтому один шаблон обслуживает все языки.

Панель **«ЗМІННІ ШАБЛОНУ»** — полный список общих переменных:

```
{{user.id}} {{user.uid}} {{user.firstname}} {{user.secondname}} {{user.patronymic}}
{{user.fullname}} {{user.email}} {{user.phone}} {{user.photo_thumb}}
{{user.position}} {{user.department}} {{user.city}} {{user.is_chief}} {{user.is_online}}
{{site.url}} {{site.domain}} {{site.title}} {{site.logo}} {{site.css}}
{{mail_settings_url}}
```

Плюс переменные конкретного события (для дней рождения — `birthdayUsers`, `singleBirthday`).

**Выводы для Lola.**

1. **Две версии текста на шаблон, а не две строки.** Текстовый вариант и MJML-вариант
   лежат в одной записи — поэтому в списке и колонки «Email | Telegram». Меняем `23` §3.1:
   `body_text` и `body_mjml` в одной строке шаблона, `channel` уходит.
2. **`{{#_tr}}` — хорошая идея, берём.** Иначе на каждый язык нужна своя копия шаблона,
   и при правке текста забывают вторую.
3. **Отдельная картинка для Telegram** — не блажь: в письме уместен баннер 600px,
   в Telegram он приходит обрезанным.
4. `{{mail_settings_url}}` — ссылка «настроить уведомления» в подвале каждого письма.
   Обязательна: без неё человек отписывается блокировкой бота.

Рядом есть `/notifications/email-template-settings` — общая обвязка письма
(шапка, подвал, стили), не снят.

### 13.6 Данные эталона как аргумент за дедупликацию

В снятом журнале один человек получил письмо «Незадовільні результати по завданню

### 13.7 Push-уведомления PWA (докс/33 D-051, `06`, `04`)

**Сделано.** Таблица `push_subscriptions` (`endpoint` — глобально уникален, `p256dh`/`auth`,
RLS) — один человек может иметь несколько подписок (несколько браузеров/устройств).
`POST /push/subscribe`, `POST /push/unsubscribe`, `GET /push/status`; клиент —
`app/composables/usePush.ts`, кнопка «Увімкнути push у цьому браузері» на
`/learn/notifications`. Манифест `public/manifest.webmanifest` и мінімальний сервіс-воркер
`public/sw.js`, без бібліотек.

Канал `push` — рядом с `telegram`/`sms`/`email` в `EnqueueInput.channel`, `sendViaChannel`
(`server/services/channels.ts`) делегирует в `server/services/push.ts#sendPushToUser`.
Правила настроек человека (`enabled`, обов'язковість коду) — те самі, що й у інших каналів
(§3.3); окремого маршруту «спробувати push, потім Telegram» не робили — це явний вибір
каналу, як `sms`/`email`, а не частина каскаду §4.

**Доставка — VAPID (RFC 8292) без бібліотек.** JWT ES256 підписується `node:crypto`
(`dsaEncoding: 'ieee-p1363'` дає одразу «сирий» r‖s, без ручного розбору DER) — заголовок
`Authorization: vapid t=<jwt>, k=<publicKey>`, ключі — `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`
в оточенні (генерація — коментар у `.env.example`). Без пари ключів канал `push`
повертає `skipped`, решта каналів не зачіпаються.

**Свідоме рішення, не недоробка `[решение]`: пуш без зашифрованої полезної нагрузки.**
Повне шифрування (RFC 8291, `aes128gcm`: ECDH + HKDF + AES-128-GCM з паддінгом) — це
самостійний обсяг криптографії заради персоналізованого тексту всередині самого пуша.
Замість цього кожен пуш — «порожній» POST (валідний сценарій Web Push): сервіс-воркер
отримує подію `push` без `event.data` і показує загальне сповіщення («У вас нове
сповіщення») з посиланням на `/learn/notifications`, де вже лежить справжній текст
(той самий рядок `notifications`, що й у дзвіночка). Доставка реальна і перевіряється
(`tests/unit/push.spec.ts` — підпис ES256 генерується і верифікується публічним ключем
на льоту), не вистачає лише персоналізації самого тексту сповіщення — це залишок,
не позначений як D- окремо, бо канал працює за призначенням («розбудити» людину).

### Г-23.1 Полный перечень кодов уведомлений

**Гипотеза.** В списке шаблонов около десяти страниц по десять строк — порядка сотни
кодов. Снятые названия группируются по префиксу: «Чат - …» (четыре кода),
«Форум - …» (два), «Коментарі - …», «Сертифікати - …», «ERP - …»,
«Нагадування про дні народження». Значит код именуется «Модуль - Подія».

**Решение для Lola `[решение]`.** Сотню кодов не копируем — у нас нет ни форума,
ни ERP, ни чата в R1. Заводим минимальный набор R1, по модулям:

| Группа | Коды |
| --- | --- |
| Доступ | `auth.otp`, `auth.new_device` |
| Назначения | `task.assigned`, `task.due_soon`, `task.due_today`, `task.overdue`, `task.autoclosed`, `task.result_failed`, `task.result_passed` |
| Проверка | `review.submitted` (наставнику), `review.returned`, `review.graded` |
| Аттестация | `cert.issued`, `cert.expiring`, `cert.revoked` |
| Траектория | `trajectory.next_unlocked`, `trajectory.finished` |
| Объявления | `notice.assigned`, `notice.not_acknowledged` |

| Бонусы | `bonus.earned`, `bonus.order_ready` |
