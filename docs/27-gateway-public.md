# Lola LMS — ТЗ. Часть 27. Веб-шлюз: публикация наружу и ссылка для третьих лиц

Цель: получить постоянную ссылку вида `https://lola.<домен>`, которую можно отправить
инвестору, клиенту или подрядчику, при том что сервер стоит дома за провайдерским NAT.
Внутренняя часть — в `26-server-local.md`.

> **Отметка «prod-proxmox» (докс/26 §26.13, докс/32 §Б строка 22).** В принятой конфигурации
> R1 (VM без белого IP, за Tailscale) Caddy из этого документа **не разворачивается** —
> TLS и вход терминирует Cloudflare, именованный тунель ходит прямо в `app:3000` (пропускает
> шаг «Caddy → app/minio» из схемы §27.2). Профиль `public` с Caddy остаётся в
> `docker/docker-compose.prod.yml` как резерв на случай VM с белым IP — тогда этот документ
> применяется буквально, включая заголовки §27.6.

## 27.1 Выбор способа публикации

| Способ | Нужен белый IP | Открытые порты на роутере | Защита от DDoS и сканеров | Сложность | Вердикт |
| --- | --- | --- | --- | --- | --- |
| **Cloudflare Tunnel** | нет | нет | да, трафик через Cloudflare | низкая | **основной** `[решение]` |
| Проброс портов + Caddy | да | 80, 443 | нет | низкая | резерв, если Cloudflare недоступен |
| VPS-прокси + WireGuard | нет | нет | частично | средняя | если понадобится свой IP и полный контроль |
| Ngrok и подобные | нет | нет | да | низкая | только для разовой демонстрации |

Основной вариант — Cloudflare Tunnel: домашний адрес наружу не светится, порты на роутере
закрыты, у сервера нет входящих соединений вообще — туннель исходящий.

## 27.2 Схема

```
Браузер третьего лица
        │  https://lola.example.com
        ▼
   Cloudflare (TLS, WAF, кеш статики)
        │  туннель (исходящее соединение от сервера)
        ▼
  cloudflared (контейнер на VM lola-prod)
        │  http://proxy:80
        ▼
     Caddy ──► app:3000        (приложение и API)
           └─► minio:9000      (медиа по /files/*)
```

Внутренний доступ `app.lola.local` продолжает работать напрямую, минуя Cloudflare, —
чтобы сеть провайдера не влияла на работу сотрудников на точках.

## 27.3 Домен и DNS

- Домен продукта: `lola.ua` (маркетинг) — отдельный проект; приложение живёт на `app.lola.ua`.
  Пока домен не куплен, используем поддомен рабочего домена: `lola.<домен>` `[сверить]`.
- Зона переносится на Cloudflare (NS-записи у регистратора).
- Записи создаёт сам туннель (`cloudflared` пишет CNAME на `<uuid>.cfargotunnel.com`),
  вручную ничего не заводим.
- Поддомены: `app.` — приложение, `demo.` — демонстрационный тенант, `staging.` — тестовая среда.

## 27.4 Настройка туннеля

```yaml
# /srv/lola/secrets/cloudflared/config.yml
tunnel: lola
credentials-file: /etc/cloudflared/lola.json
ingress:
  - hostname: app.lola.example.com
    service: http://proxy:80
    originRequest:
      connectTimeout: 30s
      noTLSVerify: true          # TLS уже терминирован Cloudflare, внутри http
  - hostname: demo.lola.example.com
    service: http://proxy:80
  - service: http_status:404
```

Контейнер `cloudflared` добавляется в тот же compose, `restart: unless-stopped`,
токен — в `.env` (`CF_TUNNEL_TOKEN`). Туннель регистрируется один раз командой
`make tunnel-init`, дальше поднимается автоматически.

## 27.5 Настройки на стороне Cloudflare

| Настройка | Значение | Зачем |
| --- | --- | --- |
| SSL/TLS mode | Full (strict) при собственном сертификате, иначе Full | не допускать обрыва шифрования |
| Always Use HTTPS | вкл | |
| Min TLS | 1.2 | |
| HSTS | вкл, 6 месяцев, includeSubDomains | после проверки, что всё работает по https |
| Bot Fight Mode | вкл | отсекает сканеры |
| WAF managed rules | вкл | |
| Rate limiting | 20 запросов/10 сек на IP для `/api/v1/auth/*` | защита OTP от перебора |
| Cache | обход для `/api/*`, кеш для `/_nuxt/*` и `/files/*` | статика с диска не держит приложение |
| Upload size | план Free ограничивает тело 100 МБ | видео уроков загружать через прямую ссылку MinIO (см. 27.7) |
| Access (Zero Trust) | включается для `staging.` и панели оператора | |

## 27.6 Заголовки и безопасность на Caddy

```
(secure_headers) {
  header {
    Strict-Transport-Security "max-age=15552000; includeSubDomains"
    X-Content-Type-Options "nosniff"
    X-Frame-Options "SAMEORIGIN"
    Referrer-Policy "strict-origin-when-cross-origin"
    Permissions-Policy "camera=(self), microphone=(), geolocation=(self)"
    -Server
  }
}
```

- Приложение доверяет `CF-Connecting-IP` только от диапазонов Cloudflare — иначе rate limiting
  обмануть тривиально. Список диапазонов обновляется задачей раз в сутки.
- Cookie сессии: `Secure`, `HttpOnly`, `SameSite=Lax`, домен — конкретный поддомен, без точки.
- CSP как в `06-infra.md`; при включении Cloudflare Rocket Loader CSP ломается — Rocket Loader выключен.

## 27.7 Загрузка больших файлов

Тело запроса на бесплатном плане Cloudflare ограничено 100 МБ, а видео уроков — до 500 МБ.
Решение: загрузка идёт **не через приложение**, а по presigned-ссылке прямо в MinIO:

1. Клиент запрашивает `POST /api/v1/media/upload-url` (через Cloudflare, тело крошечное).
2. Сервер отдаёт presigned PUT на `https://files.lola.example.com/...` — это отдельный
   поддомен, вынесенный из туннеля в **DNS-only** режим (серое облако) или на отдельный
   туннель без ограничения, в зависимости от плана `[сверить]`.
3. Браузер грузит файл напрямую, приложение узнаёт о загрузке через `POST /media/:id/complete`.

Если серое облако недопустимо (светит домашний IP), альтернатива — чанковая загрузка
по 20 МБ через приложение с последующей сборкой в воркере `[решение]`.

## 27.7.1 Собственный домен клиента (докс/33 D-059)

Код хранит и резолвит `tenants.custom_domain` (`25` §16.1), но настройка DNS и сертификата —
ручная операция оператора, не автоматизация:

1. Клиент создаёт у себя запись `CNAME navchannya.kappi.ua → <ingress-хост Lola>` (тот же
   хост, что и wildcard `*.lola.<домен>`, см. `26`).
2. Оператор проверяет запись (`dig CNAME navchannya.kappi.ua`) — она должна указывать именно
   на инфраструктуру Lola, а не оставаться прежней. Это и есть «проверка владения доменом»
   из `25` §16.1 (п. 9): ручная, потому что автоматический ACME-вызов на чужом домене требует
   доступа к его DNS или файлу на его вебсервере, которого у Lola нет.
3. Сертификат Let's Encrypt на новый домен выпускается тем же способом, что и на основной
   (`26`, DNS-01 для wildcard или HTTP-01 для отдельного имени) — вручную добавляется в Caddy/
   Cloudflare как ещё один hostname, не меняя конфигурацию остальных тенантов.
4. Только после того, как CNAME и сертификат готовы, оператор вписывает домен в карточку
   тенанта (панель платформы → «Домен»); запрос на несуществующий сертификат до этого момента
   отдаст ошибку TLS раньше, чем приложение вообще увидит `Host`.
5. Отвязка домена (поле очищено) не требует правок DNS/сертификата на стороне Lola — хост
   просто перестаёт резолвиться в тенант и попадает в обычный фолбек `25` §16.1.

## 27.8 Ссылка для третьих лиц

Три сценария, у каждого своя механика:

**A. Показать продукт инвестору или клиенту**
- Отдельный тенант `demo` на `demo.lola.example.com`, заполненный демонстрационным контентом.
- Вход без пароля по ссылке-приглашению с ограничением: `GET /demo?key=<token>` создаёт
  временную сессию демо-пользователя на 2 часа, роль — только чтение.
- Демо-тенант сбрасывается к эталонному состоянию ежедневно в 05:00 фоновой задачей
  (`demo.reset`), чтобы следы предыдущих гостей не мешали.
- В шапке — плашка «Демо-простір. Дані очищаються щодня».

**B. Дать доступ подрядчику или разработчику**
- Cloudflare Access на `staging.` — вход по одноразовому коду на почту, список почт в политике.
- Доступ выдаётся на срок (7/30 дней), отзывается в один клик, каждый вход виден в журнале.

**C. Публичная ссылка на сертификат**
- `https://lola.example.com/c/<public_token>` — страница проверки сертификата без входа:
  имя, курс, дата, номер, статус (действителен / отозван), QR. Индексация запрещена
  `X-Robots-Tag: noindex`; токен не угадывается (32 байта).

## 27.8.1 Правило публичного контура `/api/v1/public/*`

> [добавлено, `docs/v2/44-decisions.md` В-9 п. 2, реализовано PR-16] Раздел появился вместе
> с публичной страницей вакансии: до неё контур состоял из трёх ручек, и правило жило в
> головах, а не в документе.

Публичный контур — **единственное место продукта, работающее без сессии**. Сюда попадают
страница вакансии и отклик (`docs/v2/29` §10), форма тайного гостя (`docs/20` §7.8),
страница гостя пространства (`docs/21` §14.6) и самостоятельная регистрация.

Ручка под `server/api/v1/public/` обязана выполнять четыре условия. Не три из четырёх:

1. **Тенант выводится из токена или хоста**, никогда из тела запроса. Строка токена ищется
   функцией `SECURITY DEFINER` (`vacancy_public_lookup`, `mystery_link_lookup`), отдающей
   минимум полей — тенанта, владельца контекста и состояние.
2. **Работа идёт внутри `withTenant()`** (CLAUDE.md правило 2). Вызов функции из п. 1 —
   единственное разрешённое обращение к БД до установки тенанта, и он ничего не отдаёт
   наружу сам.
3. **У ручки стоит `hitRateLimit`.** Без него перебор токенов ограничен только их длиной;
   пороги — по смыслу ручки (просмотр щедрее отправки).
4. **Несуществующий токен даёт `404`, выровненный по времени.** Чужой, удалённый и
   несуществующий неразличимы — ни телом ответа, ни задержкой (правило 15 CLAUDE.md).

Проверяется проверкой 8 скрипта `scripts/v2-crosschecks.sh` (пп. 2 и 3 — статически) и
интеграционными спеками контура (пп. 1 и 4 — фактом в базе, а не текстом кода).

## 27.9 Доступность и деградация

- Туннель разрывается → Cloudflare отдаёт свою страницу ошибки; настраивается кастомная
  страница «Lola тимчасово недоступна» с контактом.
- Провайдер дома упал → сотрудники на точках не могут учиться. Митигация: приложение —
  PWA с офлайн-кешем открытого урока и очередью отправки прогресса (см. `03-modules.md` §3.2).
- Плановые работы: страница обслуживания на Caddy по флагу `MAINTENANCE=1`, API отвечает 503
  с `Retry-After`, Telegram-бот отвечает «Оновлення, спробуйте за 10 хвилин».

## 27.10 Что логируем на шлюзе

- Caddy: метод, путь, статус, время, `CF-Connecting-IP`, `CF-Ray` — в json, ротация 7 дней.
- `CF-Ray` пробрасывается в приложение и попадает в `trace_id`: по одному идентификатору
  находится и запрос в Cloudflare, и строка в логе приложения.
- Персональные данные в логи шлюза не пишутся: телефон в query-строке запрещён (только тело).

## 27.11 Критерии приёмки

1. `https://app.lola.<домен>` открывается снаружи с валидным сертификатом, порты на роутере
   при этом закрыты, домашний IP в DNS не светится (`dig` показывает адреса Cloudflare).
2. Перезагрузка сервера: туннель поднимается сам, ссылка работает без ручных действий.
3. Загрузка видео 300 МБ проходит, приложение показывает урок после обработки.
4. Демо-ссылка открывает демо-тенант в режиме чтения и перестаёт работать через 2 часа.
5. Демо-тенант после ночного сброса выглядит как эталонный.
6. Rate limiting: 30 запросов к `/auth/otp/request` подряд с одного IP → 429 от Cloudflare,
   приложение при этом не нагружено.
7. По `CF-Ray` из ответа находится строка в логе приложения.
8. Отключение туннеля: внутренний адрес `app.lola.local` продолжает работать.
