## Б. Что требует решения заказчика

Каждый пункт: контекст → варианты → моя рекомендация. Без ответа не делаю.

**Б.1 Подпись проверяемого в чек-листе** (docs/20, `require_signature`)
- (а) рисование пальцем на экране → PNG в S3, подпись видна в отчёте;
- (б) вместо подписи — код-подтверждение: проверяемому уходит SMS/Telegram с кодом, наблюдатель вводит;
- (в) убрать флаг, достаточно факта «показано проверяемому».
- Рекомендую (а): просто, как в эталоне, работает офлайн.

**Б.2 Тайный покупатель без входа** (docs/20)
- (а) одноразовая ссылка с токеном на 24 часа, привязана к точке и волне, открывает форму без входа, результат анонимен;
- (б) тайный покупатель — обычный сотрудник с ролью и скоупом `checklist.run` (так сейчас);
- (в) внешний аккаунт-«гость» с ограниченной ролью.
- Рекомендую (а) — но нужно решить, кто выдаёт ссылки и как считаем волны (по датам или вручную).

**Б.3 Занятие как урок курса** (docs/18 §7.7)
- (а) тип урока `meetup`: в дереве курса урок «Очне заняття», человек записывается из курса, `attended` = урок пройден;

- Рекомендую (а), объём ~2 дня.

**Б.4 Автозакрытие разрыва компетенции курсом** (docs/19 §7.3 `[решение]`)

## В. Чего в ТЗ не было — решено самостоятельно (проверить)

Всё это записано в `docs/28` по мере работы. Здесь — сводка, чтобы было видно, где я домыслил.

**Инфраструктура и качество**
1. Тест полноты RLS: любая новая таблица с `tenant_id` без политики валит CI.
2. Значения по умолчанию тенанта (статусы целей, шкалы оценки, роли) заводятся кодом при создании тенанта (`tenantDefaults.ts`), не миграцией — иначе новые тенанты пустые.
3. Прод-образ собирается в CI и публикуется в GHCR; демо-компоуз для машины на 1 ГБ; код входа на экране при `OTP_DEBUG=1` (в ТЗ демо-режима не было).
4. `/metrics` Prometheus, `x-request-id` в ошибках, Sentry на сервере; PDF сертификата через pdfkit, а не headless-браузер (в ТЗ способ не задан).
5. MinIO в CI, e2e на desktop + mobile (320 px) для каждого этапа.

**Доменные решения, которых ТЗ не задавало**
6. **Правило автоматизации = фильтр аудитории** (docs/15 по эталону), задержка правила → `available_from` зачисления в программу.
7. **Программа и траектория — одна сущность** с `mode`; для линейной рёбра выводятся из порядка узлов; «зачёт прежних результатов» — по последней попытке/записи.

10. **Блокировка** = `status=suspended` + отзыв сессий (в ТЗ статуса для «заблокирован» нет, есть флаг).
11. **Слияние дублей** переносит 10 таблиц; **GDPR-удаление** — формат «Користувач #xxxxxxxx», заметки удаляются, результаты остаются.

14. **Объявление** = новость `kind=announcement` с `ack_due_at` (до docs/21 отдельной сущности не было) — при переходе на docs/21 станет отдельной таблицей.
