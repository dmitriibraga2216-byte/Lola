# Кандидати — снято с эталона (Sintegrum)

## 1. Назначение
Модуль рекрутинга: воронка кандидатов на вакансию, привязанная к треку типа «Рекрутинг» (прохождение кандидатом тестового трека до найма). Отсутствует в исходном ТЗ Lola — целиком новый блок.

## 3. Модель данных (предварительно, по формам)
`candidate`: імʼя, прізвище, email, телефон (с кодом страны, дефолт UA +380), резюме (файл), філія (обязательна), мова відправлення листів кандидату (дефолт «Українська»), дата «Доступ до» (дедлайн доступа кандидата к треку, есть info-тултип — [гипотеза] описывает, что будет после этой даты), ознака «Використовувати новий рекрутинг» (чекбокс), призначені треки (множественный выбор, счётчик «Призначені треки (N)»), оцінка, оцінка ТЗ, оцінка ШІ (окремі числовые поля — три независимых вида оценки одного кандидата, не путать между собой), коментар, статус.

## 4. Статусы (сняты дословно, кандидатский канбан `/candidates`)
Полный набор статус-колонок канбана (переключатель список/канбан — иконки над таблицей):
**НЕ ПОЧАЛИ · ПРОХОДЯТЬ · НА ПЕРЕВІРЦІ · СХВАЛЕНІ · ВІДХИЛЕНІ · ПІД СУМНІВОМ**
Плюс служебная колонка **ДОДАТИ** справа — создание собственной (кастомной) колонки-статуса. [решение] Значит статусная модель кандидата расширяема пользователем: не enum, а таблица `candidate_status(order, name, is_system)`, где 6 выше — системные (is_system=true, не удаляются/не переименовываются — не проверено, гипотеза).
Статус «Архівні» и «Найняті» встречались в статистике рекрутерів (`/recruiters`) как отдельные счётчики — [гипотеза] это два дополнительных терминальных статуса поверх кандидатского канбана (архивация/найм), либо считаются на уровне вакансии, а не кандидата. Чем проверяется: создать тестового кандидата, довести до «СХВАЛЕНІ», посмотреть — появляется ли отдельная кнопка «Найняти»/«Архівувати».

## 5. Экраны

### 2.1 Список кандидатів (таблица) — `/candidates?candidate_status=0`
Заголовок «Кандидати», справа — «Кількість кандидатів: N».
Фильтры: Пошук (текст), Філії (select), Трек (select), Статус (select, дефолт «Активні», с крестиком сброса).
Переключатель вида: Список / Канбан (две иконки).
Кнопки: «+ Додати» (открывает модалку создания), «⋮» (доп. меню — не раскрыто, [гипотеза] массовые действия/экспорт).
Колонки таблицы (полный список, слева→направо): чекбокс, Прізвище Ім'я, Контакти, Філії, Трек, Доданий (дата), Останній вхід, Зарплата, Коментар, Оцінка, Оцінка ТЗ, Оцінка ШІ, Статус.

### 2.2 Канбан кандидатів — тот же `/candidates`, вид «Канбан»
6 колонок статусов + колонка «ДОДАТИ» (см. §4). На проходе — 0 кандидатов, карточки внутри колонок не увидены. [гипотеза] карточка кандидата в канбане показывает мини-превью (имя, філія, оцінка) — по аналогии с типовыми ATS. Чем проверяется: создать кандидата и посмотреть карточку.

### 2.3 Форма створення кандидата (модалка «Додати», без отдельного URL)
Поля (сверху вниз): **Ім'я\***, **Прізвище\*** (в одну строку), **Email**, **Телефон** (маска с флагом страны, дефолт Україна +380), блок **«Резюме»** → кнопка «Прикріпити файл» (загрузка CV), **Виберіть філію\*** (select, обязательное), **Мова відправлення для кандидата** (select, дефолт «Українська» — значит кандидату шлются письма/приглашения на этом языке), **Доступ до** (date picker + info-иконка с пояснением дедлайна), чекбокс **«Використовувати новий рекрутинг»**, кнопка-счётчик **«Призначені треки (0)»** (открывает выбор треков для кандидата), кнопки **Скасувати / Створити**.
[гипотеза] Иконка (ⓘ) у поля «Доступ до» содержит текст-объяснение — не раскрыт (наведение не выполнялось, чтобы не провоцировать вызов доп. запросов). Чем проверяется: навести курсор на ⓘ в реальной сессии и прочитать тултип.

### 2.4 Карточка/детали кандидата
Не снято — в системе 0 кандидатів, открыть профиль не на чем (§3 шаг 4 процедуры — «правило одной карточки» неприменимо, карточек нет вовсе). [гипотеза] отдельный экран `/candidates/:id` с историей прохождения трека, результатами оценки (ручной/ТЗ/ШІ), CV-файлом, комментариями рекрутера, и, возможно, «3Д-резюме» (термин из офиц. мануала Sintegrum — видеообзор/интерактивная презентация кандидата). Чем проверяется: создать тестового кандидата, пройти его по канбану, открыть карточку.

## 15. Гипотезы
- Г-02.1 — назначение поля «Доступ до» (тултип не прочитан).
- Г-02.2 — статусы «Найняті»/«Архівні» — отдельные терминальные статусы кандидата или атрибут вакансии.
- Г-02.3 — содержимое карточки кандидата (`/candidates/:id`) не снято — нет данных.
- Г-02.4 — вид карточки в канбане не снят — нет данных.
- Г-02.5 — состав доп. меню «⋮» в списке не раскрыт.
