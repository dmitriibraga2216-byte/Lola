# Співробітники — снято с эталона (Sintegrum)

## 1. Назначение
Реестр сотрудников + карточка сотрудника с назначенными треками (обучение/онбординг/база знаний) и активностью.

## 4. Роли (сняты дословно, дропдаун «Виберіть роль» при создании адміністратора)
**Регіональний директор · Адміністратор · Директор · Менеджер · Ментор · Рекрутер · Контент Менеджер · Автор**, плюс замечен непереведённый служебный ключ **`role_author_mentor`** — [гипотеза] составная роль «Автор+Ментор» (баг локализации в эталоне, ключ вместо перевода — не переносить сам баг, но саму составную роль как сущность учитывать). [решение] Роли — не строгий enum на 6-7 пунктов, а расширяемый справочник `role(code, name, permissions[])`, из которых минимум одна — составная/кастомная.

## 5. Экраны

### 4.1 Список співробітників — `/users?status-users=2`
Заголовок «Співробітники», рядом «Кількість співробітників: N» (реально 43 в эталоне).
Фильтры: Пошук, Філії, Відділ, Трек, + ссылка «Показати більше» (доп. фильтры, не раскрыты — [гипотеза]: роль, дата працевлаштування, статус).
Кнопка «Додати» (модалка, см. 4.3).
Колонки таблицы: Прізвище Ім'я, Email, Філії, Трек (название активного трека + «(N%)» прогресса инлайн), Дедлайн, Останній вхід, отдельная **колонка «%»** справа (замечены значения >100%, напр. 102%, 101% — [гипотеза] это не «% прохождения», а суммарный «рейтинг/оцінка» сотрудника, который может расти сверх 100% за счёт бонусных баллов/переоценки — не переносить как %, буквально снять шкалу отдельно), «⋮» меню на строку.
`status-users=2` в URL — [гипотеза] это фильтр «Активні» по аналогии с фильтром «Статус» у кандидатів — есть и другие числовые статусы (0,1,3…), не перебраны. Чем проверяется: последовательно подставить `status-users=0..N` и посмотреть, что меняется в фильтре «Показати більше».

### 4.2 Карточка співробітника — `/users/:companyId/:userId` (пример: `/users/141/598`)
Блок **«Активність за N» (текущий год)** — календарь-тепловая карта активности по дням/неделям/месяцам (github-style), с легендой «Інше» (типы активности — не раскрыты полностью, замечен только один тип в легенде на пустых данных).
Блок **«Призначені треки»** — сгруппирован **по категориям треков** (те же 10 категорий, что в модуле «Треки»): Рекрутинг, Онбординг, Інтеграція, Підвищення кваліфікації, Атестація, База знань, Офбординг, Психологічні тести, Опитувальник. У каждой категории — ссылка «Управління треками» (переход к назначению).
Для назначенного трека (снято на примере Онбордингу) карточка показывает: превью-обложку, название трека («Ласкаво просимо до BRG Hotels»), круговой индикатор + «N%» прогресса, иконки: перезапуск (↻), письмо (✉ — отправить напоминание/ссылку кандидату?), копировать (⧉ — скопировать ссылку на трек), «Призначено: DD.MM.YY» (с ⓘ), «Дедлайн: DD.MM.YY» (цвет меняется — зелёный/красный, при просрочке) + ссылка «Змінити», «Пройдено модулів: X/Y», «Плановий час: HH:MM:SS», «Час проходження: HH:MM:SS» (план vs факт — отдельные метрики).
Категория **«База знань»** показывает не прогресс-карточки, а **плоский список назначенных документов**, каждый — просто «Назва документа» + «Призначено: DD.MM.YY» (без %, без дедлайна, без времени — т.е. база знаний = материалы для ознакомления, не тестируемый модуль). Примеры названий (домен — гостиничная сеть, ценно как словарь): «Посадова інструкція оператора пральних машин», «...бармена», «...офіціанта», «...охоронця», «...техніка», «Як надати першу допомогу: загальні правила», «Правила поведінки у надзвичайних ситуаціях», «Стандарт прибирання після виїзду», «Стандарт професійної поведінки», «Робота з міні-баром (Дерибас)» (филиал-специфичный документ!), «Стандарт роботи при надходженні інформації про крадіжку», «Хто такий внутрішній клієнт у мережі готелів BRG Hotels», «Відео про роботу у BRG», «Про компанію BRG Hotels», «Бенефіти компанії», «Вітальне слово від СЕО», «Команда керуючої компанії», «Місія та цінності компанії», «Команда керуючих».
Блок личных данных: **Ім'я Прізвище** (заголовок), Email, Телефон, Філії, **Дата народження**, **Дата працевлаштування**, **Нотатки (0)**, **Документи (0)** — последние два, судя по счётчику в скобках, разворачиваемые секции (заметки рекрутера/HR + прикреплённые документы сотрудника, не раскрыты подробно).

### 4.3 Форма створення співробітника (модалка «Додати»)
Переключатель наверху (два таба): **«Співробітник»** / **«Адміністратор»** — определяет набор полей.
Общие поля (обе вкладки): Ім'я*, Прізвище*, Email, Телефон (UA +380 по умолчанию), блок «Резюме» → «Прикріпити файл» (т.е. у сотрудника, как и у кандидата, можно приложить CV — подтверждает связь «кандидат → нанятый сотрудник»), Виберіть філію*, Виберіть відділ, Посада (select), Мова відображення для співробітника (дефолт Українська), Дата народження, Дата працевлаштування, Доступ до (+ ⓘ), кнопка-счётчик «Призначені треки (0)», Скасувати/Створити.
**Разница вкладки «Адміністратор»**: добавляется обязательное поле **«Виберіть роль»** сразу после «Резюме» — дропдаун (см. §4 выше).

## 15. Гипотезы
- Г-04.1 — значения фильтра `status-users` (0..N) не перебраны.
- Г-04.2 — точный смысл колонки «%» >100% в списке (рейтинг vs прогресс).
- Г-04.3 — содержимое доп. фильтров за «Показати більше».
- Г-04.4 — что именно логируют «квадратики» активности (типы событий).
- Г-04.5 — содержимое секций «Нотатки» и «Документи» в карточке сотрудника.
- Г-04.6 — назначение иконок ↻ / ✉ / ⧉ на карточке трека сотрудника (предположения даны в скобках, не подтверждены кликом).
- Г-04.7 — роль `role_author_mentor` — подтвердить, что это баг локализации составной роли, а не отдельная системная роль.
