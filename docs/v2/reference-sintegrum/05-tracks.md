# Треки — снято с эталона (Sintegrum)

## 1. Назначение
Ядро LMS: визуальный граф-конструктор обучающих/оценочных треков, организованных в 10 категорий (соответствуют этапам жизненного цикла сотрудника). Аналог «Треків» в исходной Lola, но с дополнительными категориями `recruiting` (авто-собеседование ИИ) и `offboarding`, которых не было в исходном ТЗ.

## 5. Экраны

### 5.0 Список треков по категории — `/tracks/{category}`
Общий для всех категорий шаблон: заголовок = назва категорії, кнопки **«Згенерувати трек»** (AI-генерация — присутствует не во всех категориях, см. ниже) и **«Створити трек»**, фильтр **«Розділ»** (select — треки внутри категории группируются по разделам), ссылка/чекбокс **«Показати неактивні»**. Список треков — сгруппирован по «Розділ», внутри — «Назва (техн.)» + «Назва (для показа)» парой строк.
[решение] Модель: `track(category, section_id, name, is_active, is_ai_generated)`, `track_section(category, name)`.

Кнопка «Згенерувати трек» **присутствует** в категориях: Рекрутинг, Онбординг (не проверено явно, но видна кнопка на скрине списка), Офбординг — [гипотеза, требует перепроверки по каждой категории]. Кнопка **отсутствует** (только «Створити трек» вручную) в категориях: **Психологічні тести**, **База знань** — [решение] логично: психологические тесты и справочные документы не должны/не могут генерироваться ИИ по методологическим/фактическим причинам.

### 5.1 Реальный состав треков по категориям (снято дословно — словарь предметной области):
- **Рекрутинг** (розділ «No section»): HR Generalist, Маркетолог / Менеджер з маркетингу, Менеджер з продажу / Менеджер по роботі з клієнтами. [решение] Треки рекрутинга создаются **на позицию** (роль вакансии), не на филиал.
- **Онбординг**: треки создаются **на пару (посада × філія)** — напр. «Адміністратор "Волна"», «Адміністратор "Дерибас"», «Адміністратор "Морський"», «Адміністратор Solva», «Бармен Solva», «Кухар "Дерибас"», «Офіціант "Морський"», «Покоївка "Морський"/Solva», «Праля готелю Solva», «Прибиральниця "Морський"/Solva», «Технік "Дерибас"/"Морський"», «Хаускіпер "Морський"», КЦ (Call-центр), Менеджер з бронювання — плюс один общекорпоративный без филиала, раздел **«Про компанію»**: «Ласкаво просимо до BRG Hotels».
- **Інтеграція** (розділ «Worksection», «Корпоративна культура»): «Робота з програмою Worksection», «Культура зворотнього зв'язку».
- **Підвищення кваліфікації** (розділи «Адміністратор Solva», «Менеджмент», «Наставництво», «Саморозвиток», «No section»): включает не только внутренние треки, но и **готовые книги/видео как отдельные треки-модули**: «Відео-лекція Адізеса "Хто такий лідер"», книги Фрідмана, Гоулмена, Шервуда, Друкера, Сьюелла — [решение] книга/видео = такой же `track`, просто с одним контент-модулем типа «Мультимедіа»/«Файл» внутри. Также есть служебные треки-инструкции самой Sintegrum: «Відповіді на питання: посібник користувача Sintegrum1», «Рекрутинг Sintegrum посібник для користувача», «Як створювати треки в Sintegrum 2.0» — не переносить в ПРОДУКТ буквально (это доки вендора-эталона), но паттерн «встроенная справка как трек» — интересное решение.
- **Атестація** (розділ «No section»): «Адміністратор готелю Атестація», «Покоївка Атестація».
- **Психологічні тести** (розділ «No section»): «Діагностика рівня емоційного вигорання (В. Бойко)», «Мотивація успіху та невдачі (А.Реана)», «Профіль стабільності кандидата» — реальные валидированные психометрические методики.
- **База знань** (розділи «Universal», «Worksection», «Адміністратор "Волна"», ещё по филиалам): большой плоский список документов/инструкций — примеры см. в 04-employees.md §4.2. Подраздел «Worksection»: «Додаток», «Задачі та комунікація», «Інструменти програми», «Налаштування профілю» — т.е. база знаний используется и для обучения работе с внутренним ПО, не только для стандартов гостиницы.
- **Офбординг**: пусто (0 треков) в эталоне на момент аудита.
- **Бібліотека модулів** (`/tracks/universal`, отдельный полноценный экран **«Бібліотека модулів»**, не граф, а таблица): колонки **Тип** (иконка типа контента) **· Назва**, строка Пошук. Примеры модулей: «А.Фрідман "Як карати підлеглих"» (тип «T» — текст), «Бронювання номерів для групи» (тип — иконка чек-листа/переліку), «Використання хімії» (тип — іконка файла/документа), и т.д. [решение] Модуль = самостоятельная переиспользуемая единица контента (см. §1 назначения: «створено один раз — використовується у кількох треках»).
- **Звіт про помилки** (`/tracks/report`) — отдельный самостоятельный экран (не список треков!): фильтр **Тип** (select), таблица с колонкой **Трек**, в эталоне «немає даних». [решение] Это фидбэк-механизм: сотрудник, проходя трек, может пожаловаться на ошибку в модуле (опечатка, битая ссылка и т.п.), и это попадает сюда для методиста/автора на разбор.

### 5.2 Граф-редактор трека — открывается по клику на трек из списка (URL с id, не зафиксирован явно)
Хлебная крошка/шапка: название трека (напр. «HR Generalist»), кнопка **«Про вакансію»** (контекстная — видна именно у трека категории «Рекрутинг», значит трек рекрутинга привязывается к вакансии и может открыть её карточку).
Канвас-редактор (zoom/pan): узлы — **круги** с двойным кольцом (внешнее пунктирное + внутреннее сплошное цветное), внутри — название модуля и оценка времени прохождения («5 хв», «2 хв»); узлы соединены однонаправленными стрелками (последовательность прохождения). У части узлов — бейдж **«AI»** (модуль сгенерирован/содержит ИИ-логику, замечено на узле-кейсе). Над частью узлов — счётчик вида «0.5K» / «0.8K» с иконкой-«≡» — [гипотеза] количество прохождений модуля всеми пользователями всех треков (аналитика популярности), не подтверждено кликом.
Тулбар канваса (справа): выбор (курсор), рука (пан), лупа (поиск по треку — открывает панель «Пошук по треку» с полем ключевых слов и кнопкой «Знайти»), шестерёнка (настройки — не раскрыта), zoom +/−, «1:1» (сброс масштаба), (i) информация.
Цвет кольца узла — [гипотеза] кодирует тип модуля (замечены минимум 2 цвета: фиолетовый и синий на разных узлах: «Ласкаво просимо»/«Про вакансію»/«Кейс 3» — фіолетовий; «CV та рекомендації» — синій). Чем проверяется: открыть настройки узла (гілка ⚙) или создать узел из палитры и посмотреть подписи цветов.

### 5.3 Контент-редактор модуля (клик по узлу графа открывает отдельный полноэкранный редактор)
Хлебная крошка «←» назад, справа чекбокс (обрезан текст, «Вр...» — [гипотеза] «Врахувати в результат» — учитывать ли модуль в итоговой оценке/прогрессе). Ссылка **«Видалити редактор»** (красная, деструктивное действие). Заголовок модуля (редактируемый текст). Тело — блочный редактор контента (как в остальных текстовых полях системы): кнопка **«Вибрати блок»** + панель «Швидка вставка» с типами блоков: **Текст, Параграф, Код…** (полный список типов блоков виден в левом сайдбаре приложения глобально: **AI, Текст, Твердження, Примітка, Код, Цитата, Перелік, Зображення, Файл, Мультимедіа, Таблиця, HTML, Формула** — 13 типов, шире, чем 11 типов контента в исходной Lola).
**Конкретный пример реального контента** (модуль «Ласкаво просимо» трека «HR Generalist», рекрутинг-категория): это сценарий для ИИ-інтерв'юера — «Вітаю! Мене звати Ольга, і я буду проводити електронн[е інтерв'ю]. Після того, як ви прослухаєте питання, ви зможете відповіст[и голосом/текстом]... через деякий час, ви отримаєте на пошту [результат]... Розкажіть, будь ласка, як вас звати...» — **подтверждает механику авто-собеседования с ИИ-персонажем**, упомянутую в официальном мануале Sintegrum как «3D-резюме»/«цифрові співбесіди».

### 5.4 Контекстное меню узла графа (правый клик по узлу) — раскрыто при повторном проходе
Пункты меню (сверху вниз): слайдер размера узла (иконка ⤢ + ползунок), **«Змінити назву»**, **«Редагувати»** (открывает контент-редактор, см. 5.3), **«Створити модуль»**, **«Поєднати»** (режим протягивания связи к другому узлу — ручное соединение), **«Тип: <текущий тип> ▸»** — раскрывающийся подсписок, **«Скопіювати»**, **«Вставити»**, **«Бібліотека модулів ▸»** (вставить существующий переиспользуемый модуль из `/tracks/universal` прямо в граф — подсписок, не раскрыт до конца), **«Видалити»** (красным).

**Закрыт вопрос о типах узлов (Г-05.4)**: подсписок «Тип» содержит ровно **3 значения**: **Стартовий · Звичайний (отмечен по умолчанию) · Фінальний**.
[решение] **В отличие от контрольных находок по эталону LMS Collaborator (start/finish/task/and/or/delay/stop_delay — 7 типов узлов с логикой ветвления в узле), в Sintegrum узлов-развилок AND/OR нет вовсе.** Модель узла графа здесь проще: `node(type: start | regular | final, ...)`, всего один «стартовий» и один/несколько «фінальний», всё остальное — «звичайний». Явного визуального ветвления (условных переходов) на этом эталоне не обнаружено — все просмотренные связи однонаправленные и безусловные (простая цепочка). [гипотеза] Либо ветвление в Sintegrum не поддерживается вовсе (более простой продукт, чем LMS Collaborator), либо задаётся не типом узла, а условием на самой связи/стрелке. Прямая проверка (клик правой кнопкой по стрелке) на этом проходе не удалась технически — см. развёрнутую гипотезу, построенную по косвенным признакам, в §5.5а ниже (Г-05.7).
**При реализации ПРОДУКТА (Lola)** — ориентироваться на более богатую модель ветвления из базового ТЗ (LMS Collaborator), т.к. Sintegrum в этой части выглядит функционально беднее, а не архитектурно другим; закрытие Г-05.4 здесь — не повод упрощать граф в ПРОДУКТЕ, а лишь честная фиксация того, что видно на этом эталоне.

### 5.5а Умови на зв'язках графа (стрілки між вузлами) — [гіпотеза, побудована замість прямої перевірки]
Прямая проверка не удалась: попытка кликнуть правой кнопкой именно по стрелке-связи (а не по узлу) дважды подряд перетриггерила контекстное меню уже выделенного узла — клик не изолировался от области узла (координаты стрелки визуально примыкают к кругу узла на канвасе с текущим zoom-уровнем). Технически это не было проверено, поэтому ниже — построенная гипотеза, а не снятый факт.

**Опорные наблюдения (снято с еталону), на которых строится гипотеза:**
- Все стрелки, увиденные на всех просмотренных треках (Рекрутинг и Онбординг), — **однонаправленные и визуально одинаковые** (нет пунктира/цвета/подписи/иконки на самой линии, которые отличали бы «условную» связь от «безусловной»).
- Контекстное меню узла (§5.4, Г-05.4 закрыта) содержит явный пункт **«Поєднати»** для создания связи, но **не содержит** пункта вида «Умова переходу» или «Умови» — если бы условия жили на связи, естественно было бы ожидать такой пункт либо в меню узла, либо в отдельном меню самой связи.
- Тип узла ограничен 3 значениями (Стартовий/Звичайний/Фінальний) без узлов-розвилок (AND/OR/delay) — т.е. на **узле** логики ветвления точно нет (это закрыто, не гипотеза).
- Для рекрутинг-треків «правила проходження» вынесены на уровень вакансії (§5.5, критерії оцінки), а не на граф — т.е. продукт в принципе тяготеет к «правила — вне графа», а не «правила — в топологии графа».

**[гіпотеза]** Исходя из этих наблюдений, наиболее вероятны — в порядке убывания правдоподобия:
1. **(найбільш імовірно)** Умов на зв'язках у Sintegrum немає взагалі — граф є простим орієнтованим ланцюжком/деревом без розгалужень за умовою; послідовність проходження визначається виключно порядком стрілок, а «розгалуження» (якщо воно комусь потрібне) імітується вручну — кількома паралельними ланцюжками від одного вузла без умовної логіки вибору.
2. **(менш імовірно)** Умова таки існує, але вона не на самій стрілці, а є прихованим атрибутом вузла-джерела (наприклад, у ще не розкритому пункті «⚙ Налаштування» — якщо такий взагалі є окремо від «Редагувати»/«Тип») — цей варіант не суперечить закритій Г-05.4, оскільки «Редагувати» веде саме в контент-редактор, а окремого «Налаштування вузла» пункту в спостереженому меню не було.
3. **(найменш імовірно)** Умова існує на зв'язці, але UI для неї відкривається не правим кліком по лінії, а якимось іншим жестом (наприклад, клік по маленькій іконці посередині стрілки, яка не була помічена через масштаб канваса, або подвійний клік).

**Чим перевіряється (для наступного проходу):** збільшити zoom канваса максимально (щоб відстань між вузлами на екрані була велика і стрілка не перекривалася колом вузла), або скористатися `resize_window` на широкий viewport, потім клікнути правою кнопкою рівно по середині довгої стрілки, подалі від обох вузлів; додатково спробувати одинарний/подвійний лівий клік по стрілці. Якщо жоден варіант не дає окремого меню — варіант 1 (умов немає) вважати підтвердженим.

**Рекомендація для реалізації ПРОДУКТА (Lola)**: незалежно від результату цієї гіпотези, при реалізації орієнтуватися на більш багату модель розгалуження з базового ТЗ (LMS Collaborator, вузли and/or/delay) — це вже зафіксовано в CLAUDE.md, п.5, і ця гіпотеза його не скасовує, а лише уточнює, де саме варто шукати умови на еталоні Sintegrum, якщо колись знадобиться звірка.

### 5.5 «Про вакансію» — панель, открывающаяся из графа трека категории «Рекрутинг» (частично закрывает Г-05.6)
Слайд-панель поверх канваса: **Опис вакансії**, **Вимоги** (буллет-лист), **Обов'язки** (буллет-лист) — дословное зеркало полей формы створення вакансії (см. 03-vacancies.md §3.2), т.е. это read-only просмотр данных привязанной вакансії прямо из редактора трека.
Ниже — блок **«Оцінка кандидата по критеріях»** с кнопками **«Додати»** (добавить критерий вручную) и **«Згенерувати критерії (AI)»** (сгенерировать критерии оценки нейросетью). В эталоне список критериев пуст (0 записей) — не досмотрена форма одного критерия (вероятные поля: назва критерію, вага/бал, опис).
[решение] **Закрывает часть Г-05.6**: критерии, по которым оценивается кандидат (та самая «Оцінка» из 3 чисел кандидата, см. 02-candidates.md), настраиваются **на уровне вакансии**, а не на уровне узла графа и не на уровне трека в целом. Это ближе к найденной в LMS Collaborator модели «правила прохождения — в завданні/призначенні, не в контенті», только здесь роль «завдання» играет вакансія (для рекрутинг-треків). [гипотеза, проверено частично] Для трека категории «Онбординг» (перепроверено отдельно, трек «Ласкаво просимо до BRG Hotels») аналог «Про вакансію» **не найден**: в шапке только «←» назад и разворачиваемый заголовок (шеврон ˅/˄, чисто визуальный тоггл, без настроек). Значит для 9 из 10 категорій (все, кроме «Рекрутинг») экран/панель с настройками спроб/прохідного балу/дедлайна на этом проходе не обнаружены вовсе — либо это атрибуты узла (не раскрыты — пункт «Редагувати» в контекстном меню узла ведёт в контент-редактор, а не в отдельную вкладку «Налаштування»), либо назначаются не на трек, а на связку «трек × співробітник» (дедлайн действительно виден именно там — см. 04-employees.md §4.2, «Призначено/Дедлайн» на карточке сотрудника). [решение, предварительное] Скорее всего, верно второе: сам трек в Sintegrum не хранит «дедлайн проходження» как константу — дедлайн назначается индивидуально при привязке трека к сотруднику/кандидату (что согласуется с находкой LMS Collaborator: «правила прохождения — в завданні/призначенні, не в контенті»). Остаётся неясным только источник «Кількість спроб» (видно как колонка в `/review/*`, см. 06-review.md) — вероятно, тоже атрибут призначення, не трека.
Дополнительно на этом проходе замечены два новых визуальных элемента узла (категория «Онбординг», отсутствовали на треке «Рекрутинг»): маленькая иконка **🖼 + число** под узлом (напр. «17», «4», «1») — [гипотеза] количество вложенных медиа/зображень в модуле; и маленькая иконка **⬡⬡⬡ (сітка з ромбиків)** внутри узла снизу — [решение] визуальный маркер «этот модуль — ссылка на переиспользуемый модуль из Бібліотеки модулів» (соответствует находке 5.1 о «Бібліотеці модулів»); также один узел («Місія та цінності компанії») выделен **золотым/жёлтым кольцом** вместо фиолетового — ещё один цвет кольца в дополнение к Г-05.3, значение по-прежнему не установлено.

## 15. Гипотезы
- Г-05.1 — наличие кнопки «Згенерувати трек» не перепроверено по каждой из 10 категорій построчно (снята выборочно).
- Г-05.2 — назначение счётчика «0.5K»/«0.8K» над узлом графа.
- Г-05.3 — смысл цвета кольца узла (тип модуля?).
- Г-05.4 *(закрыта частично)* — состав типов узла закрыт (контекстное меню → «Тип»: Стартовий/Звичайний/Фінальний, см. §5.4), логики ветвления AND/OR на узле нет; открытым остаётся только вопрос, где тогда живут условия — см. Г-05.7.
- Г-05.5 — чекбокс «Вр...» в редакторе модуля.
- Г-05.6 *(уточнена, не закрыта до конца)* — где именно настраиваются попытки/проходной балл/дедлянка: для «Рекрутинг» частично закрыто — критерії оцінки живуть на вакансії (§5.5); для інших 9 категорій панель-аналог «Про вакансію» не знайдена, [рішення, попереднє] — дедлайн/спроби, ймовірно, атрибут призначення «трек × співробітник», а не самого треку.
- Г-05.7 *(нова, побудована як гіпотеза замість прямої перевірки)* — умови на зв'язках (стрілках) графа: пряма перевірка (правий клік по стрілці) не вдалася технічно; побудована гіпотеза по непрямих ознаках — див. §5.5а. Найбільш імовірний варіант: умов на зв'язках немає взагалі, граф — простий орієнтований ланцюжок без розгалужень.
