# Налаштування — снято с эталона (Sintegrum)

## 5. Экраны

### 10.1 Налаштування компанії — `/company-settings`
Блок **«Компанія»**: Назва компанії, Пошта компанії, **Колонтитул** — чекбокс «Відображати назву та логотип компанії в контенті під час проходження треків» (брендирование обучающих материалов).
Блок **«Підключити Штучний інтелект»**: текст «Порівняйте відповіді співробітника з контентом модуля та контрольними ключами, щоб допомогти менторам проводити перевірку завдань. Генеруйте вміст для нових треків.» + «Доступно до: DD.MM.YYYY (N днів)» — [решение] ИИ — не встроен безусловно, а подключаемый и ограниченный по сроку модуль (несмотря на то, что во всех тарифах есть суффикс «.AI» — вероятно, ИИ включён в подписку, но имеет отдельный «срок действия»/лимит, независимый от даты окончания тарифа). Две функции ИИ явно названы: **1) сверка ответа сотрудника с ключом для помощи ментору при проверке**, **2) генерация контента новых треков** (соответствует кнопке «Згенерувати трек» и «Створити з AI» в вакансиях).
Блок **«Налаштування мов»**: чекбоксы выбора языков интерфейса, доступных сотрудникам компании — **32 языка** (полный список сохранён дословно): Русский, English, Українська, العربية, Azərbaycan dili, Български, বাংলা, Čeština, Deutsch, Ελληνικά, Español, Français, हिन्दी, Magyar, Հայերեն, Bahasa indonesia, Italiano, 日本語, ქართული, Қазақ тілі, 한국어, Lietuvių, Latviešu, Nederlands, Polski, Português, Română, සිංහල, Wikang tagalog, Türkçe, Ўзбек, Tiếng việt, 中文.
Блок **«API»**: приватный токен доступа к Sintegrum API (замаскирован звёздочками) — подтверждает наличие публичного API (см. также `/api-doc`).
Блок **«Налаштування сертифікатів»**: чекбокс «Дозволити співробітникам завантажувати сертифікати про успішне проходження треків» + ссылка/кнопка **«Конструктор сертифікатів»** (отдельный визуальный редактор шаблона сертификата — не раскрыт, не открывался).
Блок **«Поведінка таблиць»**: чекбокс «Тільки для цього браузера» + «Автоматично завантажувати дані після прокручування таблиці вниз» (infinite scroll вкл/выкл, настройка персональная per-браузер).
Блок **«Автоматичне видалення відхилених кандидатів в архів»**: чекбокс «Видаляти відхилених кандидатів автоматично» + поле **«Видаляти через»** (кількість днів, не уточнено число дефолта).
Блок **«Автоматична відправка неповного 3Д-резюме кандидатам»**: чекбокс «Відправляти неповне 3Д-резюме кандидатам після завершення проходження рекрутингу?» + условие **«Відправляти посилання після отримання наступної оцінки: Оцінка рекрутера»** (select — очевидно можно выбрать, от какой именно оцінки триггерится отправка — «Оцінка», «Оцінка ТЗ», «Оцінка ШІ» или «Оцінка рекрутера», см. 02-candidates.md о типах оценок кандидата) — **важная находка**: подтверждает, что «3Д-резюме» — это генерируемый компиляцией итоговый артефакт по кандидату, который можно доотправить даже при неполном прохождении.
Блок **«Двофакторна авторизація Google Authenticator»**: чекбокс «Включити двофакторну авторизацію».
Блок **«Кількість днів відпустки»**: подпись «Норма днів відпустки на рік за промовчанням для співробітників. Індивідуально залишок може скоригувати HR у картці співробітника.» — два числовых степпера: **«Днів відпустки на рік»** (дефолт 24) и **«Лікарняний»** (дефолт 5) — [решение] значит карточка сотрудника (не увиденная детально в 04-employees.md — не долистано) содержит учёт отпускных/больничных дней, компания задаёт норму по умолчанию, HR может скорректировать индивидуально.
Кнопка **«Зберегти»** внизу всей страницы (единая форма настроек компании).

### 10.2 Керування філіями — `/branches`
Заголовок «Керування філіями», кнопка **«Додати філію»**. Таблица, колонки: **Місто**, **Включено відпустки** (у всех 13 филиалов в эталоне — «—», т.е. переопределение нормы отпуска по филиалу не задано, наследуется дефолт из `/company-settings`). Полный список 13 филиалов подтверждён (см. 01-statistics.md §1.4). [гипотеза] Форма создания/редактирования филиала (по клику «Додати філію» или на строку) не открывалась — вероятные поля: назва, місто/адреса, включено відпустки (override), контакти.

### 10.3 Керування посадами — `/jobs`
Заголовок «Керування посадами», Пошук, кнопка **«Додати посаду»**. Таблица, колонки: **Назва посади**, **Опис**, **Треки**, **Статус** (у всех строк в эталоне «—», т.е. эти два столбца не заполнены). Список 20+ посад на первой из 2 страниц пагинации (реальный словарь, справочно): Адміністратор готелю, Керуючий готелю, Покоївка, Офіціант, Помічник керівника, Оператор пральні, Фінансовий директор, Бухгалтер, Менеджер з розвитку, Менеджер з навчання, Керівник відділу продажів, Керівник call-центру, Директор керуючої компанії, Робітник, Помічник кухаря, Кухар, Аніматор, Прибиральниця, Лікар, Медична сестра (+ ещё стр. 2, не досмотрена).
[решение] Колонка **«Треки»** у посади — подтверждает связь «посада → трек» напрямую (не только через пару посада×філія, как в 05-tracks.md): вероятно, посаде можно назначить типовой трек по умолчанию, который применяется при создании сотрудника на эту посаду.
Строки в списке кликабельны только как tooltip с полным текстом названия (не переход на форму редактирования) — [гипотеза] форма редактирования посади открывается другим способом (иконка в конце строки при наведении, не проверено).

### 10.4 Керування відділами — `/departments`
Заголовок «Керування відділами», кнопка **«Додати відділ»**, фильтр **Статус**. Таблица, колонки: **Статус**, **Відділ**. Реальный список названий отделов см. 01-statistics.md §1.5 (Хаускіпінг, Служба прийому та розміщення, Майстри, Ресторан, і т.д.) — подтверждён повторно, 12 отделов, пагинация не понадобилась (1 страница).

### 10.5 Оргструктура — `/org-structure`
Заголовок «Оргструктура», **2 таба**: **«Адмін — конструктор»** (редактируемый режим) / **«Співробітник — перегляд»** (read-only режим для рядового сотрудника — без иконок управления).
Визуальное **дерево-конструктор** (не граф со свободным позиционированием, а иерархическое дерево родитель→дети, судя по вертикальным соединительным линиям). Корневая точка входа — кнопка **«Додати кореневий вузол»**.
Узел дерева — карточка с названием и **набором иконок при наведении**: person-icon (значок человека — [решение] привязать конкретного сотрудника к узлу), **+** (добавить дочерний узел), карандаш (редактировать), красная корзина (удалить).
**Важная находка**: узлы дерева бывают двух видов — **узел-посада** (просто название должности, напр. «Адміністратор денний», «Покоївки», «Майстер») и **узел-конкретный сотрудник** (аватар-инициалы + ФИО + email — привязка реального человека к точке структуры, обычно на роли керівника/директора філії). [решение] Модель: `org_node(parent_id, type: position | employee, position_id?, employee_id?)` — оргструктура смешивает роли (позиции) и конкретных людей в одном дереве, т.е. это одновременно и шаблон структуры, и фактическая расстановка людей по руководящим точкам.
Дерево эталона фактически отражает всю управленческую иерархию сети BRG Hotels (директор по филиалам → керуючі готелів → адміністратори/майстри/покоївки и т.д., плюс отдельная ветка управляющей компании: фінансовий директор, менеджер з розвитку, SMM, бухгалтер, помічник СЕО) — реальные ФИО и email руководителей увидены, но намеренно не переносятся в спецификацию (персональные данные, не относятся к требованиям продукта).

### 10.6 Ролі — `/roles`
Заголовок «Ролі», кнопка **«Додати роль»** (подтверждает — роли расширяемы, не жёсткий enum). Таблица, колонки: **Аліас** (системный код, англ., напр. `admin`, `author`, `author_mentor`, `content_manager`, `director`, `manager`, `mentor`, `recruiter`, `regional_director`), **Назва**, **Тип** (у всех сняли `systemic` — то есть все текущие 9 ролей помечены как системные/встроенные, не удаляемые — [гипотеза]), **Опис**.
[решение] Подтверждает Г-04.7 из 04-employees.md: `author_mentor` — реальная системная роль (не баг локализации — просто нет перевода в конкретном дропдауне создания пользователя), составная роль «автор+ментор».
Полный список 9 системных ролей задокументирован дословно, полностью совпадает с дропдауном при создании администратора (04-employees.md §4).
[гипотеза] Права/permissions на роль (что именно разрешено каждой роли) не раскрыты — открывается, вероятно, по клику на строку роли (не проверено).

### 10.7 Сховище — `/storage`
Заголовок «Сховище», кнопка **«Збільшити сховище»** (докупить объём — подтверждает, что 100 Gb из тарифа можно расширить отдельной опцией). Сводка **«Використовується: 5.27 Gb / 100 Gb»** с разбивкой **по категориям треків**: Рекрутинг, Інтеграція, Онбординг, Офбординг, Атестація, **Інше** (в эталоне именно «Інше» — 4.74 Gb — занимает почти всё место, т.е. основной расход места не в треках, а вне их прямой категоризации).
Фильтры: **Категорія** (select), **Вибрати період** (date range). Кнопка **«Видалити»** (массовое удаление выбранных файлов).
Таблица (**172 файли** в эталоне), колонки: **Файл** (имя файла — сняты как UUID-подобные `.mp4`), **Співробітник**, **Трек**, **Дата**, **Розмір файлу**.
[решение] Судя по реальным именам файлов (случайные числа + `.mp4`) и колонке «Трек» = конкретные посадо-філіальні онбординг-треки («Прибиральниця Solva», «Адміністратор Solva») — сховище состоит в основном из **видеоответов сотрудников на задания треків** (запись с веб-камеры, см. тип завдання «відео-відповідь» в мануале). Это объясняет, почему «Інше» — крупнейшая категория: возможно, видеофайлы не классифицируются по категории трека автоматически, либо「Інше」включает CV/3D-резюме кандидатів (`progress-item/cv-list` из API, см. §10.8) и служебные файлы контента (обложки модулів, зображення).

### 10.8 Документація API — `/api-doc`
Встроенный **Swagger UI** (OAS3), заголовок «Sintegrum API», сервер `https://api.sintegrum.com`. Реальный REST API, доступный внешним интеграциям по приватному токену из `/company-settings`.
**Полный список груп ендпоінтів (тегів), снятый дословно**: **Branch** (керування філіями), **Candidate** (керування кандидатами, включно з `CandidateCreate`), **Config** (`GET /config` — конфігурація компанії), **Course** (!) — [решение] **внутреннее API-название сущности «Трек» — `Course`**, не совпадает с UI-термином, важно для реалізації API самого ПРОДУКТА; **Department**, **Position**, **Position Group** (!, ще одна сутність — групи посад, не бачена в UI напряму — [гипотеза] відповідає «Розділ» у списках посад/треків), **Progress** (прогрес користувача/кандидата по треку: `assigned/{userId}`, `finished/{userId}`, `in-progress/{userId}`), **Progress Item** (`cv-list` — «List 3D...» тобто **список 3Д-резюме** — прямое API-подтверждение сущности; `list` — окремі елементи прогресу), **Statistic** (`GET /statistic/index` — загальні лічильники компанії), **Student** (!) — [решение] **внутреннее API-название сущности «користувач, який проходить трек»** — тобто в моделі даних співробітник і кандидат, схоже, зведені до спільної батьківської сутності `Student`/`User` для цілей проходження треків, а розрізняються типом; **User** (`GET /user/list`).
Секция **Schemas** (DTO-моделі, зняті часткові назви): `Branch`, `Candidate`, `CandidateCreate`, `Course`, `CvProgressItem`, `Department`, `Group`, `Position` (+ далі за списком, не докручено до кінця).
[решение] Це найцінніша знахідка для проєктування API ПРОДУКТА: реальна доменна модель на рівні бекенду використовує терміни **Course** (не Track), **Student** (не User/Employee), **CvProgressItem** (не «3D resume»), що відрізняється від UI-термінології — при реалізації Lola варто явно розвести UI-словник (укр. лейбли з цього аудиту) і внутрішню модель даних, і НЕ калькувати англійські назви сутностей 1:1 з UI-лейблів.

## 15. Гипотезы
- Г-10.1 *(закрыта)* — все 8 пунктів меню «Налаштування» тепер відкриті й задокументовані.
- Г-10.2 — дефолтное число дней в «Видаляти через» (автоархивация отклонённых кандидатов) — поле не заповнене значенням за замовчуванням в эталоні.
- Г-10.3 — содержимое «Конструктора сертифікатів» — кнопка не відкривалась.
- Г-10.4 — точный список опций в селекте «Відправляти посилання після отримання наступної оцінки».
- Г-10.5 — форма редагування конкретної посади/відділу/філії (по кліку на рядок відкривається лише tooltip, не форма) — спосіб відкриття форми редагування не знайдено.
- Г-10.6 — призначення колонок «Треки»/«Статус» у `/jobs` (порожні в еталоні).
- Г-10.7 — повний перелік Schemas в Swagger не докручено до кінця (обірвано на `Position`).
- Г-10.8 — сутність **Position Group** («групи посад») з API не знайдена як окремий UI-екран — можливо, це і є «Розділ» в списках, а можливо окремий незнайдений екран.
