# CLAUDE.md — правила для агента, который будет реализовывать эти дополнения в Lola

## Что это за репозиторий
Пакет **дополнений** к существующему ТЗ Lola, снятых с эталона Sintegrum
(`brghotels.sintegrum.com`). Это не самостоятельный продукт и не полное ТЗ — перед началом
работы нужно свести это с уже существующим репозиторием `lola-spec` (базовое ТЗ, снятое с
LMS Collaborator).

## Ключевые архитектурные инварианты (снятые с этого эталона)

1. **Кандидат ≠ Співробітник, но одна модель полей.** Форма кандидата и форма сотрудника
   почти идентичны (ім'я, email, телефон, резюме, філія, мова, дедлайн доступу,
   призначені треки) — при найме кандидат, вероятно, конвертируется в сотрудника без
   повторного ввода данных. Не разносить эти сущности по несвязанным таблицам без
   миграционного пути «кандидат → сотрудник».
2. **Статусы кандидата — расширяемый справочник, не enum.** Канбан кандидатів имеет
   служебную колонку «Додати» для создания собственных статусов поверх 6 системных.
3. **Оценка кандидата — минимум 3 независимых числа**: Оцінка (ручна), Оцінка ТЗ, Оцінка
   ШІ. Не схлопывать в одно поле «score».
4. **Треки организованы в 10 фиксированных категорий** (recruiting, onboarding,
   integration, training, attestation, psychological, knowledge, offboarding, universal,
   report) — категория **не является пользовательским полем** трека, это фиксированная
   таксономия верхнего уровня с разным поведением на каждую (см. 05-tracks.md: не у всех
   категорий есть AI-генерація, «База знань» вообще не поддерживает граф/прогресс-модель).
5. **Трек — граф модулей-узлов**, не линейный список. Узлы содержат блочный контент (13
   типов блоков — см. 05-tracks.md §5.3). Условия/ветвления графа не подтверждены на этом
   эталоне (в отличие от контрольных находок по LMS Collaborator, где ветвление — в узлах
   типа and/or/delay) — при реализации сверяться с базовым ТЗ Lola по LMS Collaborator,
   а не считать эталон Sintegrum источником истины по ветвлениям.
6. **Роли — расширяемый справочник с флагом `systemic`**, не enum (`/roles`, кнопка
   «Додати роль»). 9 системных ролей задокументированы в 04-employees.md и 10-settings.md.
7. **Тарификация по 2 независимым осям** — «співробітники» и «кандидати» считаются
   раздельно, «треки» не лимитируются вовсе.
8. **Настройки компанії — единая форма с ~10 разноплановыми блоками** (не разносить в 10
   отдельных экранов): брендинг контента, AI-подписка (со своим сроком действия, отдельным
   от тарифа), 32 языка интерфейса, API-токен, конструктор сертифікатів, поведінка таблиць
   (per-browser!), авто-архівація відхилених кандидатів, авто-відправка 3Д-резюме за
   умовою оцінки, 2FA, норми відпустки/лікарняного (с override на уровне филиала).
9. **«3Д-резюме»** — генерируемый по итогам AI-собеседования кандидата артефакт, может
   быть отправлен кандидату даже при неполном прохождении (настраивается условием «после
   получения оцінки X»).

## Правило работы с гипотезами
Каждый `[гипотеза]` в документах — это осознанный пробел, а не ошибка аудита. Перед
реализацией соответствующей фичи стоит либо (а) перепроверить на живом эталоне по
инструкции «Чем проверяется», либо (б) принять собственное `[рішення]` и явно
задокументировать его в этом же файле правкой с пометкой-исправлением (не тихой заменой).
